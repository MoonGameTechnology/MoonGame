# Отчёт: связность и подход документации — 2026-07-26

> Оценка того, **как построена** документация Void Dominion: подход, связность,
> точки входа, декомпозиция, исполняемость. Сверено с `docs/` (77 .md-файлов,
> ~19 200 строк), `scripts/docs-check.mjs`, `CLAUDE.md`, `CONTRIBUTING.md`,
> корневым `README.md`, `.claude/skills/sync-state-doc/SKILL.md`.
>
> **Контекст стадии:** альфа, нет прода/пользователей, крит-путь к играбельности.
> Документация ведётся по правилу «код первый, доки после» + «реконсилируй,
> не дописывай» (скилл `sync-state-doc`).

---

## 1. Подход: «граф знаний», а не «стопка файлов»

Документация построена **осознанно как граф знаний** — это прямо декларировано в
`scripts/docs-check.mjs`: «docs/ — это и есть граф знаний проекта (сотни
перекрёстных ссылок между state.md / backlog.md / роадмапами)». Это **не** типичный
подход — большинство проектов держат доки как набор файлов без проверяемых связей.
У вас связи **исполняемы**.

**Масштаб:** 77 .md-файлов, ~19 200 строк. 65 в корне `docs/`, 7 в `docs/security/`,
5 в `docs/reviews/`. 34 roadmap-файла.

---

## 2. Что построено правильно

### 2.1. `docs-check.mjs` — исполняемая целостность графа

Проверяет на каждый PR (входит в `pnpm run check`):
- markdown-ссылки `[текст](файл)` — резолв относительно файла-источника;
- backtick-упоминания `` `имя.md` `` — резолв от корня/файла/по уникальному имени;
- словарь зон backlog'а (`[core]`/`[act]`/…/`[ops]`) против `ZONES` — не даёт
  зонам расползаться опечатками;
- `ALLOW` — forward-ссылки с причиной и датой (конвенция `.trivyignore`);
- `docs/reviews/**` исключены — датированные исторические снапшоты, им позволено
  ссылаться на имена, актуальные на их дату.

Это **редкая зрелость** — граф знаний с исполняемой целостностью, а не «доки,
которые никто не открывает».

### 2.2. `state.md` как живой якорь контекста

1421 строка, 11 секций, шапка с «быстрым стартом сессии» (навигация → §11
возобновить / §9 статус / §10 команды / `backlog.md` кирпичики / `CLAUDE.md`
инварианты). 11 файлов ссылаются на `state.md` — это **хаб** графа. Подход «код
первый, доки после» + «реконсилируй, не дописывай» (скилл `sync-state-doc`) —
правильный: одна живая версия факта, а не две разъехавшиеся.

### 2.3. `backlog.md` как исполняемый план

1490 строк, 28+ блоков, кирпичики со статусами `✅`/`⏳`/`🔒`/`🔶`/`❌` и зонами.
Зоны машинно проверяются `docs-check`. Правило «1 кирпич ≈ 1 PR ≈ 1 сессия, в
пределах одной зоны» — фиксирует границы параллельной работы. Это **не** «список
идей» — это назначаемый план с границами.

### 2.4. Роадмапы по темам

34 `*-roadmap.md` файла — каждый тема-специфичный (server, onboarding, arsenal,
AvA, persistence, security…). `roadmap.md` — верхний уровень,
`deep-technical-roadmap.md` — инженерный. `security-master-plan.md` синтезирует
5 security-под-роадмапов. Это **правильная декомпозиция** — один файл не тянет
всю карту, темы разделены.

### 2.5. `docs/reviews/**` — датированные исторические снапшоты

5 файлов (code-review, docs-audit, strategy-coverage, multiplayer-readiness).
Исключены из `docs-check` — им позволено ссылаться на имена, актуальные на дату.
Это **правильно** — ревью — историческая запись, «актуализация» уничтожила бы
смысл.

### 2.6. Точки входа

Корневой `README.md` ссылается на `game-description.md` (что есть), `state.md`
(живой снимок), `gdd.md`/`architecture.md`/`modulesystem.md`/`tech-stack.md`
(дизайн), `roadmap.md`/`backlog.md` (план). `state.md` шапка отсылает к
`backlog.md`/`CLAUDE.md`/`README.md`. `CLAUDE.md` — операционный короткий. Есть
**несколько входов** под разные задачи (новичок → README, разработчик →
CLAUDE.md, сессия Claude → state.md).

## 3. Слабые места

### 3.1. Нет `docs/README.md` — индекса

`state.md` шапка пишет «полный индекс доков → `README.md`», но имеется в виду
корневой `README.md`, а не `docs/README.md`. В `docs/` 65 файлов — без индекса
найти нужный roadmap сложно. `docs/README.md` с таблицей «файл → назначение →
статус» решил бы это.

### 3.2. 3 орфана — файлы без входящих ссылок

`game-vision-roadmap.md`, `ping-system.md`, `rustore-release-roadmap.md` — ни один
файл на них не ссылается. Они **существуют**, но из графа знаний **не достижимы**.
Нашлись только полным перебором. Это разрыв связности — `docs-check` проверяет,
что ссылки ведут на существующие файлы, но **не проверяет**, что каждый файл
кем-то связан.

### 3.3. 15 файлов с ≤1 входящей ссылкой

`bughunt-2026-07-10.md`, `engineering-risks.md`, `game-modes-roadmap.md`,
`hud-inmatch.md`, `open-questions.md`, `playtest-hardening-roadmap.md`,
`readiness.md`, `security-a06.md`, `ship-modules-roadmap.md`,
`store-description.md`, `tech-tree-roadmap.md` — почти изолированы. Они не орфаны
(1 ссылка), но слабо встроены в граф. Найти их можно только если знаешь имя.

### 3.4. Roadmap-фрагментация

34 `*-roadmap.md` — это много. Некоторые дублируют друг друга по теме (например,
`persistence-roadmap.md` + `persistence-accounts-roadmap.md` +
`accounts-roadmap.md` + `account-level.md` — 4 файла по одной теме). Без индекса
сложно понять, какой roadmap каноничен для данной темы.

### 3.5. `state.md` — 1421 строка

Это **большой** якорь. Шапка хороша (быстрый старт), но сам файл тяжело читать
целиком. Секции §1–§11 — правильная декомпозиция, но 1421 строка в одном файле —
риск, что он станет недоступным для точечных правок. Реконсилируй-не-дописывай
помогает, но файл растёт.

### 3.6. `ALLOW` растёт

6 forward-ссылок сейчас (3 security-отчёта + 3 базовых). Каждая — с причиной и
датой, но если не следить — `ALLOW` станет свалкой. Стоит периодически чистить
(когда файл реально создаётся — убирать из `ALLOW`).

| Измерение | Оценка | Комментарий |

| **Подход** | ★★★★★ | «Граф знаний» с исполняемой целостностью — редкая зрелость |

исполняемой целостностью графа — это редко. Слабые места: 3 орфана, нет
`docs/README.md` индекса, roadmap-фрагментация.
