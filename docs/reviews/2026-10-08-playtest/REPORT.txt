Подтверждённые дефекты и нестабильный сценарий

P1 PT-01: Окно флота перехватывает выбор точки отступления

Где. Void Dominion, desktop 1280×800, общий интерфейс флота. Воспроизведено на локальном клиенте с подготовленным тестом боем; общий код используется также Sector Zero, её регрессию нужно повторить.

Шаги. Выбрать свой флот в бою → открыть «Ещё» → выбрать ручное отступление → нажать на допустимый мир, расположенный под окном состава.

Ожидалось / получилось. Окно должно освободить карту и приказ должен выйти из боя. Вместо карты на координате (640; 389,09) находится section.fc-comp; спустя 500 мс флот всё ещё имеет battleId=battle:0, назначения нет.

Уверенность. Высокая: основной smoke и диагностический запуск упали одинаково. Это дефект маршрутизации клика интерфейсом, а не отказ правил отступления.

Что проверить при исправлении. Скрывать перекрывающие окна на всех режимах выбора точки, включая desktop retreat; проверить обычный и оконный интерфейс, отмену прицела, клавиатуру, телефон. prototype/src/main.ts:9433

Доказательства. retreattest.log, retreat-diagnose.log, retreat-before-click.png / retreat-after-click.png.

P2 PT-02: CSP серверного клиента ломает скрытие части элементов

Где. Void Dominion, реальная выдача HTML через prototype/netserver с аккаунтами и PostgreSQL, Chromium. Не переношу этот результат автоматически на отдельный архив Яндекс Игр.

Шаги. Открыть сервер → зарегистрироваться → «Игра по сети» → смотреть браузер матчей, не открывая фильтр карты.

Получилось. Выпадающий список с «Nexus» уже виден поверх ползунков фильтра. Видна и кнопка обновления, у которой в разметке style="display:none", а вычисленный display:block. В консоли блокируются атрибуты style; nettest насчитал 102 таких нарушения и намеренно допускает их.

Причина. Политика разрешает хешированные блоки style, но не style-атрибуты в статической и динамической разметке. packages/server/src/securityHeaders.ts:108; известное послабление теста: prototype/nettest.mjs:220

Что исправить. Согласовать разметку и политику: скрытие через CSS-классы/hidden, динамические значения через разрешённый механизм. После этого требовать отсутствие style-src-attr нарушений в проверке фактического серверного HTML; не отключать целиком CSP.

Доказательства. nettest.log, auth-browser-transcript.jsonl, 15-void-match-browser-csp.png. Вход и исследование при этом работают.

PT-02: неоткрытый список карт перекрывает фильтр числа игроков — 15-void-match-browser-csp.png

P2 PT-03: Перебазирование эскадры нестабильно в первом браузерном прогоне

Наблюдение. Сценарий трюм корабля → порт мира, desktop 1280×800: после взведения прицела elementFromPoint(dest) вернул BUTTON вместо CANVAS. Smoke остановился до выдачи приказа.

Повторная диагностика. При дополнительном чтении DOM и снятии скриншота перед проверкой прошли все четыре комбинации: порт/трюм × ПК/телефон. В первичном снимке сохраняется компактное окно приказов.

Вывод. Подтверждено падение приёмочного сценария; постоянная неисправность самой механики не подтверждена. Возможна задержка обновления окна/прицела. Нужен тест клика сразу после взведения и после первого отрисованного кадра, без произвольного sleep как окончательного исправления.

Доказательства. relocatetest.log, relocate-diagnose.log, failure-relocate-hold-1280.json / .png; prototype/relocatetest.mjs:199

P2 PT-04: Игрок видит внутренние идентификаторы мест в режиме «Курс»

Шаги. Sector Zero → обучение или новая экспедиция → выбрать флот → «Курс».

P2 PT-05: Два процесса могут одновременно сломать первичную миграцию PostgreSQL

Условие. Свежая пустая база, два одновременных вызова migrate из отдельных пулов. Это условный риск запуска нескольких экземпляров; обычный одиночный запуск прошёл.

Результат. Один вызов успешен, второй падает с 23505 / pg_type_typname_nsp_index: тип matches уже существует. Аналогичная ошибка возникла в параллельных выбранных серверных тестах; последовательно они проходят.

Исправление. Сериализовать миграцию отдельным шагом развёртывания либо блокировкой PostgreSQL; проверить два одновременных старта на пустой базе. packages/server/src/store/postgres.ts:58

Доказательства. migration-race.log и migration-race.mjs. Потеря пользовательских данных не наблюдалась.

P2 PT-06: Доступное имя переключателя языка не содержит видимый язык

Где. Sector Zero: #sz-lang; Void Dominion: #clang, #hub-lang. Проверка axe-core 4.14, WCAG 2.1 A/AA.

Получилось. На кнопке написано «Русский», но её aria-label="Язык". Нарушение Label in Name (2.5.3): управление голосом по видимому тексту может не найти кнопку.

Исправление. Включать текущий язык в доступное имя, например «Русский — выбрать язык», и обновлять его при смене языка.

Доказательства. a11y-results.json. Один дополнительный автоматический сигнал касается подписи кошелька «Аукцион»; его нужно оценить вручную, он не посчитан отдельным подтверждённым дефектом.
