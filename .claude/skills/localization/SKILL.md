# Локализация: текст живёт в `/localization`, в коде только ключ

Правило одной строкой: **в коде нет человекочитаемого текста — есть КЛЮЧ.**

```ts
t('err.no-capacity')            // → «трюм полон» / “the hold is full”
t('fleet.eta', { n: 3 })        // '{n}' подставляет живое значение
tData('Metal Mine')             // ИМЯ игровых данных → ключ data.metal-mine
```

Это не стилевое пожелание: гейт (`prototype/src/i18n.test.ts`) роняет сборку на
русском литерале внутри `t()` и на ключе, которого нет в локали. Переходного периода
нет — `t('трюм полон')` больше не переводится, такая строка доедет до игрока как есть.

## 1. Что где лежит

| Файл | Что это |
| --- | --- |
| `localization/ru.ts` | **источник.** Плоская карта `ключ → текст`, разбита на доменные секции |
| `localization/en.ts` | английская локаль, тот же набор ключей (паритет держит тест) |
| `localization/index.ts` | `LOCALES` / `DEFAULT_LOCALE` / `LOCALE_LABEL` / `dataKey()` |
| `localization/runtime.ts` | **один рантайм на всех** (LOC-5): `t`, `tData`, `lookup`, `hasKey`, `setLocale`, `localizeStaticDom` |
| `localization/runtime.test.ts` | тест самого рантайма (поиск, подстановка, фолбэки) |
| `prototype/src/i18n.test.ts` | **гейт ключей** — 11 тестов, см. §5 |

Потребители импортируют рантайм напрямую: `from '../../localization/runtime'`
(прототип) и `from '../../../localization/runtime'` (`packages/client`). Своей копии
рантайма ни у кого нет и заводить её не надо — до LOC-5 копий было две, и они разошлись.

Порядок поиска: выбранная локаль → **русский как источник** (непереведённый ключ виден
по-русски, а не пустотой) → сам ключ (значит, опечатка — она и должна быть заметна).

## 2. Как завести новый текст (порядок обязателен)

1. **Придумай ключ:** `домен.сущность.аспект`. Точки — иерархия, kebab-case внутри
   сегмента: `err.no-capacity`, `side.build.upgrade`, `hero.ability.corridor.desc`.
   Домен бери существующий — секции в `ru.ts` подписаны (`// --- cmd — Командная
   панель флота: …`), новый домен заводи только под новый экран.
2. **Впиши ключ в `ru.ts` И в `en.ts`** — в ту же доменную секцию, по алфавиту внутри
   неё, в кавычках, отступ 2 пробела:
   ```ts
   'side.retreat': 'Отступить',        // ru.ts
   'side.retreat': 'Retreat',          // en.ts
   ```
   Оба файла обязательны сразу: тест паритета красный, если ключ есть только в одном.
3. **Только теперь пиши код:** `t('side.retreat')`. Не «напишу пока по-русски, переведу
   потом» — гейт этого не пропустит, а строка молча доедет до игрока.
4. **Прогони гейт:** `pnpm test i18n` (быстро) или `pnpm run check` (перед коммитом).

Подстановка значений — `{имя}` в тексте, объект вторым аргументом:
`'fleet.eta': 'подлёт {n} ч'` → `t('fleet.eta', { n: 3 })`.

### Статичная разметка (`prototype/build.mjs`)

Узел в разметке **пуст**, ключ стоит в ЗНАЧЕНИИ атрибута — текст приходит только из
локали, поэтому формулировка физически не может разъехаться:

```html
<b data-i18n="hub.play"></b>
<button data-i18n-title="rail.tech.title">⚛</button>
```

Атрибутные близнецы: `data-i18n-title` → `title`, `data-i18n-ph` → `placeholder`,
`data-i18n-aria` → `aria-label`. Проставляет всё `localizeStaticDom()` на старте.

### Сообщения об ошибках — ключ не пишется руками

`errText()` строит ключ из кода отказа ядра: `E_NO_CAPACITY` → `err.no-capacity`.
Новый код отказа в `shared-core` = новая запись `err.*` в обеих локалях, вызов менять
не нужно.

## 3. Имена игровых ДАННЫХ — отдельная механика

Имена в `data/*.json` и в каталоге `prototype/src/prototypeData.ts` **остаются
английскими**: `name: 'Metal Mine'`. Показывает их `tData()`, который строит ключ
слагом `dataKey()` — тот вырезает всё, кроме `[a-z0-9]`.

**Русское имя схлопнется в ключ `data.`** — перевод станет недостижим, и игрок на любой
локали увидит исходную строку. Поэтому:

- имя данных — по-английски, а русский текст для него живёт ключом `data.<слаг>`:
  `'data.metal-mine': 'Рудник'`;
- добавил здание/юнит/модуль/фиттинг/сектор/тип планеты — **сразу заведи `data.*`**,
  иначе в русском интерфейсе всплывёт английское имя (ровно так «Spaceport» дожил до
  игрока). Это ловит тест «у каждого ИМЕНИ игровых данных есть ключ `data.*`»;
- `t()` и `tData()` не взаимозаменяемы: `tData()` ждёт ИМЯ, `t()` — КЛЮЧ. Передашь ключ
  в `tData()` — страховка вернёт перевод, но это подпорка, а не разрешение путать.

## 4. Ловушки, на которых уже обжигались

- **Ключ в переменной гейт не видит.** Разбор ищет литералы в `t('…')`. Если ключ
  приходит из таблицы (`GLOSSARY`, `INTROS`, `FIRST_GOALS`, туры, поля
  `prototypeData.ts`), опечатка доедет до игрока сырым ключом. Такие таблицы должны
  хранить **ключ**, а не текст, и проверяются отдельными тестами — заводишь новую
  таблицу копии, добавь её в тест «таблицы копии отдают ключи, а не текст».
- **Тернарник внутри вызова** — `t(cond ? 'а.б' : 'в.г')` — разбор видит только первый
  литерал. Лучше выбирать ключ до вызова.
- **Дубли ключей в локали.** В объектном литерале побеждает последняя запись — молча,
  без ошибки. Держит тест «в исходнике локали нет дублей ключей» (читает ФАЙЛ, а не
  собранный объект).
- **Осиротевший ключ.** Завёл ключ и не использовал → тест сирот красный. Ключи,
  которые собираются в рантайме, перечислены префиксами в списке `DYNAMIC`
  (`err.`, `data.`, `hud.resource.`); новый такой префикс добавляй туда с объяснением,
  кто его строит.
- **Текст, уходящий через `esc()`.** Подпись кнопки экранируется — HTML из хелпера
  вроде `cost()` игрок увидит разметкой. Для таких мест есть плоские форматтеры
  (`costText()`); проверяй, куда именно уходит строка.
- **Комментарии не локализуются** — они для разработчика.

## 5. Гейт: что именно ломается

`pnpm test i18n` → `prototype/src/i18n.test.ts`, 11 тестов:

| Тест | Что означает падение |
| --- | --- |
| паритет `ru`/`en` | ключ добавлен только в один файл |
| нет дублей ключей | одна и та же строка ключа встречается дважды |
| ключи полей каталога заведены | в `prototypeData.ts` лежит ключ, которого нет в локали |
| ключ из кода заведён | `t('…')` зовёт несуществующий ключ (обычно опечатка) |
| статичная разметка на ключах | в `build.mjs` `data-i18n` без значения или с чужим ключом |
| нет осиротевших переводов | ключ в локали никто не использует |
| **в коде нет русского текста** | русский литерал внутри `t()`/`tData()` |
| в EN нет кириллицы | русский текст попал в `en.ts` |
| таблицы копии отдают ключи | таблица хранит текст вместо ключа |
| у юнита есть имя / у ИМЕНИ данных есть `data.*` | новый контент без перевода имени |

Гейт сканирует `prototype/src` **и** `packages/client/src` — оба потребителя.

## 6. Новый язык

Положить `/localization/<код>.ts` той же формы и дописать его в `LOCALES` и
`LOCALE_LABEL` в `index.ts` (подпись — на самом языке). Больше ничего. Непереведённые
ключи автоматически покажутся по-русски.

## 7. Что намеренно НЕ локализовано

`prototype/src/testmode.ts` (дев-экран), поисковые алиасы в `codexIndex.ts`
(двуязычны по назначению) и `CHAT_BADWORDS`. Трогать их не нужно.
