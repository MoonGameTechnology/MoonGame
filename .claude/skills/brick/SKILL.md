# Ритуал кирпичика

`docs/backlog.md` — назначаемый список задач. Правило: **1 кирпичик ≈ 1 PR ≈ 1 сессия,
в пределах одной зоны**. Оно не бюрократия: зона (пакет / модуль / данные) — это граница,
по которой репозиторий физически не конфликтует, поэтому две параллельные сессии могут
работать одновременно, только если каждая сидит в своей зоне.

## 1. Выбрать кирпичик

Прочитай шапку `docs/backlog.md` (`## Как взять кирпичик`, `## Зоны`, `## Статусы`) — она
первоисточник, этот файл лишь исполняет её.

Статусы из легенды: `✅` готово · `⏳` можно брать · `🔒` ждёт зависимость (в скобках — какую).
В тексте встречаются ещё `🔶` (сделан частично — остаток описан в самом кирпиче) и `❌`
(вырезано решением владельца, не задача).

- **`🔒` не берут никогда.** В скобках стоит незакрытая зависимость: у кирпича нет опоры,
  которую он предполагает (данных, API, схемы). Сделанный «вперёд» — это код против
  несуществующего контракта, который придётся переписать.
- `🔶` брать можно, но задача — **только описанный остаток**, а не переделка сделанного.
- У части кирпичей есть явная строка **«Готово, когда: …»** — это и есть приёмочный
  критерий, превращай его в тест.

Зоны (легенда в backlog): `[core]` `packages/shared-core/src/modules` (+`data`) · `[act]`
`action-layer` · `[srv]` `server` · `[cli]` `client` · `[proto]` `prototype` · `[data]`
`data/*.json` · `[docs]` `docs` · `[sec]` CI/сканеры · `[ops]` эксплуатация/хостинг.
Словарь зон машинно проверяется гейтом: он продублирован в `ZONES` в
`scripts/docs-check.mjs`. Новая зона добавляется в **оба** места, иначе `pnpm run check`
красный.

Кирпич с несколькими зонами (`[srv]` `[cli]`) — норма, если это один сквозной срез.
Два независимых кирпича одновременно — нет: PR перестаёт быть обозримым, а конфликт
с напарником становится вопросом времени.

## 2. Сверить кирпич с реальностью — до кода

Описание кирпича могло устареть относительно кода (репозиторий живёт быстрее текста).
Перед первой правкой:

- прочитай соответствующий раздел `docs/state.md` (§5 — модули ядра, §7 — прототип,
  §9 — статус этапов) и **исходники, которые собираешься трогать**;
- проверь, не закрыт ли кирпич фактически другим PR'ом (тогда задача — отметить ✅,
  а не писать код заново).

Это прямое требование `CLAUDE.md` («Verify docs against reality»): единственный дешёвый
способ не построить второй `diplomacy.declare` рядом с существующим.

## 3. Ветка

```bash
git checkout main && git pull --rebase origin main
git checkout -b <короткое-имя-под-кирпич>
```

`main` защищён (`CONTRIBUTING.md`): прямой push запрещён, всё сходится через PR с зелёным
CI. Ветвись **от свежего `main`**, не от чужой feature-ветки — `main` единственная точка
интеграции, ветка от ветки создаёт цепочку, которую нельзя смерджить по частям.

## 4. TDD-цикл

`CONTRIBUTING.md` §«Тесты и документация»: **RED → GREEN → REFACTOR → COMMIT**.

1. **RED** — падающий тест на поведение из кирпича («состояние А + действие Б → ожидаем В»).
   Тесты лежат рядом с кодом как `*.test.ts`; корневой `vitest.config.ts` их находит сам.
2. **GREEN** — минимум кода до зелёного.
3. **REFACTOR** — чистка при зелёном гейте.
4. **COMMIT** — маленький коммит.

Пока пишешь, держи инварианты ядра (`CLAUDE.md`, нарушение = баг, не стиль):

- **Детерминизм** — ни `Math.random()`, ни `Date.now()` в `shared-core` (ESLint это ловит):
  сервер и реплей обязаны получать один и тот же результат из `(state, action, ctx)`.
- **Чистота** — `applyAction` не мутирует вход; `GameState` остаётся JSON-сериализуемым,
  потому что он хранится как JSONB и переживает рестарт.
- **Только через шину** — модули не импортируют друг друга (события / хуки / capability),
  и любая точка расширения обязана мягко деградировать: нет модуля → базовый дефолт.
- **Fail-secure** — ошибка → `h.reject(code)` со стабильным `E_*`, без деталей наружу.
- **Server-authority** — клиент шлёт намерение, не состояние.

Новая механика = новый модуль в `packages/shared-core/src/modules/` (+ данные), а не правка
`kernel/` — ядро заморожено.

## 5. Гейт

```bash
pnpm run check   # = lint + typecheck + test + docs-check
```

`docs-check` (`scripts/docs-check.mjs`) — исполняемая часть правила «сверяй доки с
реальностью»: он валит гейт на битой `.md`-ссылке в `docs/` и на незнакомом теге зоны в
backlog. Красный гейт не коммитим и не мерджим.

Полезное рядом: `pnpm test`, `pnpm run lint`, `pnpm run typecheck`, `pnpm run format`,
`pnpm run prototype` (собрать `prototype/dist/void-dominion.html`),
`pnpm run dev:proto-server`, `pnpm run doctor`.

## 6. Финальный ритуал — самое забываемое

**В ТОМ ЖЕ PR, что и код:**

1. Отметь кирпичик `✅` в `docs/backlog.md` и допиши в его текст, **что реально сделано**
   (одна-две строки в стиле соседних кирпичей: механизм, коды отказа, число тестов).
2. Обнови `docs/state.md` — живой снимок. **Реконсилируй, не дописывай:** найди устаревшее
   утверждение и перепиши/удали его, а не ставь новый абзац рядом со старой правдой.
   Если изменился счётчик тестов — он в шапке `state.md`.
3. Если кирпич закрыл этап роадмапа — обнови секцию **«Статус реализации»** в
   `docs/roadmap.md`.

Почему именно в том же PR: `backlog.md` и `state.md` — общий якорь контекста команды и
следующих сессий Claude. Если код влился в одном PR, а отметка ✅ приедет в следующем, то
между ними якорь **врёт**: кто-то возьмёт уже сделанный кирпич или начнёт работу по
описанию, которое больше не соответствует коду. Пара «две живые версии одного факта» хуже,
чем отсутствие факта.

Шаг 2 — самостоятельная процедура со своими тонкостями (какая секция `state.md` владеет
фактом, откуда брать счётчик тестов, чего не трогать в `docs/reviews/**`). Она описана в
скилле **`sync-state-doc`** — открой его, а не пересказывай по памяти; здесь намеренно
только то, что нельзя забыть сделать.

## 7. PR

PR **в `main`**, маленький и сфокусированный. Шаблон `.github/pull_request_template.md`
уже содержит чек-лист (зона · `pnpm run check` · тесты · инварианты · `docs/state.md`) —
пройди его честно, а не галочками. Ревьюера пока назначают **вручную**: `.github/CODEOWNERS`
существует, но целиком закомментирован (`CONTRIBUTING.md` говорит про автоназначение по
зонам — это опережает реальность; сверяйся с файлом, а не с описанием).

## Чек-лист закрытия

- [ ] Кирпич был `⏳`/`🔶` (не `🔒`), взята одна зона.
- [ ] Ветка от свежего `main`, PR в `main`.
- [ ] Новое поведение покрыто тестами; инварианты ядра не нарушены.
- [ ] `pnpm run check` зелёный.
- [ ] `docs/backlog.md`: `✅` + что сделано.
- [ ] `docs/state.md`: реконсилирован (устаревшее переписано, не продублировано).
- [ ] `docs/roadmap.md` §«Статус реализации» — если закрыт этап.
