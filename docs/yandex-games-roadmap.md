## 0. Достоверность источников — читать первым

**Официальная документация площадки в сессии агента недоступна:** хосты `yandex.ru` и
`yandex.com` закрыты политикой egress-прокси. Всё, что касается требований площадки,
собрано из поисковых сводок по её документации и открытой сторонней обвязки SDK —
**не из первоисточника**.

Рабочее соглашение (`CLAUDE.md`, «verify docs against reality») запрещает документировать
по неподтверждённому, поэтому утверждения помечены:

- **✔ проверено** — сверено с кодом или измерено в этом репозитории;
- **◆ сверено по декларациям** — взято из `@types/ysdk@1.2.0` (DefinitelyTyped, скачан с
  npm-реестра): машинные объявления типов реального SDK. Даёт **сигнатуры** авторитетно;
  политику (лимиты, квоты, правила модерации) не даёт вовсе;
- **⚠ требует сверки** — вторичный источник о площадке (поисковые сводки);
- **⊚ сверено по открытым источникам (2026-09-22)** — прямое чтение страницы закрыто
  (проверено и `fetch`'ем, и браузером: прокси отвечает 403 на CONNECT к `yandex.ru`),
  но утверждение подтверждено ДВУМЯ независимыми каналами: поисковой сводкой ПО САМОЙ
  странице документации и сторонней обвязкой SDK на GitHub (`indiesoftby/defold-yagames`,
  `fookix/YGChecker`). Слабее, чем «открыл и прочитал», сильнее, чем блог-пересказ;
  **три ошибки этот уровень всё же пропустил** — две разобраны в «Исправлено» в §1.2,
  третью («0,33 с» вместо настоящих 2 секунд) поймал второй пакет первоисточника, и она
  показательна: цифра выглядела точной именно потому, что была придумана. Совпадение двух
  пересказов подтверждает, что пересказы читали друг друга, а не документацию;
- **✔ ПЕРВОИСТОЧНИК (YAG-0.1 и YAG-0.2, 2026-09-22)** — текст страниц **предоставлен
  владельцем**: сессия агента открыть их не может, а обходить политику (архивы, зеркала,
  кеши) README прокси прямо запрещает. Пункты цитируются по номерам — это высший
  доступный здесь уровень достоверности. Пакетов было два:
  `YAG-0.1` — «Требования к игре» (редакция **18.08.2026**) с подстраницами и страницы
  SDK «Реклама» и «Инап-покупки»; `YAG-0.2` — «Подключение и использование», «Данные
  игрока», «Расположение рекламы», «Языки и домены».

**Кирпич не берётся в работу, пока ЕГО СОБСТВЕННЫЕ ⚠-предпосылки не подтверждены.**
Правило посильнее «ждём YAG-0.1»: после сверки 2026-09-22 часть предпосылок закрыта, и
запирать на общем кирпиче работу, которой больше ничего не мешает, значит держать
мёртвый замок. Цифры площадок меняются, а ошибка здесь стоит отказа модерации —
поэтому у сверки есть ДАТА, и у требований площадки тоже: сторонний чекер фиксирует
свою сверку версией от **22.08.2026** (`requirements-version.json`), а площадка ведёт
`release-notes`. Перед подачей в модерацию сверку повторяют.

## 1. Площадка: API и политика — это разные уровни достоверности

### 1.1 API — формы ◆ по `@types/ysdk@1.2.0`, подключение и лимиты ✔ по первоисточнику

Разделение не формальное. Декларации типов дают **сигнатуры** авторитетно и не дают
ничего про то, КАК SDK подключается и СКОЛЬКО раз его можно звать; страницы SDK
(`YAG-0.2`, 2026-09-22) дают ровно это. Ниже помечено, откуда что взято.

**✔ Подключение — дословно, и путь зависит от способа размещения.** Требование 1.19.1
обязывает подключать SDK «строго так, как указано»; модерация проверяет это индикатором
лоадера на debug-панели (`W` — ждёт, `IT` — верно, `IF` — старый лоадер).

```html
<!-- Yandex Games SDK -->
<script async src="/sdk.js" onload="initSDK()"></script>
<script>
    async function initSDK() {
        const ysdk = await YaGames.init();
    }
</script>
```

**Путь — ОТНОСИТЕЛЬНЫЙ (`/sdk.js`) при загрузке архива через Консоль разработчика**, и это
рекомендуемый площадкой вариант; абсолютный `https://sdk.games.s3.yandex.net/sdk.js` —
только при интеграции через свой домен. Скачивать `sdk.js` не нужно и нельзя: при
разработке его **проксирует локальный сервер**. Скрипт обязан быть подключён ДО
`YaGames.init()` — иначе `Uncaught ReferenceError: YaGames is not defined`.

**✔ Лимиты вызовов — то, чего декларации не дают вовсе.**

| Метод | Размер на игрока | Частота |
| --- | --- | --- |
| `player.setData()` / `getData()` | **200 КБ** | 100 запросов за 5 минут |
| `player.setStats()` / `getStats()` / `incrementStats()` | **10 КБ** | 60 запросов за 1 минуту |
| `ysdk.getPlayer()` | — | 20 запросов за 5 минут |

Страница добавляет к этому прямую рекомендацию, которая для нас важнее самих чисел: **часто
меняющиеся ЧИСЛА (очки, опыт, валюта) хранить в `setStats()`, а не в `setData()`** — там
выше допустимая частота. А если данные не влезают, «используйте собственный сервер»: это
прямое разрешение площадки, а не обход её правил.

**✔ Авторизация — как попросить и как узнать отказ.**

```ts
ysdk.auth.openAuthDialog(): Promise<void>   // отказ игрока ОТКЛОНЯЕТ промис
player.isAuthorized(): boolean              // player.getMode() устарел
```

Две детали, которые меняют код, а не только текст. Первая: **после успешного входа надо
заново позвать `getPlayer()`** — прежний объект остаётся неавторизованным, и это прямо
показано в примере документации. Вторая: **отказ игрока приходит отклонением промиса**,
значит «игрок отказался» и «площадка этого не умеет» различимы по-настоящему, а не по
догадке. Страница отдельно требует объяснить игроку выгоду ДО показа окна — иначе «он
откажется и выйдет из игры».

**Жизненный цикл.**

```ts
YaGames.init<TGlobalSigned>(opts?: { signed?: TGlobalSigned }): Promise<SDK>
ysdk.features.LoadingAPI.ready(): void
ysdk.features.GameplayAPI.start(): void
ysdk.features.GameplayAPI.stop(): void
```

**Реклама — колбэки, возврат `void`, а НЕ промис.**

```ts
adv.showFullscreenAdv(opts?: { callbacks?: {
  onOpen?(), onClose?(wasShown: boolean), onError?(e: Error), onOffline?() } }): void
adv.showRewardedVideo(opts?: { callbacks?: {
  onOpen?(), onRewarded?(), onClose?(), onError?(e: Error) } }): void
adv.showBannerAdv(): Promise<{ reason?: StickyAdvError }>
adv.hideBannerAdv(): Promise<{ stickyAdvIsShowing: boolean }>
adv.getBannerAdvStatus(): Promise<{ stickyAdvIsShowing: boolean; reason?: StickyAdvError }>
```

Два следствия. Контракт `PlatformAds` из `platform-adapters.md` объявлен промисами —
значит адаптер **переводит** колбэки в промис, это не проброс. И `onRewarded` отдельно от
`onClose`: закрытие ролика наградой **не является**, что и подтверждает инвариант «награду
выдаёт игра только по подтверждённому результату адаптера».

**Покупки.**

```ts
payments.getCatalog(): Promise<Product[]>
payments.purchase(opts?: { id: string; developerPayload?: string }): Promise<Purchase | Signature>
payments.getPurchases(): Promise<Purchase[] | Signature>
payments.consumePurchase(token: string): Promise<void>
ysdk.getPayments<TSigned>(opts?: { signed?: TSigned }): Promise<Payments<TSigned>>
```

**Личность игрока — и это меняет историю с entitlement.**

```ts
ysdk.getPlayer<TSigned>(opts?: { signed?: TSigned }):
  Promise<TSigned extends true ? Signature : Player>
player.getUniqueID(): string                 // постоянный id; player.getID() УСТАРЕЛ
player.getIDsPerGame(): Promise<Array<{ appID: number; userID: string }>>
player.isAuthorized(): boolean
player.getPayingStatus(): "not_paying" | "partially_paying" | "paying" | "unknown"
player.setData(data, flush?): Promise<void>
player.getData<T>(keys?): Promise<Partial<Record<T, Serializable>>>
player.setStats / getStats / incrementStats
```

Тип `Signature` документирован дословно: *«при передаче через signature объект возвращается
не сам по себе — поле signature содержит зашифрованную строку с полями объекта, которую
можно расшифровать на вашем сервере»*. То есть площадка умеет отдавать **проверяемое на
сервере доказательство личности**, и межпродуктовый entitlement внутри площадки упирается
не в аккаунты/OIDC, а в тот же эндпойнт проверки подписи, что и покупки (`YAG-4.1`).

А `getIDsPerGame()` отдаёт идентификаторы игрока **в других играх того же разработчика** —
значит будущий First Contact увидит, что этот же человек прошёл Sector Zero, без кодов.
Код остаётся нужен только для перехода С площадки в основную игру. Первоисточник (`YAG-0.2`)
добавил два условия, которых в декларациях нет и которые меняют код: метод **доступен
только авторизованному** игроку, а перед вызовом обязательна проверка
`ysdk.isAvailableMethod('player.getIDsPerGame')` — то есть ещё до First Contact путь
упирается в гостя, и `YAG-1.4` тут предпосылка, а не соседний кирпич. Отдельно: сами
идентификаторы приходят лишь по тем играм, где игрок **явно согласился** на передачу
персональных данных, так что «увидит» — это «увидит, если разрешил».

**Остальное, чего в роадмапе не было и что стоит знать.**

```ts
ysdk.serverTime(): number
ysdk.getFlags(params?): Promise<Record<string, string>>
ysdk.getStorage(): Promise<SafeStorage>          // typeof window.localStorage
ysdk.on("game_api_pause" | "game_api_resume", observer): () => void
ysdk.onEvent("EXIT" | "HISTORY_BACK", listener): () => void
ysdk.environment.i18n.lang: ISO_639_1            // 73 языка
ysdk.environment.i18n.tld: TopLevelDomain        // 19 доменов
ysdk.deviceInfo.isDesktop/isMobile/isTablet/isTV()
ysdk.shortcut.canShowPrompt() / showPrompt()
ysdk.feedback.canReview() / requestReview()
ysdk.leaderboards.setScore / getEntries / getPlayerEntry / getDescription
ysdk.multiplayer.sessions                        // асинхронный «призрачный» мультиплеер
```

Четыре из них меняют проектирование, и им заведены кирпичи Фазы 6:

- **`serverTime()`** — у нас игра в реальном времени на клиенте. Без серверного времени
  забег промотается переводом системных часов.
- **`getFlags()`** — удалённый конфиг, то есть правку баланса можно выкатить **без
  пересдачи на модерацию** (3–5 рабочих дней). Для «проверим баланс на живых» это
  решающее.
- **`getStorage()`** — безопасная обёртка над `localStorage`, и первоисточник (`YAG-0.2`)
  сузил её роль до нуля для нашего случая: она нужна **только при интеграции через свой
  домен**, где новые версии iOS сбрасывают `localStorage`. При загрузке архива «специальная
  обёртка в SDK автоматически делает `localStorage` надёжным» — делать не надо ничего.
  Мы грузим архив (`YAG-1.1b`), так что это снятая работа, а не новая. Абстракция
  хранилища из `PVR-0.3` остаётся полезной, но уже не ради этого риска.
- **`game_api_pause` / `resume`** — площадка сообщает о паузе (например, на показе
  рекламы). Мир идёт по стенным часам: надо решить, замирает он или тикает без игрока.

Отдельно: **`isTV()` — телевизор как тип устройства**, другая модель ввода. Мы
проектируем под телефон; это стоит явно объявить вне охвата v1.

### 1.2 Политика ✔ — сверено с ПЕРВОИСТОЧНИКОМ, редакция требований 18.08.2026

Страница «Требования к игре» и её подстраницы закрыты для агентской сессии egress-политикой
(проверено браузером и fetch'ем 2026-09-22: `403` на CONNECT). **Текст первоисточника
предоставил владелец 2026-09-22** — это и закрыло `YAG-0.1`. Ниже пункты цитируются по
номерам; всё, что помечено ⚠, взято не из этой страницы, а из её подстраниц или соседних
разделов, которых в переданном тексте не было.

> **Две вчерашние правки этого раздела оказались ошибочными, и обе исправлены ниже:**
> запрет сторонней рекламы (п. 4.1) — **безусловный**, а требование «название языка на
> этом языке» — **рекомендация**, а не требование. Разбор — в «Исправлено» в конце раздела.

**Сборка.** П. 1.21: размер всех файлов **не более 100 МБ в разархивированном виде**.
П. 1.22: **в корень архива добавлен `index.html`; в названиях файлов и папок не
используются пробелы и русские символы**. П. 1.24: новые версии сохраняют основную
концепцию — подменить игру обновлением нельзя.

**Модерация.** «Обычно модерация занимает 3–5 рабочих дней». Проверка идёт **на
окружениях, приближенных к пользовательским**, и отдельной строкой: «Отсутствие
найденного замечания на устройстве разработчика не является обоснованием для снятия
замечания» — то есть «у меня работает» не аргумент. ⚠ Сроки повторной подачи (24 ч с
удвоением до 384 ч) и ускоренная проверка 1–2 дня при неизменном архиве — со страницы
«Модерация», её в переданном тексте не было.

**Авторизация — п. 1.2, и он бьёт по нашей архитектуре.** «Для запуска и использования
игры **не требуется регистрация или авторизация на сторонних сервисах**. Допустима только
авторизация с Яндекс ID». П. 1.2.1: авторизация — только после осознанного действия, с
пояснением выгоды. П. 1.2.2: **реализован гостевой вход, и прогресс при этом
сохраняется**. Наш собственный логин (ник+пароль, JWT) для площадки — сторонний сервис;
см. §1.3.

**Сохранение прогресса — п. 1.9.** «Изменения сохраняются **сразу после действия игрока
или по специальной кнопке**. После обновления страницы или смены ориентации экрана на
мобильном устройстве прогресс не теряется». Подстраница прямо называет
«Прогресс сохраняется **периодически**» неправильным вариантом, но разрешает выход:
другую механику нужно **описать в комментарии разработчика**. П. 1.11: если используются
облачные сохранения — включить соответствующую опцию в черновике.

**Покупки — раздел 1.13.** П. 1.13.1 — **подключён метод консумирования** (именно это, а
не проверка подписи). П. 1.13.2 — портальная валюта определяется автоматически, название и
иконка берутся из SDK. **П. 1.13.3 — «прогресс игры сохраняется на сервере и доступен для
одного пользователя с разных устройств»**: облачные сохранения при инап-покупках
**обязательны**. П. 1.13.4 — цена цифрами и с указанием портальной валюты. П. 1.13.5 —
описание покупки соответствует тому, что игрок получает. П. 1.13.6 — список покупок в игре
совпадает с Консолью в обе стороны.

**Реклама — раздел 4.** П. 4.1: «Реклама вызывается только через SDK Яндекс Игр.
**Отсутствует реклама от сторонних рекламодателей, в том числе статичные рекламные
изображения и текст**». П. 4.3: все блоки имеют ориентацию, соответствующую ориентации
игры. П. 4.4: реклама не мешает взаимодействовать с игрой и показывается только в
логических паузах. П. 4.7: при показе полноэкранной рекламы или rewarded video **звук и
игровой процесс ставятся на паузу**. П. 4.2: внутренний процесс сохраняется после перехода
по рекламе и возврата. П. 4.6: дополнительными блоками считаются **только стики-баннеры**,
кастомные RTB-баннеры запрещены. П. 1.16: запрещено имитировать рекламные блоки сервиса —
свои полноэкранные окна или RV с собственными кнопками.

**✔ Задержка между действием и показом — 2 СЕКУНДЫ, а не «0,33 с».** Подстраница
«Расположение рекламы» пришла со вторым пакетом первоисточника (`YAG-0.2`) и опровергла
нашу цифру: «максимальная допустимая задержка между действием пользователя и началом
рекламы — 2 секунды», и отдельной строкой — «модерация считает нарушением только явную
задержку больше 2 секунд, все случаи меньше этого времени и пограничные пройдут проверку».
Та же страница задаёт и методику: три запуска (обычный, инкогнито, другое устройство), и
если задержки не было хотя бы в одном — требование выполнено.

Правила расположения оказались богаче одного числа, и для нас это существеннее. Игры
делятся на **условно-пошаговые** (реклама сразу после действия игрока, без предупреждения)
и **в реальном времени**, где всё решает длина уровня: **короче 5 минут — реклама внутри
уровня НЕДОПУСТИМА вовсе**, только после неигрового действия; длиннее 5 минут — можно в
любой момент, но с паузой и заметным предупреждением-таймером ровно на 2 секунды.

### 1.3 Требования, которые меняют наш план

Четыре пункта первоисточника затрагивают то, что у нас уже построено или запланировано.

**1. Собственный логин несовместим с п. 1.2.** У нас вход по нику и паролю с JWT
(`packages/server`), и для площадки это «авторизация на стороннем сервисе». В сборке для
Яндекса вход обязан быть **гостевым по умолчанию**, с сохранением прогресса без
авторизации; единственная допустимая авторизация — Яндекс ID через SDK, и только по
осознанному нажатию с объяснением выгоды. Это работа `YAG-1.1b` (платформенная цель
сборки) и `YAG-1.2`, а не «когда-нибудь».

**2. Покупки тянут за собой облачные сохранения (п. 1.13.3).** Прогресс обязан быть
доступен одному игроку с РАЗНЫХ устройств. То есть `YAG-4.*` нельзя делать раньше
`YAG-2.*`: продать что-либо, не имея облачного сейва, — прямое нарушение. Порядок фаз в
этом документе оказался верным, но причина теперь не «логично», а «иначе отклонят».

**3. Периодическое автосохранение — нарушение п. 1.9 по умолчанию.** Прототип пишет соло-
и забеговый сейв **по таймеру** (4 с) плюс на `pagehide`; подстраница «Сохранение
прогресса» прямо называет «прогресс сохраняется периодически» неправильным вариантом.
Выхода два: сохранять **по событию** (конец волны, взятое усиление, конец боя) или
**описать механику в комментарии разработчика** при подаче. Дешевле первое — событие у нас
и так есть; второе оставить как страховку. Кирпич: `YAG-2.1`.

**4. Матрица платформ шире нашей (п. 1.20): iOS 9.0+, Android 5.0+, Windows Vista.**
Это очень старые рантаймы. Наш бандл собирается esbuild'ом без транспиляции под такие
цели, и `Promise`/`??`/`?.`/`structuredClone` там не везде живы. Перед подачей нужен либо
замер на нижней границе, либо явное сужение заявленных платформ в черновике (в черновике
платформы **выбираются**, и требование применяется к выбранным — п. 1.6).

**И одно, что нужно прочитать владельцу, потому что это про сеттинг, а не про код.**
П. 3.4.4 запрещает «изображения или отсылки к политике, политическим ситуациям,
политическим деятелям, внутригосударственным или межгосударственным конфликтам, **войнам**».
Void Dominion — военная стратегия: флоты, вторжения, захват миров. Запрет почти наверняка
нацелен на РЕАЛЬНЫЕ конфликты, а фантастические войны в каталоге Яндекс Игр представлены
широко, — но формулировка широкая, и решает модератор. Практический вывод, который ничего
не стоит: **в подаче и промоматериалах не должно быть ни одной привязки к реальности** —
ни флагов, ни узнаваемой геополитики, ни лексики новостей. Отдельно в нашу пользу играет
то, что на площадку идёт **Sector Zero** — PvE против инопланетного Роя, а не PvP-война
между игроками. ⚠ Если у владельца есть сомнения, это вопрос в поддержку площадки ДО
подачи, а не после отказа.

**И одно про формулировку, а не про механику.** П. 1.23 запрещает «интерактивный
искусственный интеллект». По смыслу раздела речь о генеративном ИИ, общающемся с игроком
(рядом стоит разрешение на заранее сгенерированные материалы), а не о боте-противнике:
игровой ИИ есть в любой стратегии каталога. Но слово «ИИ» в НАШЕМ тексте встречается часто
(«политики сложности ИИ», «ИИ-драйверы»), и в промоматериалах его лучше не употреблять —
пусть будут «боты» и «противники». Кода это не касается.

## 2. Что измерено и что из этого следует

### 2.1 Сохранение забега В ОБЛАКО ВЛЕЗАЕТ — но компактный сейв всё равно лучше

**Прежняя редакция называлась «НЕ влезает». Сверка 2026-09-22 это опровергла.**

**✔ Измерено 2026-09-16.** Состояние партии на карте, которую прототип играет сегодня
(`nexus`, 121 сектор): **29.3 КБ на старте, 30.9 КБ после шести игровых часов**.

⊚ **Лимит `setData` — 200 КБ** (§1.1), а не 10 КБ: «10 КБ» относится к `setStats`, куда
`GameState` не кладут в принципе (там только плоская карта чисел). Значит состояние
влезает с шестикратным запасом, и аргумент «не помещается втрое» снят.

**Форма сейва от этого не меняется, но меняется ПРИЧИНА.** Компактный дескриптор
выбирается уже не лимитом, а тремя другими доводами: частота (`setData` — 100 запросов
за 5 минут, и сохранять весь мир на каждое событие всё равно нельзя), время записи по
сети на телефоне, и совместимость версий — дескриптор переживает смену формата
`GameState`, а блоб нет. Рекомендация ниже поэтому смягчается с «обязательно» до
**«предпочтительно, и по этим причинам»**; аварийный путь «положить весь `GameState`»
перестал быть невозможным и становится честным запасным вариантом.
Маленькая карта спасает частично: `skirmish-1` (5 секторов) — 2.1 КБ на старте и 3.5 КБ
через сутки; карта забега `pve-1` имеет 7 секторов и десять волн впереди.

**Следствие для PVR-0.3 и YAG-2.1: сейв — это НЕ `GameState`.** Варианты:

- **(а) компактный дескриптор забега** — сид, сложность, номер волны, взятые усиления;
  мир пересобирается. Классическая форма сейва рогалика, влезает в сотни байт. Опирается
  на детерминизм — здесь это инвариант №1, закреплённый golden-тестами.
- **(б) лог действий + реплей** — машинерия ✔ уже есть: `ReplayLog` и `runReplay`
  (`packages/shared-core/src/replay/replay.ts`) с CI-тестом, который гоняет живую комнату
  48 игровых часов и сверяет `hashState` бит-в-бит. Точнее, но лог растёт и упрётся в тот
  же лимит.
- **(в) гибрид** — точное состояние локально, дескриптор в облако.

**Рекомендация — (а), с (в) как поведением по умолчанию.** Рогалику не нужно возвращать
позицию флота попиксельно: достаточно вернуть игрока в тот же забег на той же волне с
теми же усилениями.

### 2.2 Покупки требуют сервера, а сервер — это цель дохода

✔ **Вопрос закрыт первоисточником: серверная проверка подписи — НЕ требование
модерации.** Страница «Инап-покупки» помещает её в раздел «Защита от накруток», то есть в
меры против накрутки, а обязательной для модерации называет другое — проверку
**необработанных** покупок (`getPurchases()` + `consumePurchase()`, п. 1.13.1). Прежняя
привязка «проверка подписи = пункт 1.13.1» была ошибкой этого документа.

**Зато нашлось требование, которое меняет порядок работ: п. 1.13.3** — при инап-покупках
прогресс обязан храниться на сервере и быть доступен одному игроку с разных устройств.
Значит фаза покупок не может идти раньше фазы сохранения (§1.3). План с сервером при этом
не меняется: доход от покупок → аренда сервера. Замкнутый круг.

**Он разрывается тем, что это НЕ игровой сервер.** Проверка подписи — функция без
состояния: приняла `signature`, сверила ключом из консоли, ответила. Ни базы, ни комнаты,
ни постоянного процесса; живёт на бесплатном тарифе и к арендованному серверу матчей
отношения не имеет. Поэтому эндпойнт — самостоятельный маленький кирпич (YAG-4.1), а не
«дождёмся сервера», и он не тянет ни `packages/server`, ни Postgres.

**✔ Про доверие.** Репозиторий стоит на server-authority (инвариант 5), одиночная игра
сервера не имеет. Даже с проверкой подписи всё, что происходит ПОСЛЕ неё — выдача
купленного, состояние прогресса — остаётся клиентским и подделывается. Это ещё одна
причина держаться guardrail'ов `platform-adapters.md` §4: продавать ускорение меты, а не
исход матча.

### 2.3 Реклама за продолжение забега — отозвано

**Ранняя редакция этого файла рекомендовала rewarded-видео за продолжение забега после
смерти («одно за забег»). Рекомендация СНЯТА** после сверки с `platform-adapters.md`,
который прямо называет такое нежелательным: §4 — не продавать «неограниченное
воскрешение/перемотку поражения», §1 — rewarded ставить на бонус к **мета-награде после
завершённого** PvE, а не к результату идущего боя, и «не должен превращаться в
проигрываю → плачу → победил».

Довод того документа сильнее моего: цена смерти — это и есть то, что делает забег
забегом, а заодно то, что мы собираемся мерить. Записано здесь, а не удалено, чтобы
предложение не всплыло второй раз как свежая идея.

**Что остаётся верным:** ✔ структура забега (этапы = волны) даёт естественные паузы, и
требование площадки «только в логических паузах» (п. 4.4) выполняется по построению.
Конкретные placements берутся из `platform-adapters.md` §1–§2, а не изобретаются здесь.

**✔ И это оказалось не только нашим вкусом.** Первоисточник, п. 4.5.2: награда за
rewarded video «представляет собой дополнительный бонус… и **не должна влиять на
возможность продолжить игровой процесс**». То есть «посмотри ролик, чтобы не умереть» —
прямое нарушение требований площадки, а не спорное дизайнерское решение. Решение,
принятое по внутренним доводам, совпало с правилом — приятно, но проверять всё равно
надо было.

## Фаза 1 · Платформенный слой и сборка `[proto]`

### YAG-1.1a · Контракты `GamePlatform` и `WebPlatformAdapter` `[proto]` ✅ — M
Контракты `GamePlatform` из `platform-adapters.md` и их fallback-реализация без внешнего
SDK — та, на которой всё тестируется детерминированно.

⚠️ **Кирпич отделён от цели сборки 2026-09-21, и вот почему.** Исходный `YAG-1.1` склеивал
две вещи с РАЗНЫМИ зависимостями: контракты с заглушкой и платформенную цель сборки. Второе
действительно ждёт `YAG-0.1` — лимит архива и раскладка это его пункты. Первое не ждёт
ничего: `GamePlatform` — НАШ интерфейс, а Web-заглушка по определению «не требует внешнего
SDK». Держать её запертой на документации Яндекса значило запирать своё на чужом.

**Сделано.** `prototype/src/platform/types.ts` — контракты (`GamePlatform`,
`PlatformCapabilities`, `PlatformAuth`/`Save`/`Ads`/`IAP`/`Analytics`, словарь
`PLATFORM_EVENTS` из 10 событий). `prototype/src/platform/web.ts` — `createWebPlatform`.

**Исходов три, а не два** (`ok` / `cancelled` / `unavailable`). Свести их к `boolean`
значило бы потерять разницу между «игрок не захотел» и «здесь этого нет», а она
продуктовая: в первом случае кнопка остаётся, во втором её не должно быть вовсе.

⚠️ **`simulate` — это про РАЗРАБОТКУ, а не «пока не сделали».** В сборке игрока обычный
браузер rewarded-рекламу не показывает и платежи не проводит, поэтому `capabilities`
честно `false`. В дев-сборке (`!__PLAYER_BUILD__`) те же флаги поднимаются и отдают
управляемые исходы — чтобы путь «посмотрел рекламу → товар выдан» проходился целиком, а не
только в юнит-тесте. Проверено обеими сборками: в дев-сборке покупка за рекламу доводит
данные 0 → 4 без списания валют, в сборке игрока кнопок за рекламу и Суверены нет вовсе.

Магазин Sector Zero (`SZE-3.1`) подключён к этим capability, как и планировалось — сменой
двух флагов, без правки витрины. Покупка за рекламу идёт ДВУМЯ шагами: подтверждённый
показ, потом выдача; сломавшийся адаптер читается как «не досмотрел» (fail-secure), иначе

### YAG-1.3 · Язык от площадки `[proto]` ✅ — S
Локаль выбирается языком игрока с площадки; подставляется в уже существующую точку выбора

мы и с собственным рантаймом: `detect()` и так отдаёт `en` всему, что не `ru`. Поэтому от
прежнего правила меняется только четвёрка `be`/`kk`/`uk`/`uz` — она уходит в русский, как
у площадки. Страница «Языки и домены» (`YAG-0.2`): `ru` — резерв для этой четвёрки, `en` —
для всех прочих; рекомендованный минимум для трафика — русский, турецкий, английский.

текст вызова, и её ловила не та проверка. В чистом виде она роняет именно тест порядка.
Живой прогон собранной цели в Chromium с поддельным лоадером: браузер `ru` + площадка `en`
→ английский (и статика, и экран игры); `en` + `ru` → русский; `en` + `uk` → русский;
`ru` + `tr` → английский; явный выбор `ru` при площадке `en` → русский, в хранилище
подсказка не пишется; площадка молчит → язык браузера. `LoadingAPI.ready()` — ровно один
раз во всех шести.

игры**, не её содержимое, и подключаются лишь пока нет опубликованной версии. Это вопрос
подачи (`YAG-5.2`), а не локализации, но решается он ДО первой публикации — то есть
пропустить момент можно навсегда.

### YAG-1.4 · Гость и повышение до аккаунта площадки `[proto]` 🔶 2026-09-23 — M

«сторонний сервис» (п. 1.2), а по существу он нужен там, где есть authoritative сервер,
то есть в основной игре.

**Слияние профилей решено заранее:** при первом входе показывается ОДИН экран выбора с
честными числами обоих профилей («здесь: 12 забегов, 340 ⍟ · в облаке: 40 забегов,
1200 ⍟»), дальше выбранный становится единственным. Автоматические «облако побеждает» и
«локальный побеждает» отклонены — оба молча уничтожают прогресс; сложение счётчиков
отклонено отдельно, оно удваивает валюту при повторной синхронизации.

**Покупки только авторизованному.** Требование 1.13.3 обязывает прогресс при покупках
храниться на сервере с доступом с разных устройств, а у гостя такого прогресса нет по
определению. Площадка покупку гостю формально разрешает — но тогда купленное живёт в
одном браузере, и это возврат и жалоба, а не продажа. Правило строже площадки осознанно,
и предложение войти показывается ПЕРЕД покупкой с этой самой причиной в тексте.

**✔ Пробел закрыт `YAG-0.2` — вызовы сверены с первоисточником.** Окно открывается
`ysdk.auth.openAuthDialog()`, статус читается `player.isAuthorized()` (метод
`player.getMode()` устарел). **Отказ игрока ОТКЛОНЯЕТ промис** — значит «отказался» и
«площадка не умеет» различимы по-настоящему, и `signIn()` может честно вернуть `cancelled`
против `unavailable`, не гадая. Третья деталь меняет порядок вызовов: **после успешного
входа `getPlayer()` зовут ЗАНОВО**, прежний объект остаётся неавторизованным — то есть
`signIn()` обязан переинициализировать игрока, иначе интерфейс покажет гостя человеку,
который только что вошёл. Страница отдельно требует объяснить выгоду ДО показа окна, что
совпадает с требованием 1.2.1 и с решением «вход по кнопке с названной пользой».

⚠️ Осталась одна неизвестность, и она не блокирующая: **код отклонения**. Промис отклонить
может и отказ игрока, и сбой SDK, а различать их по тексту ошибки нельзя. Пока трактуем
любое отклонение как `cancelled` (fail-secure в пользу игрока: кнопка входа остаётся), и
это же надо проверить на живой площадке при первой подаче.

**Готово, когда:** гость играет и сохраняется; кнопка входа видна только там, где
`canSignIn`; отказ игрока отличим от «площадка не умеет»; экран слияния показывается один
раз и не теряет ни один из профилей; покупка недоступна гостю и объясняет почему.

_Сделано 2026-09-23 — контракт и оба адаптера._ `PlatformAuth` получил `canSignIn` и
`signIn(): { status, player }`. Адаптер Яндекса: вход есть, только когда у SDK есть и
`auth.openAuthDialog`, и `getPlayer`; уже вошедшему окно не показывается; отклонение окна —
`cancelled` (в журнал сбоев не пишется, иначе туда лёг бы каждый «не сейчас»); после
успеха игрок запрашивается ЗАНОВО, и если он всё ещё гость — `cancelled`, а не `ok`;
двойной тап ждёт исхода одного окна, после исхода окно снова открывается. Веб-адаптер —
`canSignIn: false` и честное `unavailable`, в том числе в симуляции. 10 тестов, мутации
**11 из 11**. «Отказ отличим от „площадка не умеет“» — закрыто.

_Остаток — и почему он ждёт, а не делается сейчас._

- **Кнопка «Войти» с названной пользой.** Польза по требованию 1.2.1 называется прямо:
  сейв в облаке и доступ с других устройств. Облачного сейва ещё нет (`YAG-2.2`), и
  кнопка сегодня обещала бы механику, которой у игрока не будет, — ровно то, что
  запрещает capability-правило. Ставится вместе с `YAG-2.2` или сразу после.
- **Экран слияния профилей.** Сравнивает локальный профиль с облачным — облачного нет
  до `YAG-2.2`. Модель решена (вариант (в), `platform-adapters.md`), строить её без
  второго профиля не на чем.
- **Стабильный id гостя.** Потребитель у него — слияние и облачный сейв; заведённый
  раньше, он был бы полем, которое никто не читает. «Гость играет и сохраняется» при этом
  уже выполнено — локальный профиль `sector-zero.progress.v1`.
- **Покупка только вошедшему** — садится на `YAG-4.2` (покупок в адаптере ещё нет).

## Фаза 2 · Сохранение `[proto]`

### YAG-2.1 · `PortableMetaSave`: компактный дескриптор забега `[proto]` 🔶 2026-09-22 — M
_Разблокирован 2026-09-22:_ квота `setData` подтверждена — 200 КБ, теперь **✔ по
первоисточнику** (`YAG-0.2`, §1.1), а не ⊚. Кирпич при этом не отменён: дескриптор
выбирается частотой записи, скоростью сети и совместимостью версий, а не размером (§2.1).
Первоисточник добавил к этому прямое указание, которое меняет ФОРМУ сейва, а не только
его размер: **часто меняющиеся числа (Варранты, счётчики забегов) кладут в `setStats`**, у
которого своя квота 10 КБ и вчетверо более щедрая частота (60 запросов в минуту против
100 за пять). То есть дескриптор забега и числовая мета — это два разных хранилища
площадки, а не одно.
Форма из §2.1(а): сид, сложность, волна, взятые усиления. Смежный кирпич — PVR-0.3
(`sector-zero-roadmap.md`), дающий абстракцию хранилища; здесь — ФОРМА того, что в неё
кладут, и её размер.
**Готово, когда:** дескриптор влезает в подтверждённый лимит с запасом, забег из него
восстанавливается на ту же волну с теми же усилениями.

**Сделано: форма и разбор — `decisions/portableRun.ts`, 25 тестов.**

_Форма оказалась меньше, чем предполагал §2.1._ Там значились «сид, сложность, волна,
усиления»; **сид не нужен вовсе**. Мир забега не случаен — он строится из фиксированной
карты (`pveMap`) одним и тем же `buildStateFromMap`, поэтому восстанавливать нечего,
кроме выбора игрока: режим, сложность, номер волны, взятые усиления и серийный номер
попытки. Это не экономия байта, а отсутствие зависимости: дескриптор не сломается при
смене генератора, потому что генератора нет. Замер: забег с десятью усилениями — **меньше
400 байт** против 29–31 КБ у состояния, то есть на два порядка.

_Порядок усилений — это история забега._ Усиления берут по одному за пережитую волну, и
`completed` хранит их в порядке взятия; сортировка была бы тихой потерей, поэтому на неё
есть отдельный тест (и мутация «добавить `.sort()`» его роняет).

_Разбор не доверяет ничему, но и не выбрасывает лишнего._ Чужая версия, дробная или
отрицательная волна, не-объект — «сохранения нет». А вот битое усиление теряет ТОЛЬКО
СЕБЯ: один неизвестный id не повод отнимать у игрока забег. Лишние поля не доезжают —
разбор собирает снимок, а не копирует вход, иначе в облако уехал бы весь блоб, от
которого кирпич и уходит. Пять мутаций (версия не проверяется, волна любая, вход
копируется целиком, дубли не схлопываются, усиления сортируются) — все пять пойманы.

_Мета сюда НЕ входит:_ звёздность, модули, герой и кошельки живут в `SectorZeroProgress`
и сохраняются раньше забега (`PVR-0.3`). Дублировать их значило бы завести второй
источник правды о прогрессе.

**Остаток (почему 🔶): восстановление из дескриптора.** Форма есть и проверена, но собрать
по ней мир — работа в `main.ts` (поднять карту, промотать до волны, выдать усиления). Шов
для неё уже есть: `YAG-1.2a` завёл `setRunActive`, единственную дверь к состоянию забега,
и восстановление по дескриптору пройдёт через неё же — иначе разметка геймплея разойдётся
с восстановленным забегом.

⚠️ **Восстановление не будет побайтовым, и это принято осознанно** (§2.1(а)): позиции
флотов, идущие бои и накопленные ресурсы не возвращаются. Игрок попадает в тот же забег,
на ту же волну, с теми же усилениями. Попытка вернуть всё попиксельно — это и есть блоб.

### YAG-2.2 · `PlatformSave` в адаптере Яндекса `[proto]` 🔒(YAG-2.1) — S
Облачное хранилище площадки как реализация контракта. Учесть квоту на частоту — писать по
событию (конец волны), не по таймеру.

## Фаза 6 · Возможности площадки, меняющие поведение мира `[proto]`

### YAG-6.1 · Серверное время вместо системного `[proto]` ⏳ — M
`ysdk.serverTime()` как источник времени для забега. Мир Sector Zero идёт по стенным часам
на клиенте игрока, то есть **перевод системных часов промотает забег** — самое дешёвое
читерство, какое бывает. Ядро времени не берёт (инвариант 1: время приходит через
`Context.now`), значит это работа адаптера и хозяина цикла, а не правка симуляции.
**Готово, когда:** забег считает время от площадки; подмена системных часов его не двигает;
отсутствие SDK (веб-фолбэк) деградирует на локальное время, а не падает.

### YAG-6.2 · Пауза площадки: что делает мир `[proto]` ⏳ — M
`ysdk.on('game_api_pause' | 'game_api_resume')`. Площадка сообщает о паузе — например, на
показе рекламы. **Это решение о поведении мира, а не подписка на событие:** мир либо
замирает (и тогда реклама даёт бесплатную паузу — игрок будет ею пользоваться), либо тикает
без игрока (и тогда ролик стоит игроку потерь). Обе модели допустимы, но выбрать надо
осознанно и одинаково для всех продуктов.
**Готово, когда:** поведение выбрано, покрыто тестом и одинаково на всех площадках через
контракт, а не через проверку имени площадки.

### YAG-6.3 · Удалённый конфиг баланса `[proto]` ⏳ — M
`ysdk.getFlags()`. Правка чисел баланса без пересдачи на модерацию (3–5 рабочих дней). Для
цели «проверить баланс на живых игроках» это разница между итерацией в день и итерацией в
неделю. Границы: флагами крутятся ЧИСЛА (длина главы, интервал волн, размеры наград), но не
правила — иначе детерминизм станет зависеть от удалённого состояния.
**Готово, когда:** числа берутся из флагов с безопасными умолчаниями; недоступность флагов
не ломает забег; тест подтверждает, что флаг не может изменить правило.

### YAG-6.4 · Кнопка «назад» и выход `[proto]` ⏳ — S
`ysdk.onEvent('HISTORY_BACK' | 'EXIT')`. На телефоне это системная кнопка, и без обработки
она выкинет игрока из игры посреди забега.
**Готово, когда:** «назад» ведёт по экранам продукта, а выход не теряет несохранённый
прогресс.

## Что НЕ делаем

- **Не проектируем экономику здесь** — товарная матрица, частоты и цены живут в
  `platform-adapters.md` как гипотезы и принимаются по данным (его §9 задаёт порядок
  проверки: сначала продукт и retention, потом деньги).
- **Не форкаем клиент и не копируем общий код** — `sector-zero-roadmap.md` §0.5.
- **Не тащим `packages/server`** — нужна одна функция проверки подписи (§2.2).
- **Не пишем цифры площадки по памяти** — §0.
- **Не делаем принудительную полноэкранную рекламу** и, как следствие, **не продаём её
  отключение** — резолюция владельца 2026-09-22, §0.6а
  [`sector-zero-economy-roadmap.md`](sector-zero-economy-roadmap.md). Отключать нечего:
  вся реклама добровольная. Записано, чтобы «а давайте ещё интерстишл между забегами» не
  всплыло как свежая идея — первоисточник её разрешает, а продукт нет.
