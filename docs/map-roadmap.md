# Map roadmap — секторная карта (плоская модель)

Технический роадмап по **карте**: модель данных, настраиваемые пути, точки
захвата, карта-как-контент и инструменты. Брики в формате репозитория
(`фаза · id · зона · статус · deps · «Готово, когда»`). Парные доки: `gdd.md`
(дизайн), `architecture.md` (ядро), `core-roadmap.md` (механики), `metagame.md`
(мета-слой), `cross-platform-roadmap.md` (рендер CP4/Голопульт).

Зоны: `[core]` shared-core · `[data]` контент/схемы · `[cli]` клиент/рендер ·
`[tools]` редактор/генерация · `[docs]` дизайн.

## 0 · Зафиксированная модель (плоские сектора)

Выбор владельца: **плоская модель, без слоя регионов.**

- **Сектор** — единственная атомарная единица карты. У него:
  - **точка захвата** — `owner` (`null` = нейтральный/незахваченный); меняется
    через бой (`combat`) или заход на необоронённый сектор;
  - **пути** — `links`, **настраиваемый элемент**, **только к соседним**
    секторам (симметричные рёбра графа; флоты ходят по ним);
  - **вид** (`kind`): `planet` / `asteroid` / `nebula` / `empty` /
    `debris_field` / `dead_world` / `void_station` (7 видов в
    `data/sectorKinds.json`) — задаёт `capturable` / `buildable` / `orbit`
    и масштаб;
  - **террейн** (модификаторы скорости/живучести) и, если это планета, **тип
    планеты** (`planetType`, бонусы добычи/обороны);
  - гарнизон, застройка, ресурсы, трейты.
- **Планета — это сектор, просто меньше**: подтип сектора (`kind: planet`),
  захватываемый и застраиваемый, с `planetType`. `empty` — необоронённый
  путевой узел (не захватывается), `asteroid`/`nebula` — промежуточные виды.
- **Регионов (групп секторов) нет.** Это сознательно отложено — см. §5.

### Геометрия — мозаика провинций (как у Bytro) ⚠️ уточнено

Изначально геометрия была понята неверно — как **граф точек-узлов + явные лейны**
(в духе Stellaris). Правильно — **карта-мозаика провинций как у Bytro** (Supremacy
1914 / Call of War / Iron Order):

- сектор — это **залитая ячейка** (провинция), а не точка; ячейки **замощают всю
  карту** без пустот;
- **соседство = общая граница** (не явные лейны). «Пути к соседям» = смежные
  провинции; дальние — авто-маршрутом через цепочку соседей (Дейкстра, уже есть);
- границы строятся **взвешенным Voronoi (power-diagram)** из центров+`size`: ресайз
  одного сдвигает общие границы соседей равномерно;
- рендер — **политическая карта**: заливка по владельцу + границы + столицы + армии.

`links` пока остаются для движения; привести соседство к границам мозаики и убрать
«пустые» путевые узлы — задача выравнивания данных (см. M4.1 / §5).

### Коллизия термина «сектор» (разводим в M0)

Сейчас слово занято трижды и это противоречиво:

| Где | Значение сейчас | Куда по модели |
|---|---|---|
| `gdd.md` | **регион** из планет + бонус «контроль целиком» | → отложено (нет регионов), см. §5 |
| `shared-core` `Planet.sectorType` | **террейн-тег** узла (`empty_space`/…) | → переименовать в `terrain` |
| `Planet` (тип) | узел карты | → **это и есть «сектор»** |
| прототип `SECTOR_TYPES` | вид узла (planet/asteroid/…) | → `kind` сектора в данных (M2.1) |

Итог термина: **Сектор = `Planet`-узел**; «вид» = `kind`; «террейн» = бывший
`sectorType`. Слово «сектор» больше не значит «регион».

## Фаза M1 · Карта как контент (data-driven)

> Сейчас карта собирается двумя несовместимыми путями: прототип — процедурно
> (`withNeighborLinks`, RNG-граф), сервер — хардкодом в `scenario.ts`. Цель —
> **одна карта = данные**, как остальной контент (`data/*.json` + zod).

### M1.1 · Схема карты `data/maps/*.json` `[data]` — ✅
**Цель:** карта — валидируемый контент. **Сделано:** `shared-core/data/mapSchema.ts`
(`MatchMapSchema` + `parseMatchMap`/`safeParseMatchMap`): сектор `{ position, kind,
terrain?, planetType?, owner?, buildings?, garrison? }` + рёбра `paths` (пары
соседей) + `players` + `fleets`. Пример `data/maps/skirmish-1.json`. Тесты
`mapSchema.test.ts` (парс + дефолты + отказ кривых). `kind` пока несётся данными,
проецируется в ядро в M2.1.
**Готово, когда:** ✅ карта парсится zod-схемой, кривая отвергается.

### M1.2 · Загрузчик карты → `GameState` `[core]` — 🚧
**Цель:** из карты-данных строить начальное состояние. **Сделано:**
`buildStateFromMap(map, data, opts)` (`shared-core/state/buildFromMap.ts`):
строит planets из секторов, **выводит `links` из undirected `paths`** (sorted,
симметрично), players, fleets; чистый/детерминированный; fail-secure (бросает
`E_INVALID_MAP`). Тесты `buildFromMap.test.ts` (стейт, links, hp, детерминизм).
**Осталось:** подключить dev-сервер и прототип к загрузке карты-файла (прототип
зависит от M4.1 — рендер из стейта, а не из `MAP`-константы).
**Готово, когда:** прототип и сервер стартуют из одной карты-файла.

### M1.3 · Валидация путей: только к соседям `[core]` — ✅
**Цель:** инвариант «пути только к соседним секторам». **Сделано:**
`validateMatchMap` — **neighbour-only**: ребро `a–b` валидно, только если между
концами никого нет. Критерий с `M2.4` — **габриэлев** (никого внутри круга с `a–b`
как диаметром); до этого стояло relative-neighbourhood, которое само по себе
держало степень любого узла на 2–3 и не давало местности ничего урезать. Плюс
симметрия/без self-loop/без дублей, связность графа (BFS), существование
владельцев/целей флотов и (с данными) террейна/типа/юнитов/построек. Тесты:
дальнее ребро → `E_PATH_NOT_NEIGHBOR`, изолят → `E_MAP_DISCONNECTED`, и т.д.
**Готово, когда:** ✅ карта с «дальним»/односторонним путём не проходит.

## Фаза M2 · Сектор как сущность (механика)

### M2.1 · Виды секторов (`kind`) в данные `[core]` `[data]` — ✅
**Цель:** перенести прототипный `SECTOR_TYPES` в контент+ядро. **Сделано:**
`data/sectorKinds.json` (7 видов: planet/asteroid/nebula/empty/debris_field/
dead_world/void_station + `capturable`/`buildable`/`orbit`) + `SectorKindDefSchema`
+ `data.sectorKinds`; поле `Planet.kind`;
аксессоры `sectorKindDef`/`isCapturable`/`isBuildable`/`hasOrbit` с мягким
дефолтом (нет вида → всё разрешено). **Мягкий дефолт стоил двух багов:** он пермиссивен,
поэтому вид без ростера получает весь каталог, а флаг, который никто не спрашивает,
не отличим от работающего. **ORB-1 (2026-09-10):** `orbit` из объявленного,
но неспрашиваемого флага стал правилом — орбитальный слой (бомбардировка сверху +
ответ ПКО) есть ровно у `planet` и `void_station`; см. `state.md` §5 «orbital». Загрузчик карты проецирует `kind`; шиппед-
лоадеры читают `sectorKinds.json`; прототип получил `kind` на узлах + `sectorKinds`
в данных (пустота снова незахватываема). Валидатор карты ловит `E_UNKNOWN_KIND`.
**ORB-4:** то же самое с `buildable` — он тоже не спрашивался никем, кроме рендера, и
астероид принимал все двадцать зданий; теперь `building.construct` спрашивает флаг ДО
ростера, ростер астероида переехал из UI прототипа в данные, а голдён-таблица шипнутого
каталога (`construction-shipped-roster.test.ts`) требует РЕШЕНИЯ по каждому новому виду.
**Готово, когда:** ✅ новый вид добавляется данными, без правок логики.

### M2.3 · Масштаб / вес сектора (планета = меньше) `[core]` `[cli]` — ✅ (интерактивный ресайз — в M3.1)
**Цель:** размер как свойство сектора, влияющий на территорию; ресайз сектора
двигает границы соседей. **Сделано:** поле `Planet.size` + `size` в схеме карты
(default 1) + проекция в загрузчике; `newGame` задаёт вес по виду (планеты —
мелкие, поля/туманности крупнее). **Чёткие** границы **уже в коде**

против поглощения соседа, клип к границе карты); бóльший сектор занимает больше
территории, ресайз сдвигает общие границы соседей.
**Осталось:** интерактивный ресайз (мышью двигать границы) — в редакторе **M3.1**.

### M2.4 · Связность — свойство местности, а не координат `[core]` `[data]` — ✅
**Замысел владельца 2026-09-18:** «логически, космически, научно обосновать, почему из
этой провинции нет больше путей. По логике должно быть много связей, но без перебора, и
надо добавить новые типы местности, которые обладают меньшими связями».

**Что было — измеримо.** Все четыре шипнутые карты объявляли **100%** геометрически
возможных связей. То есть связность не была свойством мира: сколько пар оказалось рядом,
столько и связей, а «тупик» означал лишь то, что автор не поставил рядом точку.

**Сделано — две ступени.** Геометрия ПРЕДЛАГАЕТ, местность РЕЖЕТ:

1. `validateMatchMap` перешёл с relative-neighbourhood на **критерий Габриэля**. Старое
   правило само держало степень узла на 2–3, поэтому никакой бюджет местности до него не
   доживал. Габриэль строго ШИРЕ прежнего, так что ни одна существующая карта не
   сломалась. (Замер к §6.1 проектного документа о местностях
   и областях, PR #1066: у Voronoi-генератора Frontier против старого правила расходилось
   ~50% рёбер, против Габриэля — ~13%, то есть два пути геометрии сблизились втрое.)
2. `SectorTypeDefSchema.maxLinks` — сколько трасс несёт среда. Нарушение →
   `E_SECTOR_OVERLINKED:<сектор>:<степень>><бюджет>`.

| местность | трасс | обоснование |
| --- | ---: | --- |
| `deep_void` | 6 | открытая пустота |
| `empty_space` | 5 | открытый космос |
| `nebula`, `solar_flare_zone` | 4 | глушит, но проходимо |
| `asteroid_field`, `dense_nebula` | 3 | коридоры между камнями / плотный газ |
| `ion_storm`, `derelict_graveyard` | 2 | узкие окна |
| **`asteroid_cluster`** (новая) | **1** | один подход, тупик |

**Новая местность — плотное скопление астероидов** (карточка `TER-08` и уточнение
владельца §5.3 из того же документа, PR #1066):
−50% скорости, +35% живучести, **добыча металла от самой местности** (`baseOutput` +
`productionByResource` на оси `terrain`, решение владельца — не через постройку). Приз
оплачивает цену: медленно и вход один, зато богато.

**Карта `pve-1` пересобрана под это.** 12 секторов, геометрия предлагает 24 связи,
объявлено 16, **местность срезала 8**. Шесть секторов стоят РОВНО на бюджете — ограничение
настоящее, а не декоративное. Маршрутов от улья до дома стало 12 (было 2). Тупиков ровно
два: улей и скопление, причём у скопления оба геометрических соседа — обычное астероидное
поле, то есть ядро внутри массива, а не голый тупик (критерий 3 из §11 того же документа).

Параллельные пути через провинцию этот кирпич не делал — их закрыл `M2.5` ниже.

⚠️ **`gravity_shear` заведён и убран в той же правке:** роль «горловина на два выхода» уже
закрыта `ion_storm` с бюджетом 2, а карточка `TER-05` прямо советует делать горловину
конфигурацией провинций, а не новым типом.

### M2.5 · Параллельные пути через провинцию `[core]` `[data]` — ✅
**Замысел владельца:** «через провинцию могут проходить параллельные пути» — то есть у
провинции может быть много связей, но не все они соединяются между собой.

**Что было.** Любая провинция была ПОЛНОЙ РАЗВЯЗКОЙ: войдя любой связью, флот выходил
любой другой. Две трассы, пересекающиеся в одной точке, автоматически соединялись, и
«много связей» всегда означало «сюда можно свернуть откуда угодно куда угодно».

**Сделано.** Сектор объявляет, какие пары соседей соединяются СКВОЗЬ него:

```json
"crossing": { …, "transit": [["core","ridge"], ["shoal","shear"]] }
```

Поля нет — полная развязка, как было и как осталось у большинства секторов (поэтому ни
одна существующая карта не изменилась). Поле есть — перечисленные пары единственные, через
которые проходят насквозь.

**Маршрутизация пошла по парам (узел, линия, которой вошёл).** Иначе Дейкстра молча
перескакивала бы между линиями, которые не встречаются. Состояние расширяется ТОЛЬКО там,
где транзит объявлен: у остальных секторов входящая линия на ответ не влияет, они остаются
одним состоянием, и большие карты не платят ничего.

**На `pve-1`** вертикаль `core — crossing — ridge` и горизонталь `shoal — crossing — shear`
лежат в одной точке и не соединяются:

| маршрут | результат |
| --- | --- |
| `hive → home_a` | `ridge → crossing → core → home_a` — вертикаль работает |
| `shoal → shear` | `crossing → shear` — горизонталь работает |
| `hive → shoal` | `ridge → crossing → core → home_a → drift → shoal` — **срезать нельзя** |

То есть Рой, идущий по хребту, больше не сворачивает на перекрёстке во фланг.

⚠️ **Остановка снимает ограничение, и это записано, а не спрятано.** Отправление — не
транзит: флот стоит, а не проходит. Значит правило берёт ВРЕМЕНЕМ (лишний приказ плюс время
прилёта), а не абсолютной стеной. Закрыть до стены можно двумя способами — запретить
парковку на развязках (`kind: empty` и так не захватывается) либо помнить в состоянии, какой
линией флот прибыл; второе делает флот «застрявшим в полосе» и в состоянии пока не нужно.

**Валидация проверяет достижимость так, как реально летает флот** — по тем же парам, из
каждого сектора (`E_TRANSIT_UNREACHABLE`). Обычная связность этого не видит: транзит может
оставить сектор связанным на графе и недостижимым для любого флота. Плюс
`E_TRANSIT_NOT_NEIGHBOR` (пара ссылается на несоседа — молча ничего бы не делала),
`E_TRANSIT_SELF`, `E_TRANSIT_DUPLICATE`.

**Манифест модулей НЕ бампался, и вот почему.** `Planet.transit` проецируется из карты при
загрузке и модулями не изменяется. У состояния, созданного раньше, поля нет нигде, то есть
все секторы остаются полными развязками и маршруты идентичны прежним — правила старого матча
не поменялись. Бампать значило бы уронить идущие матчи ради правки, которая на них доказуемо
не влияет.

### M2.6 · Непроходимость перестала быть декоративной `[core]` `[data]` — ✅
**Находка.** Флаг `traversable: false` живёт в каталоге с `M2.1`, но читался РОВНО В ОДНОМ
месте — `hero.ts`, личный коридор. Ни `planRoute`, ни ворота `fleet.move`, ни проверка
связности его не видели. Шипнутая чёрная дыра была непроходима только потому, что
генератор случайно не дал ей рёбер: соглашение, а не правило.

**Сделано — правилом, без правки маршрутизатора.** Непроходимому сектору не нужен
роутер: он **запирает собой**. Правило соседства уже убивает любую трассу, которая прошла
бы сквозь занятое им место, — значит достаточно двух вещей:

1. **В него нельзя вести трассу** — `E_IMPASSABLE_HAS_LANE:<сектор>`. Нет рёбер — нечему и
   маршрутизироваться.
2. **Достижимости с него не спрашивают.** Связность раньше требовала дойти до КАЖДОГО
   сектора, поэтому барьер ронял карту в `E_MAP_DISCONNECTED`, и автору оставалось либо
   просверлить в барьере трассу, либо выключить проверку — оба варианта барьер и убивают.
   Теперь требование распространяется на то, куда флот может войти (критерий 6 §11
   проектного документа, PR #1066).

**Каталог: две карточки из шестнадцати.**

- **`rift`** (`TER-02`, пространственный разлом) — вид объекта: дыра в карте. Не
  захватывается, не застраивается, очков не даёт, трасс не несёт. Делит фронты тем, что
  занимает место.
- **`depleted_system`** (`TER-14`, истощённая система) — СРЕДА: навигация обычная (+10%
  скорости — выработано, зато чисто), добыча срезана (`metal −40%`, `credits −25%`),
  очков 1, пять трасс. Держат её за ПОЛОЖЕНИЕ, а не за доход — ровно формулировка карточки.
  Первый в проекте отрицательный множитель добычи, поэтому схема получила пол `−1`: ниже
  множитель сменил бы знак и сектор начал бы ТИХО СЛИВАТЬ казну.

**Почему именно эти две, а не все шестнадцать.** Документ прямо говорит: «все 16 пунктов
не нужно автоматически превращать в 16 новых `kind`». Разбор по карточкам:

| уже закрыто существующим | заперто отсутствующей механикой |
| --- | --- |
| `TER-03` штормовой фронт → `ion_storm` (дубль запрещён) | `TER-07` сенсорная туманность → нужна механика разведки |
| `TER-05` горловина → конфигурация путей | `TER-09` гравитационное течение → направленная стоимость ребра |
| `TER-06` узел навигации → `empty_space`/`deep_void` + `transit` | `TER-10` зона пульсара → периодический износ |
| `TER-01` карман, `TER-04` анклав → композиции | `TER-13` кладбище → конечный сальваж |
| `TER-11` пояс, `TER-12` энергетика → существующие виды и `planetType` | `TER-15` биомассив → система заражения Роя |
| `TER-16` карантин (статичный) → бюджет связей | `TER-16` подавление → снято этим кирпичом |

Завести остальные записями в каталоге значило бы ровно то, от чего документ
предостерегает: они лежали бы и ничего не делали.

⚠️ **В `pve-1` ни `rift`, ни `depleted_system` НЕ поставлены.** Разлом потребовал бы
пересобрать выверенную раскладку бюджетов, а истощённая система — решения о экономике
забега, которого владелец не принимал. Обе держатся тестами на синтетических картах;
документ это и разрешает: «всё содержимое каталога сохраняется, но не обязано
одновременно попадать в первую карту».

### M2.7 · Граница, через которую нет пути, видна как барьер `[cli]` `[proto]` — ✅
**Замысел.** Вся работа `M2.4`–`M2.6` — бюджет связей, транзит, непроходимость — живёт в
данных и маршрутах, а игрок её не видит. Первый порыв был неверным и записан здесь, чтобы
не повторился: **рисовать лейны нельзя.** §0 этого файла фиксирует ровно обратное как уже
ИСПРАВЛЕННУЮ ошибку — геометрия не «граф точек + явные лейны в духе Stellaris», а мозаика
провинций как у Bytro, где **соседство = общая граница**.

**Значит чинить надо границу, а не добавлять линии.** В мозаике общая граница ЧИТАЕТСЯ как
«здесь можно пройти». Если пути нет, граница молча обещает переход, которого не существует.

**Сделано.** `classifyBorders` (общий рендер территории, `packages/client`) получил корзину
`sealedEdge` и необязательный предикат `sealed(a, b)`. Ребро помечается АДДИТИВНО: оно
по-прежнему классифицируется по владению, поэтому закрытая граница читается и как «чья», и
как «закрыта». `drawTerritory` штрихует её последней, фиолетовым — тем же, что несёт `rift`
в каталоге. Цвет намеренно вне циановой семьи карты: «закрыто» не должно читаться как
оттенок «чьё».

**Барьер рисуется по двум правилам, и оба — решения владельца.**

1. **Только там, где мир его объясняет** — одна из сторон непроходима. Причина в замере:
   на песочнице прототипа **341 граница мозаики против 170 путей**, то есть барьером
   оказались бы **59%** всех границ, и карта превратилась бы в лабиринт. Данные при этом не
   врут — расходятся мозаика (Вороной) и граф связей (соседство RNG). Это та самая «задача
   выравнивания данных» из §0, и она остаётся открытой.
2. **Только там, где игрок знает обе стороны.** Неразведанный подход — «неизвестно», а не
   подтверждённо закрыто (§3.2 каталога местностей).

⚠️ **Ловушка, стоившая бы молчаливого нуля.** `SECTOR_TYPES` в прототипе строится из
ФИКСИРОВАННОГО UI-списка, и новый вид каталога (`rift`) в неё не попадает. Спросить
непроходимость через неё — значит получить «проходим» и не нарисовать барьер НИКОГДА.
Поэтому `isImpassableKind` выведен из каталога тем же способом, что `capturable`/`buildable`,
и на это стоит отдельный тест.

⚠️ **На `pve-1` барьеров сейчас не видно:** разломов там не поставлено, а две расходящиеся
границы (`drift—hive`, `hive—veil`) объяснения в мире не имеют и потому молчат.

**Открытым остаётся расхождение трёх графов**, и это выбор владельца, а не недоделка:
мозаика рисует по Вороному, валидатор разрешает по Габриэлю (`M2.4`), песочница проложила
связи по соседству RNG. §0 предписывает свести связи к границам мозаики — но это спорит с
бюджетом связей из `M2.4`, который режет их НИЖЕ геометрического соседства. Одновременно
верным быть не может.
