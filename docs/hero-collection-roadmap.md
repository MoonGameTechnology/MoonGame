# Коллекция героев: типы, редкость, сборка под себя — технический roadmap

> Видение владельца: герой — **пустая болванка**, которую игрок собирает сам. Редкость даёт
> число слотов, скиллы приходят из инвентаря, предрасположенность даёт бонус к части
> скиллов, а детальки для повышения редкости падают в конце матча или покупаются на
> аукционе. Сегодня в коде есть только «адмиралы» с заранее выданными способностями.
> Парные доки: `heroes.md` (дизайн героев), `state.md` §5 (hero/heroEffects), `gdd.md` §6.2
> (три типа), `arsenal-roadmap.md` (мета-инвентарь), `economy-roadmap.md` (аукцион, осколки,
> заточка), `backlog.md` (закрытый блок HERO-0..9 — сессионная половина).
> Формат — кирпичики: `id · зона · статус · «Готово, когда»`. Зоны: `[core]` · `[data]` ·
> `[proto]` · `[srv]` · `[docs]`.
>
> **Префикс `HC-*`, а не `HERO-*`:** `HERO-0..9` — закрытый блок в `backlog.md`
> (внутриматчевая система героев), переиспользовать его id нельзя.

## 0. Модель (read first)

### 0.1 Две РАЗНЫЕ оси, которые нельзя мешать

| | Сессионная ось (есть) | Мета-ось (видение) |
| --- | --- | --- |
| Что это | герой внутри матча | герой как собственность аккаунта |
| Прокачка | дерево навыков за **ресурсы сессии** (`data/heroSkillTrees.json`: `requires`/`cost`/`grants`) | детальки, редкость, инвентарь скиллов |
| Живёт | в `GameState`, умирает с матчем | на сервере, между матчами |
| Готовность | **✅ построено** (блок HERO-0..9) | **почти ничего** |

Кирпич обязан называть свою ось. Правка сессионного дерева не приближает мета-коллекцию, и
наоборот — это разные механизмы, а не разные стадии одного.

### 0.2 Пять типов из видения против кода

| Тип владельца | Что в коде |
| --- | --- |
| **Основной (мейн)** | `grade: 'main'`, 4 слота, зовётся позывным игрока — **только в прототипе** (`prototype/src/heroes.ts`) |
| **Герои по редкости** | `HERO_GRADES` common/rare/legendary = 1/2/3 слота — тоже только в прототипе |
| **Учёные** | ✅ **есть и работают**, но ОТДЕЛЬНОЙ сущностью: `data/scientists.json`, совет до 2, хук `research.slots`, гейты `has_scientist`. По функции — ровно «пассивки + открывают ветки» |
| **Губернатор** | ❌ только в `gdd.md` §6.2 (Адмирал / Губернатор / Генерал), кода нет |
| **Наземный герой** | ❌ там же, кода нет |

Сейчас все 4 архетипа (`data/heroes.json`) — флагманы на корабле, то есть только «адмиралы».

**Учёных вторым способом НЕ заводить.** Тип 3 из видения уже закрыт другим механизмом;
объединять их с героями стоит максимум в интерфейсе (одна витрина «штаб»), но не в данных —
иначе получится второй `scientist` рядом с первым.

### 0.3 Развилка, которую надо снять до любого кода

**Слоты героя считаются двумя несовместимыми способами одновременно:**

- **ядро** берёт их от АРХЕТИПА — `data/heroes.json`: `commander` 4, `ravager` 3,
  `vanguard` 2, `warden` 1; именно это число ограничивает `hero.fit`;
- **прототип** берёт их от РЕДКОСТИ — `HERO_GRADES` 1/2/3/4 (`prototype/src/heroes.ts`).

Ядро при этом редкость НОСИТ, но не применяет — `gameState.ts`: *«Rarity tier … Drives the
client roster's module-slot count; the core carries it but does not enforce slots»*.

Пока развилка не снята, любой кирпич про слоты будет чинить одну половину и ломать другую.
Это задача класса CONV («реализованное дважды сводится к одному»), поэтому она первая.

### 0.4 Что из мета-оси УЖЕ работает — и это больше, чем кажется

**Паттерн «собери героя из инвентаря аккаунта» существует для ФИТТИНГОВ.** `hero.fit`
гейтится владением: если у места есть снапшот арсенала, ставится только то, чем аккаунт
владеет (`hero.ts`, гейт ARS-3), иначе отказ. `PlayerArsenal` — это
`{hulls, modules, fittings}`, а `ArsenalItemKindSchema` знает вид `hero_fitting`.

То есть половина «игрок сам собирает героя» уже построена — но только для фиттингов
корабля, не для способностей. Вторая половина (способности как предметы) — это HC-2.

**Дроп в конце матча тоже есть:** `dropTables.json` (1 место — 60%, топ-3 — 35%, дальше —
20%, pity за 4 сухих матча, exactly-once на (матч, аккаунт)) плюс сальваж-осколки за павший
вражеский состав. Но **пул содержит только корпуса и модули** — ни героев, ни скиллов.

### 0.5 Чего нет вовсе

- **Предрасположенность** — 0 совпадений по всему репозиторию.
- **Герой как предмет аккаунта.** Герой сегодня — экземпляр архетипа внутри матча, а не
  собственность. Комментарий `prototype/src/heroes.ts` помечает это прямо: *«Grade is an
  intrinsic property of a hero … the player doesn't pick it; **until a hero acquisition/
  collection system lands**, the roster is a fixed set of default heroes»*.
- **Пустая болванка.** Герой рождается со `startAbilities`/`startPassives` из архетипа —
  прямо наоборот видению.
- **Повышение редкости за детальки.** Осколки есть (сальваж), но это вход для крафта
  МОДУЛЕЙ (`EC-2.2`), а не редкости героя.

### 0.6 Шесть способностей из видения (2026-09-07): половина уже в игре

Владелец назвал шесть способностей. Проверка по коду ДО обсуждения (скилл `brainstorming`
§1) меняет разговор: две из них давно работают и переросли своё описание, ещё две
упираются в уже существующий шов, и только одна требует механики, которой нет.

| Идея владельца | В коде | Цена |
| --- | --- | --- |
| **Коридор** | ✅ `corridor` (`type: temp_lane`), три ступени дерева `overclocked_helm` → `corridor_sustained` → `corridor_open` | 0 |
| **Разведка** | ✅ `scan` (`type: reveal`), три ступени `psi_veil` → `psi_weak_points` → `psi_evasion` | 0 |
| **Пассив «скорость флота в радиусе»** | 🟡 пустая клетка ЗАПОЛНЕННОЙ матрицы | только JSON |
| **Варп-прыжок** | 🟡 обобщение `recall` | один провайдер |
| **Фантомный радарный сигнал** | 🟠 механики нет, но шов есть (`SignatureContact`) | эффект + чтение в проекции |
| **«Опытный командир» — юниты союзника** | 🔴 шва нет вовсе | новый механизм |

**Коридор сильнее своего описания.** Ступень 3 (`corridor_open`) не просто продлевает
проход — она открывает его СОЮЗНИКАМ вместе с ускорением, а противнику даёт дорогу, но не
скорость (`hero.ts`, хук `fleet.speed`, ветка `laneIsPublic && isAllied`). Это уже сыграно
и покрыто тестами; заводить «коридор» второй раз нечего.

**Разведка тоже переросла «просто вскрыть туман».** Ступени 2–3 делают просвеченную зону
боевой: враг внутри получает +5% урона, свои и союзники — −5% входящего
(`heroEffects.ts`, `revealZoneFactor`). Зона живёт в проекции ВЛАДЕЛЬЦА скана и к сопернику
не течёт.

**Пассив «скорость в радиусе» — одна запись в `data/heroPassives.json`.** Пассив
описывается парой `hook × scope`; словари — `HERO_PASSIVE_HOOKS` (`fleet.speed`,
`combat.damage`) и `HERO_PASSIVE_SCOPES` (`heroFleet`, `ownFleetsNear`). Матрица 2×2,
занято три клетки: `fleet.speed`×`heroFleet` — `vanguard_impulse`,
`combat.damage`×`ownFleetsNear` — `rally_beacon`. Четвёртая — ровно то, что просит
владелец, и она УЖЕ исполняема: `passiveApplies` умеет `ownFleetsNear` с радиусом, а хук
`fleet.speed` получает узел (`passiveBonus(h, 'fleet.speed', owner, { fleetId, node: from })`).

> Деталь, которую надо знать ДО баланса: хук получает узел ОТПРАВЛЕНИЯ (`from`). Значит
> пассив ускоряет флоты, **стартующие** в радиусе от героя, а не пролетающие мимо. Это
> осмысленно (герой командует сбором, а не подгоняет чужой транзит), но это решение, а не
> само собой разумеющееся.

**Варп-прыжок — это `recall` с целью.** `recall` уже телепортирует корабль героя в столицу
со всеми нужными защитами: нельзя выдернуть корабль из активного боя (`E_FLEET_BUSY`),
нельзя прыгнуть туда, где уже стоишь (`E_SAME_LOCATION`). Прыжок отличается ровно одним:
цель — узел в радиусе вместо `hero.home`. Радиус-гейт (цель существует, цель в дальности)
диспетчер `hero.ability` применяет ГЕНЕРИЧЕСКИ до вызова эффекта, так что провайдеру
остаётся перенос. Флот переносится целиком — десант в трюме едет с кораблём.

**Фантом — не флот, а запись в проекции.** Соблазн сделать «фейковый сигнал» настоящим
пустым флотом надо погасить сразу: пустой флот лезет в бой (`fleetOps.ts` отдельно
запрещает «бой призраков» — `E_NO_FLEET`), в захват и в подсчёт победы. Правильный шов —
`SignatureContact {location, size}`: массив `signatures` собирается ПО ЗРИТЕЛЮ внутри
`visibleState`. Значит фантом живёт записью на герое (по образцу `activeReveals`), а
подмешивается только в проекцию ЧУЖИХ. Фальшивого флота в `GameState` нет ⇒ детерминизм,
бой и захват не тронуты вовсе.

**«Опытный командир» — единственная идея без шва.** Владелец флота не меняется нигде:
`.owner =` встречается только у планет (`captureOnArrival.ts`, `combat.ts`). Опереться
стоит на обмен картами: `mapShare` — двусторонний договор с предложением и принятием
(`setMapShareOffer` → `setMapShare`, снятие при войне), то есть союзник СОГЛАШАЕТСЯ, а не
отдаёт молча.

**Отдельно про «самый редкий, красный».** Редкости у способности сегодня нет: `rarity` не
встречается в `schemas.ts` ни разу, а `Hero.grade` — редкость ГЕРОЯ, и ядро её носит, но не
применяет (§0.3). Пока не закрыт HC-2.1 (способности как предметы инвентаря), «красная
способность» может быть только дорогим узлом дерева на дальней ветке. Прыжок это не
блокирует: сделать сейчас, покрасить потом.

## Фаза 1 · Сессионная половина под новую модель `[core][data]`

### HC-1.1 · Ядро применяет слоты по редкости `[core]` 🔒(HC-0.1) — M
**Подзадачи:** перенести кап слотов с `archetype.slots` на `Hero.grade` (если так решит
HC-0.1); `hero.fit` считает бюджет по редкости; прототипный `heroSlots()` перестаёт быть
второй правдой и читает то же самое; поднять `version` модуля `hero`.
**Готово, когда:** число слотов одинаково в ядре и в прототипе по построению, а не по
совпадению; покрыто тестом на каждую ступень редкости.

### HC-1.2 · Герой как пустая болванка `[core][data]` 🔒(HC-1.1) — M
**Подзадачи:** снять `startAbilities`/`startPassives` из `data/heroes.json` (или оставить
пустыми) — герой приходит без способностей; игрок вставляет их в слоты сам; предусмотреть
миграцию: старые сохранённые состояния несут заполненные `abilities`, ядро не должно на них
падать; решить, что происходит с героем без единой способности (он бесполезен, но легален).
**Готово, когда:** свежий герой не имеет способностей; вставка в слот работает; старое
состояние грузится без ошибок.

### HC-1.3 · Предрасположенность `[data][core]` 🔒(HC-1.2) — M
**Подзадачи:** поле предрасположенности у архетипа (список способностей/веток и множитель);
эффект применяется через существующие хуки, а не новым спецкодом; неизвестный id — правило
инертно (fail-secure, как в движке эффектов `EFX-1`).
**Готово, когда:** одна и та же способность у героя с предрасположенностью сильнее, чем без;
разница видна в тесте числом, а не «должна быть».

### HC-1.4 · Губернатор и наземный герой `[core][data]` 🔒(HC-1.1) — L
**Подзадачи:** сегодня герой обязан быть флагманом (`ship.unit`, позиция = нода корабля,
смерть по `unit.died`/`fleet.destroyed`). Губернатор привязан к ПЛАНЕТЕ, наземный — к
гарнизону; значит у героя появляется вид носителя, и от него зависят позиция, смерть и
респаун. Пассивки губернатора идут в существующие хуки (`economy.production`,
`combat.damage`), новых точек расширения не требуется.
**Готово, когда:** губернатор даёт бонус своей планете и гибнет с её потерей; наземный
герой воюет в наземной фазе; ни один не ломает существующего адмирала.

## Фаза 2 · Мета-половина `[srv]`

### HC-2.1 · Способности как предметы инвентаря `[srv][data]` 🔒(EC-1.1 — `economy-roadmap.md`) — L
**Подзадачи:** расширить `ArsenalItemKindSchema` (сейчас `hull | module | hero_fitting`)
видом «способность героя»; `PlayerArsenal` получает четвёртый список; гейт владения для
вставки способности — по образцу уже работающего гейта `hero.fit`; снапшот в матч через
`SlotAssignment`, как у фиттингов, — ядро о сервере по-прежнему не знает.
**Готово, когда:** способность, которой аккаунт не владеет, не вставляется; владение
доезжает в матч снапшотом; сессионное дерево навыков не задето.

### HC-2.2 · Герой как собственность аккаунта `[srv]` 🔒(EC-1.1 — `economy-roadmap.md`) — L
**Подзадачи:** герой перестаёт быть фиксированным ростером и становится предметом с
редкостью; хранение — там же, где арсенал (леджер, а не JSONB-свалка, требование `EC-1.3`);
предматчевый выбор ростера читает собственность.
**Готово, когда:** два аккаунта имеют разные наборы героев; ростер матча собирается из
того, чем игрок владеет.

### HC-2.3 · Детальки → повышение редкости `[srv][data]` 🔒(HC-2.2) — M
**Подзадачи:** новый вид дропа (детальки героя) в `dropTables.json` — пул сегодня содержит
только корпуса и модули; накопление → повышение редкости (то есть числа слотов); pity, как
у существующего дропа; экономика деталек согласуется с осколками модулей (`EC-2.2`), чтобы
не завести вторую валюту с той же ролью.
**Готово, когда:** серия матчей поднимает редкость героя; путь воспроизводим из seed и
аудируем.

### HC-2.4 · Герои и детальки на аукционе `[srv]` 🔒(EC-3.1 — `economy-roadmap.md`) — M
**Подзадачи:** листинг/покупка героев и деталек по правилам аукциона; `soulbound` для
донатных экземпляров (анти-RMT); комиссия сжигается — те же стоки, что у остальных лотов.
**Готово, когда:** герой продаётся и покупается по общим правилам аукциона, без своей
параллельной торговли.

## Фаза 3 · Новые способности из видения `[data][core]`

> Фаза независима от Фаз 0–2: способности живут на СЕССИОННОЙ оси (§0.1) и не ждут ни
> развилку слотов, ни мета-инвентарь. Порядок внутри фазы — по возрастанию цены (§0.6).
> «Коридор» и «Разведка» из того же списка кирпича не получают: они готовы.

### HC-3.1 · Пассив «скорость флота в радиусе» `[data]` ⏳ — S
**Подзадачи:** запись в `data/heroPassives.json` (`hook: fleet.speed`, `scope: ownFleetsNear`,
`params {bonus, radius}`); узел `heroSkillTrees.json`, который её выдаёт (`grants.passive`),
с `requires`/`cost` в стиле соседей по ветке; ключи имени и описания в `/localization`;
тест на сложение с `vanguard_impulse` — герой на своём же корабле попадает под ОБА бонуса,
и это надо либо подтвердить как задуманное, либо развести по разным веткам дерева.
**Кода не пишем:** клетка `fleet.speed`×`ownFleetsNear` уже исполняема (§0.6) — кирпич
проверяет это тестом, а не добавляет механизм.
**Готово, когда:** флот игрока, выходящий из узла в радиусе от живого РАЗВЁРНУТОГО героя,
летит быстрее; герой на скамейке не ускоряет никого (`alive !== true` ⇒ вклада нет);
единственный рычаг баланса — число в JSON.

### HC-3.2 · Варп-прыжок: `hero.effect.jump` `[core][data]` ⏳ — S
**Подзадачи:** провайдер `hero.effect.jump` в `heroEffects.ts` по образцу `recall` (те же
отказы: не развёрнут → `E_HERO_NOT_DEPLOYED`, в бою → `E_FLEET_BUSY`, уже там →
`E_SAME_LOCATION`); запись в `heroAbilities.json` с НЕнулевым `range` — тогда диспетчер сам
потребует и провалидирует цель — и с длинным `cooldownHours` (плюс `cost`, если прыжок
должен стоить казны); событие `hero.jumped` для отрисовки; ключи локализации.
**Развилка (решение владельца):** прыгать сквозь ТУМАН или только в разведанный узел.
Дешевле — сквозь туман: гейт уже есть, добавлять нечего. Осторожнее — требовать видимости,
но это новая проверка, которой нет ни у одной другой способности, и она тянет за собой
вопрос «видимость чьими глазами».
**Готово, когда:** герой мгновенно переносит свой флот вместе с десантом в трюме в узел в
радиусе; из активного боя не выдёргивается; кулдаун списан ровно один раз, а на отказе не
списан вовсе.

### HC-3.3 · Фантомный радарный сигнал `[core][data]` ⏳ — M
**Подзадачи:** провайдер `hero.effect.decoy`, пишущий на героя `{center, size, until}` по
образцу `activeReveals`; чтение этой записи в `visibleState` при сборке `signatures` для
ЧУЖИХ игроков; протухшие записи подрезаются на касте, как у `activeAuras`/`activeReveals`;
тест «в `GameState` не появилось ни флота, ни юнита».
**Развилки (решение владельца):**
· **кто видит фантом** — все, кроме владельца (проще), или только враждебные (союзника не
  путаем, но появляется вопрос про нейтралов и про игрока, с которым мир);
· **палится ли фантом** — гаснет ли он, когда чужой флот долетает до узла и видит пустоту.
  Дешевле — не палится, истекает по времени; интереснее — гаснет при идентификации, но это
  ещё одно чтение в проекции.
**Готово, когда:** соперник видит контакт `{location, size}` там, где ничего нет; бой,
захват и подсчёт победы не изменились ни на шаг; владелец своего же фантома не видит.

### HC-3.4 · «Опытный командир»: юниты союзника под управление `[core][data]` ⏳ — L
**Подзадачи:** механизм временной передачи флота — его в игре нет ни в каком виде (§0.6);
согласие союзника по образцу `mapShare` (предложение → принятие, снятие при объявлении
войны); срок и возврат — кому достаётся флот, если срок истёк вдали от хозяина или хозяин
выбыл; «N юнитов от прокачки» — это `params` способности и ступени `tiers`, а не отдельный
механизм.
**Развилки (решение владельца):** передаётся ФЛОТ целиком или N юнитов из него (второе
требует расщепления состава — заметно дороже); возвращается по сроку сам или держится до
отзыва; что происходит при разрыве союза посреди срока — мгновенный возврат безопаснее
всего.
**Почему L, а не M:** сменить `Fleet.owner` мало — на владельце завязаны видимость, бой,
приказы, содержание и подсчёт победы. Кирпич обязан НАЧАТЬСЯ с ревизии этих читателей,
иначе получится флот, который считается своим для боя и чужим для победы.
**Готово, когда:** союзник отдаёт флот на срок и получает его назад; отданный флот слушается
получателя и виден ему; при разрыве союза он не остаётся у бывшего союзника.

## Открытые вопросы

- **Стимул доигрывать.** Владелец формулирует: «выжить всегда выгоднее, чем бросить».
  Сейчас награды пишутся каждому севшему игроку («participation pays even in defeat»), и
  единственный градиент — шанс дропа по месту. Нужно ли отдельное наказание за выход из
  матча — решение владельца; кирпича под него пока нет намеренно.
- **Витрина.** Показывать ли учёных и героев одним экраном (они разные в данных, но для
  игрока это «мой штаб») — вопрос UI, решается при первом `[proto]`-кирпиче.
- **Сколько героев в матче.** Сегодня кэп 3 активных + ростер до 3 разных архетипов.
  С коллекцией это число становится балансным рычагом.
- **Редкость у СПОСОБНОСТИ.** Владелец называет варп-прыжок «самым редким, красным», но
  редкость сегодня — свойство героя (`Hero.grade`), а у способности её нет вовсе (§0.6).
  Либо цвет способности появляется вместе с HC-2.1 (способности как предметы инвентаря),
  либо «редкость» до тех пор выражается глубиной ветки дерева. Выбор нужен до того, как
  цвет попадёт в интерфейс, иначе игроку покажут шкалу, которой нет в данных.
- **Кулдаун и глобальность новых способностей.** Прыжок и фантом сильно меняют карту, а
  единственный сдерживающий рычаг у способности — `cooldownHours` (плюс `cost`). Насколько
  редкими они должны быть — балансное решение владельца; кирпичи HC-3.2/HC-3.3 оставляют
  числа пустыми намеренно.
