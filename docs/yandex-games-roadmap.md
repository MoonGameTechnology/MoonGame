## 0. Достоверность источников — читать первым

**Официальная документация площадки в сессии агента недоступна:** хосты `yandex.ru` и
`yandex.com` закрыты политикой egress-прокси. Всё, что касается требований площадки,
собрано из поисковых сводок по её документации и открытой сторонней обвязки SDK —
**не из первоисточника**.

Рабочее соглашение (`CLAUDE.md`, «verify docs against reality») запрещает документировать
по неподтверждённому, поэтому утверждения помечены:

- **✔ проверено** — сверено с кодом или измерено в этом репозитории;
- **◆ сверено по декларациям** — взято из `@types/ysdk@1.2.0` (DefinitelyTyped, скачан с
  npm-реестра): машинные объявления типов реального SDK. Даёт **сигнатуры** авторитетно;
  политику (лимиты, квоты, правила модерации) не даёт вовсе;
- **⚠ требует сверки** — вторичный источник о площадке (поисковые сводки);
- **⊚ сверено по открытым источникам (YAG-0.1, 2026-09-22)** — прямое чтение страницы
  по-прежнему закрыто (проверено в тот же день: прокси отвечает `EGRESS_BLOCKED` на
  `yandex.com`), но утверждение подтверждено ДВУМЯ независимыми каналами: поисковой
  сводкой ПО САМОЙ странице документации и сторонней обвязкой SDK на GitHub, которая
  мирроррит требования в код (`indiesoftby/defold-yagames`, `fookix/YGChecker`). Это
  слабее, чем «открыл и прочитал», и сильнее, чем блог-пересказ: два источника,
  независимые друг от друга, дают одно и то же число.

**Кирпич не берётся в работу, пока ЕГО СОБСТВЕННЫЕ ⚠-предпосылки не подтверждены.**
Правило посильнее «ждём YAG-0.1»: после сверки 2026-09-22 часть предпосылок закрыта, и
запирать на общем кирпиче работу, которой больше ничего не мешает, значит держать
мёртвый замок. Цифры площадок меняются, а ошибка здесь стоит отказа модерации —
поэтому у сверки есть ДАТА, и у требований площадки тоже: сторонний чекер фиксирует
свою сверку версией от **22.08.2026** (`requirements-version.json`), а площадка ведёт
`release-notes`. Перед подачей в модерацию сверку повторяют.

## 1. Площадка: API и политика — это разные уровни достоверности

### 1.1 API ◆ — сверено по `@types/ysdk@1.2.0`

**Жизненный цикл.**

```ts
YaGames.init<TGlobalSigned>(opts?: { signed?: TGlobalSigned }): Promise<SDK>
ysdk.features.LoadingAPI.ready(): void
ysdk.features.GameplayAPI.start(): void
ysdk.features.GameplayAPI.stop(): void
```

**Реклама — колбэки, возврат `void`, а НЕ промис.**

```ts
adv.showFullscreenAdv(opts?: { callbacks?: {
  onOpen?(), onClose?(wasShown: boolean), onError?(e: Error), onOffline?() } }): void
adv.showRewardedVideo(opts?: { callbacks?: {
  onOpen?(), onRewarded?(), onClose?(), onError?(e: Error) } }): void
adv.showBannerAdv(): Promise<{ reason?: StickyAdvError }>
adv.hideBannerAdv(): Promise<{ stickyAdvIsShowing: boolean }>
adv.getBannerAdvStatus(): Promise<{ stickyAdvIsShowing: boolean; reason?: StickyAdvError }>
```

Два следствия. Контракт `PlatformAds` из `platform-adapters.md` объявлен промисами —
значит адаптер **переводит** колбэки в промис, это не проброс. И `onRewarded` отдельно от
`onClose`: закрытие ролика наградой **не является**, что и подтверждает инвариант «награду
выдаёт игра только по подтверждённому результату адаптера».

**Покупки.**

```ts
payments.getCatalog(): Promise<Product[]>
payments.purchase(opts?: { id: string; developerPayload?: string }): Promise<Purchase | Signature>
payments.getPurchases(): Promise<Purchase[] | Signature>
payments.consumePurchase(token: string): Promise<void>
ysdk.getPayments<TSigned>(opts?: { signed?: TSigned }): Promise<Payments<TSigned>>
```

**Личность игрока — и это меняет историю с entitlement.**

```ts
ysdk.getPlayer<TSigned>(opts?: { signed?: TSigned }):
  Promise<TSigned extends true ? Signature : Player>
player.getIDsPerGame(): Promise<Array<{ appID: number; userID: string }>>
player.isAuthorized(): boolean
player.getPayingStatus(): "not_paying" | "partially_paying" | "paying" | "unknown"
player.setData(data, flush?): Promise<void>
player.getData<T>(keys?): Promise<Partial<Record<T, Serializable>>>
player.setStats / getStats / incrementStats
```

Тип `Signature` документирован дословно: *«при передаче через signature объект возвращается
не сам по себе — поле signature содержит зашифрованную строку с полями объекта, которую
можно расшифровать на вашем сервере»*. То есть площадка умеет отдавать **проверяемое на
сервере доказательство личности**, и межпродуктовый entitlement внутри площадки упирается
не в аккаунты/OIDC, а в тот же эндпойнт проверки подписи, что и покупки (`YAG-4.1`).

А `getIDsPerGame()` отдаёт идентификаторы игрока **в других играх того же разработчика** —
значит будущий First Contact увидит, что этот же человек прошёл Sector Zero, без кодов.
Код остаётся нужен только для перехода С площадки в основную игру.

**Остальное, чего в роадмапе не было и что стоит знать.**

```ts
ysdk.serverTime(): number
ysdk.getFlags(params?): Promise<Record<string, string>>
ysdk.getStorage(): Promise<SafeStorage>          // typeof window.localStorage
ysdk.on("game_api_pause" | "game_api_resume", observer): () => void
ysdk.onEvent("EXIT" | "HISTORY_BACK", listener): () => void
ysdk.environment.i18n.lang: ISO_639_1            // 73 языка
ysdk.environment.i18n.tld: TopLevelDomain        // 19 доменов
ysdk.deviceInfo.isDesktop/isMobile/isTablet/isTV()
ysdk.shortcut.canShowPrompt() / showPrompt()
ysdk.feedback.canReview() / requestReview()
ysdk.leaderboards.setScore / getEntries / getPlayerEntry / getDescription
ysdk.multiplayer.sessions                        // асинхронный «призрачный» мультиплеер
```

Четыре из них меняют проектирование, и им заведены кирпичи Фазы 6:

- **`serverTime()`** — у нас игра в реальном времени на клиенте. Без серверного времени
  забег промотается переводом системных часов.
- **`getFlags()`** — удалённый конфиг, то есть правку баланса можно выкатить **без
  пересдачи на модерацию** (3–5 рабочих дней). Для «проверим баланс на живых» это
  решающее.
- **`getStorage()`** — безопасная обёртка над `localStorage`. Снимает риск
  партиционирования в iframe, о котором писал `PVR-0.3`.
- **`game_api_pause` / `resume`** — площадка сообщает о паузе (например, на показе
  рекламы). Мир идёт по стенным часам: надо решить, замирает он или тикает без игрока.

Отдельно: **`isTV()` — телевизор как тип устройства**, другая модель ввода. Мы
проектируем под телефон; это стоит явно объявить вне охвата v1.

### 1.2 Политика ⊚ — сверено по открытым источникам 2026-09-22 (YAG-0.1)

Декларации типов политику не несут, а страница документации закрыта egress-политикой.
Ниже — то, что удалось подтвердить двумя независимыми каналами (см. ⊚ в §0), с указанием
раздела документации, к которому утверждение относится. **Два утверждения прежней
редакции оказались НЕВЕРНЫ — они помечены «было/стало».**

**Сборка ⊚.** Содержимое архива до сжатия — **не более 100 МБ**; в корне архива **один
`index.html`**; в именах файлов и папок **нет пробелов и кириллицы**
([`concepts/requirements`](https://yandex.ru/dev/games/doc/ru/concepts/requirements)).
Те же три проверки реализованы в открытом чекере `fookix/YGChecker` — независимое
подтверждение формулировок кодом.

**Модерация ⊚.** Штатный срок — **3–5 рабочих дней**; если архив не менялся, а правки
в черновике незначительные, проверка идёт ускоренно, **1–2 рабочих дня**. После
отклонения повторная отправка возможна **не раньше чем через 24 часа**, и время ожидания
**удваивается после каждого отклонения**, максимум **384 часа (16 дней)**
([`concepts/moderation`](https://yandex.ru/dev/games/doc/ru/concepts/moderation)).
Число попыток не ограничено. Есть отдельная страница
[«Критерии прохождения модерации»](https://yandex.ru/dev/games/doc/ru/concepts/criteria)
— её стоит открыть перед подачей (YAG-5.2).

**Локализация ⊚.** Русский обязателен, чтобы игра попала в каталог на домене `.ru`.
**Автоопределение языка обязательно у ВСЕХ игр** — даже если заявлен один язык или
текстов нет вовсе; язык берётся из `environment.i18n.lang`, а неподдержанный язык уводит
на резервный набор
([`requirements/2/14`](https://yandex.ru/dev/games/doc/ru/requirements/2/14)). Отдельное
требование к переключателю: **название языка пишется на этом языке**
([`requirements/8/2/3`](https://yandex.ru/dev/games/doc/ru/requirements/8/2/3)).
Нарушение требований к локализации — основание не допустить игру к публикации или снять
её с публикации в любое время. ⚠ Формулировку «частичный перевод хуже отсутствующего»
процитировать не удалось: подтверждается только общая санкция, не сравнение. На нашу
работу это не влияет — гейт `i18n.test.ts` не допускает частичного перевода в принципе
(§3).

**Запрещено ⊚.** Ссылки в текстах и медиаматериалах не ведут на внешние ресурсы: сайт
автора, сайт самой игры, сторы, студии, партнёров, скачивание файлов, вредоносные
страницы. Запрещено автоматическое перенаправление на внешние сайты — и по действию
игрока, и без него, — как и рекомендации перейти на сторонние ресурсы. Запрещена
**обязательная регистрация или авторизация в сторонних сервисах** для запуска игры.
Платежи внутри игры — **только через SDK площадки**
([`concepts/requirements`](https://yandex.ru/dev/games/doc/ru/concepts/requirements)).

> **Было/стало №1 — реклама сторонних сетей.** Прежняя редакция писала «запрещена
> реклама сторонних сетей, включая статичные картинки и текст». Это НЕ безусловный
> запрет: у площадки есть опция **«Внешние рекламные сети»**, разрешающая показывать
> рекламу сторонних монетизаторов (называются Google AdSense, MyTarget). Запрет
> касается подключения чужих рекламных SDK МИМО этой опции — что и проверяет чекер
> («third-party ad and payment SDK detection»). Для нас практической разницы нет: своей
> рекламы мимо площадки мы не ставим, — но формулировка «запрещено» в доке была ложной.

**Правила показа рекламы ⊚.** Показ — только в логических паузах (перед началом игры,
при переходе на следующий уровень, после проигрыша). Задержка между действием, вызвавшим
рекламу, и началом показа — **не более 0,33 с**. На время показа игра И звук ставятся на
паузу. Все рекламные блоки имеют **ориентацию, совпадающую с ориентацией игры**. Реклама
вызывается только через SDK площадки. Если ролик показывается посреди уровня, игру
обязательно ставят на паузу и предупреждают игрока таймером
([`requirements/4/4`](https://yandex.ru/dev/games/doc/ru/requirements/4/4),
[`sdk/sdk-adv`](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv)).

**Частота фуллскринов ⊚ — управляется ПЛОЩАДКОЙ, а не нами.** Раньше SDK жёстко не
показывал фуллскрин чаще **раза в три минуты**; сейчас площадка перешла на гибкое
ограничение интервала и продолжает его настраивать
([блог площадки](https://yandex.ru/blog/gamesfordevelopers/obnovlenie-algoritmov-pokaza-fulskrinov)).
У rewarded-видео частота **не ограничена**. Следствие для `YAG-3.2`: рассчитывать на
конкретное число нельзя, «показали или нет» узнаётся из колбэка — то есть пропущенный
показ обязан быть штатным исходом, а не ошибкой.

**Покупки ⊚ + ⚠.** Заявку на подключение покупок подают **заранее**: без подключённых
покупок игра модерацию не пройдёт. Тестировать покупки можно только после подключения
их **консумирования**, иначе появляются необработанные платежи, и они делают прохождение
модерации невозможным
([`sdk/sdk-purchases`](https://yandex.ru/dev/games/doc/ru/sdk/sdk-purchases)).

> **Было/стало №2 — чей это пункт 1.13.1.** Прежняя редакция писала: «проверка подписи
> покупки на своём сервере обязательна для модерации (называется пункт 1.13.1)».
> **Пункт 1.13.1 про другое** — он требует ПОДКЛЮЧЁННОГО КОНСУМИРОВАНИЯ, и именно
> непогашенные платежи делают модерацию невозможной. ⚠ Обязательность серверной проверки
> подписи на уровне цитаты подтвердить не удалось: сводки это утверждают, но номера
> пункта не дают, а страница закрыта. Механизм документирован (`signed: true` → данные
> `payments.getPurchases()`/`purchase()` приходят только зашифрованными в `signature`,
> сверяются секретным ключом игры из консоли), и `YAG-4.1` остаётся нужным независимо
> от того, гейт это модерации или защита от накрутки, — но называть его «требование
> 1.13.1» больше нельзя.

**Квота данных игрока ⊚ — противоречие снято, и оба числа были правдой.** Они просто
принадлежат РАЗНЫМ методам, как и подсказывала форма API:

| Метод | Размер на игрока | Частота |
| --- | --- | --- |
| `setData` (произвольный JSON) | **200 КБ** | **не более 100 запросов за 5 минут** |
| `setStats` (плоская карта чисел) | **10 КБ** | **не более 60 запросов в минуту** |
| `player` (инициализация) | — | **не более 20 запросов за 5 минут** |

Источники: [`sdk/sdk-player`](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player) (поисковая
сводка по странице) и README `indiesoftby/defold-yagames`, где те же числа записаны
рядом с обёртками методов. Числа совпали дословно, включая лимит на `player_init`,
которого у нас не было вовсе. **Прежнее «10 КБ на всё» относилось к `setStats`** —
отсюда и вывод §2.1, который теперь пересмотрен.

## 2. Что измерено и что из этого следует

### 2.1 Сохранение забега В ОБЛАКО ВЛЕЗАЕТ — но компактный сейв всё равно лучше

**Прежняя редакция называлась «НЕ влезает». Сверка 2026-09-22 это опровергла.**

**✔ Измерено 2026-09-16.** Состояние партии на карте, которую прототип играет сегодня
(`nexus`, 121 сектор): **29.3 КБ на старте, 30.9 КБ после шести игровых часов**.

⊚ **Лимит `setData` — 200 КБ** (§1.2), а не 10 КБ: «10 КБ» относится к `setStats`, куда
`GameState` не кладут в принципе (там только плоская карта чисел). Значит состояние
влезает с шестикратным запасом, и аргумент «не помещается втрое» снят.

**Форма сейва от этого не меняется, но меняется ПРИЧИНА.** Компактный дескриптор
выбирается уже не лимитом, а тремя другими доводами: частота (`setData` — 100 запросов
за 5 минут, и сохранять весь мир на каждое событие всё равно нельзя), время записи по
сети на телефоне, и совместимость версий — дескриптор переживает смену формата
`GameState`, а блоб нет. Рекомендация ниже поэтому смягчается с «обязательно» до
**«предпочтительно, и по этим причинам»**; аварийный путь «положить весь `GameState`»
перестал быть невозможным и становится честным запасным вариантом.
Маленькая карта спасает частично: `skirmish-1` (5 секторов) — 2.1 КБ на старте и 3.5 КБ
через сутки; карта забега `pve-1` имеет 7 секторов и десять волн впереди.

**Следствие для PVR-0.3 и YAG-2.1: сейв — это НЕ `GameState`.** Варианты:

- **(а) компактный дескриптор забега** — сид, сложность, номер волны, взятые усиления;
  мир пересобирается. Классическая форма сейва рогалика, влезает в сотни байт. Опирается
  на детерминизм — здесь это инвариант №1, закреплённый golden-тестами.
- **(б) лог действий + реплей** — машинерия ✔ уже есть: `ReplayLog` и `runReplay`
  (`packages/shared-core/src/replay/replay.ts`) с CI-тестом, который гоняет живую комнату
  48 игровых часов и сверяет `hashState` бит-в-бит. Точнее, но лог растёт и упрётся в тот
  же лимит.
- **(в) гибрид** — точное состояние локально, дескриптор в облако.

**Рекомендация — (а), с (в) как поведением по умолчанию.** Рогалику не нужно возвращать
позицию флота попиксельно: достаточно вернуть игрока в тот же забег на той же волне с
теми же усилениями.

### 2.2 Покупки требуют сервера, а сервер — это цель дохода

⚠ Проверка подписи покупки **на вашем сервере** — документированный механизм защиты от
накрутки (`signed: true`); обязательна ли она ДЛЯ МОДЕРАЦИИ, сверка 2026-09-22
подтвердить не смогла, а прежняя привязка к «пункту 1.13.1» оказалась ошибочной (§1.2,
«было/стало №2»: 1.13.1 — про консумирование). План при этом не меняется: доход от
покупок → аренда сервера. Замкнутый круг.

**Он разрывается тем, что это НЕ игровой сервер.** Проверка подписи — функция без
состояния: приняла `signature`, сверила ключом из консоли, ответила. Ни базы, ни комнаты,
ни постоянного процесса; живёт на бесплатном тарифе и к арендованному серверу матчей
отношения не имеет. Поэтому эндпойнт — самостоятельный маленький кирпич (YAG-4.1), а не
«дождёмся сервера», и он не тянет ни `packages/server`, ни Postgres.

**✔ Про доверие.** Репозиторий стоит на server-authority (инвариант 5), одиночная игра
сервера не имеет. Даже с проверкой подписи всё, что происходит ПОСЛЕ неё — выдача
купленного, состояние прогресса — остаётся клиентским и подделывается. Это ещё одна
причина держаться guardrail'ов `platform-adapters.md` §4: продавать ускорение меты, а не
исход матча.

### 2.3 Реклама за продолжение забега — отозвано

**Ранняя редакция этого файла рекомендовала rewarded-видео за продолжение забега после
смерти («одно за забег»). Рекомендация СНЯТА** после сверки с `platform-adapters.md`,
который прямо называет такое нежелательным: §4 — не продавать «неограниченное
воскрешение/перемотку поражения», §1 — rewarded ставить на бонус к **мета-награде после
завершённого** PvE, а не к результату идущего боя, и «не должен превращаться в
проигрываю → плачу → победил».

Довод того документа сильнее моего: цена смерти — это и есть то, что делает забег
забегом, а заодно то, что мы собираемся мерить. Записано здесь, а не удалено, чтобы
предложение не всплыло второй раз как свежая идея.

**Что остаётся верным:** ✔ структура забега (этапы = волны) даёт естественные паузы, и
требование площадки «только в логических паузах» выполняется по построению. Конкретные
placements берутся из `platform-adapters.md` §1–§2, а не изобретаются здесь.

v1, и её стоит вычеркнуть явно.

### YAG-1.1a · Контракты `GamePlatform` и `WebPlatformAdapter` `[proto]` ✅ — M
Контракты `GamePlatform` из `platform-adapters.md` и их fallback-реализация без внешнего

⚠️ **Кирпич отделён от цели сборки 2026-09-21, и вот почему.** Исходный `YAG-1.1` склеивал

действительно ждёт `YAG-0.1` — лимит архива и раскладка это его пункты. Первое не ждёт

**Сделано.** `prototype/src/platform/types.ts` — контракты (`GamePlatform`,
`PlatformCapabilities`, `PlatformAuth`/`Save`/`Ads`/`IAP`/`Analytics`, словарь
`PLATFORM_EVENTS` из 10 событий). `prototype/src/platform/web.ts` — `createWebPlatform`.

**Исходов три, а не два** (`ok` / `cancelled` / `unavailable`). Свести их к `boolean`
значило бы потерять разницу между «игрок не захотел» и «здесь этого нет», а она
продуктовая: в первом случае кнопка остаётся, во втором её не должно быть вовсе.

⚠️ **`simulate` — это про РАЗРАБОТКУ, а не «пока не сделали».** В сборке игрока обычный

честно `false`. В дев-сборке (`!__PLAYER_BUILD__`) те же флаги поднимаются и отдают
управляемые исходы — чтобы путь «посмотрел рекламу → товар выдан» проходился целиком, а не
только в юнит-тесте. Проверено обеими сборками: в дев-сборке покупка за рекламу доводит
данные 0 → 4 без списания валют, в сборке игрока кнопок за рекламу и Суверены нет вовсе.

Магазин Sector Zero (`SZE-3.1`) подключён к этим capability, как и планировалось — сменой
двух флагов, без правки витрины. Покупка за рекламу идёт ДВУМЯ шагами: подтверждённый
показ, потом выдача; сломавшийся адаптер читается как «не досмотрел» (fail-secure), иначе
исключение в SDK площадки превратилось бы в бесплатный лот.

**Готово:** ✅ `WebPlatformAdapter` покрывает success/cancel/unavailable для рекламы и
покупок (7 тестов); квитанция бывает только у успешной покупки; недоступное хранилище не
роняет игру.

### YAG-1.1b · Платформенная цель сборки и раскладка архива `[proto]` ⏳ — L
_Разблокирован 2026-09-22:_ все три предпосылки (100 МБ, `index.html` в корне, имена без
пробелов и кириллицы) подтверждены сверкой YAG-0.1 (⊚, §1.2).
Отдельная цель сборки рядом с тремя существующими. Общее (ядро, `/localization`,
`/decisions`, рендер) берётся импортом, НЕ копией. Ждёт `YAG-0.1` по существу: лимит архива
и требования к раскладке — его пункты, и проверять их надо по первоисточнику.

**Механизм уже есть, изобретать не надо.** `prototype/build.mjs` гоняет esbuild от
`entryPoints` по графу импортов с `write: false` — шага «скопировать каталог» в сборке нет
вообще, и что не импортировано, того в артефакте нет физически. Измерено 2026-09-17 одним

в 6,5 раз получается только от другой точки входа (`admin.ts` против `bootstrap.ts`).

**Решение владельца 2026-09-17: артефакт РАЗЛОЖЕННЫЙ**, а не один самодостаточный HTML.
`index.html` в корне архива плюс `assets/` рядом. Сегодня прототип инлайнит всё в один файл
(`loader: { '.webp': 'dataurl' }`), и для площадки это был бы самый простой возможный архив
— ровно один файл. Но data-URL это base64 (около +33% на бинарниках), и кэширования по
частям нет: правка одной строки заставляет игрока перекачать весь бандл. Раскладка принята
до того, как приедет настоящий арт, а не после третьего релиза.

⚠️ **Свой сторож для бандла данных — обязателен, иначе контент пропадёт молча.**
`data/bundle.ts` вшивает 21 фрагмент `data/*.json` статическими импортами, и его шапка
предупреждает: каждое поле каталога в `schemas.ts` несёт `.default({})`, поэтому
НЕ переданный фрагмент **не роняет загрузку** — zod подставляет пустую запись, и приложение
получает валидный бандл с молча пропавшим контентом. Это уже случалось: до браузера доехали
11 фрагментов из 18, а весь слой героев и модулей корабля был пуст. Готовое противоядие —
`data/bundle.test.ts` (список сверяется с тем, что реально спрашивает композер; каждый
фрагмент резолвится в контент, а не в `undefined`; каталоги заполнены). Своему набору
фрагментов Sector Zero нужен свой такой тест.

**Готово, когда:** цель собирается в `index.html` + `assets/`, и распакованный результат
запускается без доступа к репозиторию; тест-сторож падает, если в граф импортов попал SDK
площадки, сетевой модуль или что-то ещё из списка «не нужно продукту» (§0.1
[`sector-zero-roadmap.md`](sector-zero-roadmap.md)); тест бандла данных падает, если
фрагмент пропал из списка; `WebPlatformAdapter` покрывает success/cancel/unavailable для
рекламы и покупок.

### YAG-1.2 · `YandexGamesAdapter`: инициализация и жизненный цикл `[proto]` 🔶 2026-09-22 — M
Подключение SDK, готовность после загрузочного экрана, разметка геймплея на старте и
паузе забега, публикация `PlatformCapabilities`.
**Готово, когда:** площадка видит игру загруженной и размеченной; capability-флаги
отражают реальную доступность, а UI решает по ним, а не по имени площадки.

**Сделано: адаптер есть и проверен, 32 теста.** Правила разметки вынесены в чистое решение
`decisions/platformLifecycle.ts` (13 тестов), проводка к SDK — в
`prototype/src/platform/yandex.ts` (19 тестов, включая сторож границы). Разделение не
формальное: правила проверяются последовательностями вызовов вообще без SDK, а адаптеру
остаётся только позвать площадку.

_Что продиктовала методика проверки (требование 1.19)._ Модерация смотрит debug-панель
покадрово, поэтому `LoadingAPI.ready()` **нельзя вешать на таймер**: сценарии «загрузочный
экран скрыт тапом» и «исчез сам» различаются только моментом готовности, и привязка ко
времени пройдёт один, провалив другой. Момент выбирает хост, адаптер гарантирует «ровно
один раз». Разметка геймплея парная: повторный `start` молчит, `stop` без `start` молчит, а
`start` **до** `ready` не уходит в SDK вовсе — иначе индикатор позеленеет раньше, чем игрок
сможет играть.

_Пауза площадки сильнее нашей._ На `game_api_pause` разметка встаёт сама, не дожидаясь
хоста, а `game_api_resume` возвращает РОВНО то состояние, что было: ушёл в меню, потом
площадка показала рекламу — после рекламы игрок по-прежнему в меню, а не в бою. Ради этого
в решении живёт отдельное «чего хотела игра» (`wantedPlaying`).

_Возможности объявляются по тому, что умеет АДАПТЕР, а не SDK._ Поднять `rewardedAds: true`
только потому, что у `ysdk.adv` есть метод, — ровно тот баг, от которого защищают
capability-флаги: кнопка появится, а нажатие ничего не сделает, пока не закрыт `YAG-3.1`.
Поэтому сегодня `true` только у `auth`; реклама, покупки и облачный сейв поднимут свои
флаги в своих кирпичах, а их вызовы до тех пор честно отвечают `unavailable` —
документированный третий исход, а не заглушка-обман.

_Гость — это норма (требование 1.2.2)._ Неудача `getPlayer()` даёт гостя, а не исключение:
игра обязана работать без авторизации, и падать из-за чужого SDK ей нельзя.

_Сторож границы._ Тесты падают, если `shared-core` узнает про `YaGames`/`ysdk`, если чистое
решение импортирует хоть что-нибудь или если в `main.ts` появится `if (platform ===
'yandex')`. Граница из `platform-adapters.md` держится проверкой, а не бдительностью.

**Остаток (почему 🔶): подключение к хосту вместе с загрузкой SDK — в `YAG-1.1b`.**
Требование 1.19.1 обязывает инициализировать SDK «строго так, как указано на странице
Подключение и использование», и модерация отдельно проверяет **версию лоадера** (на
debug-панели `IT` — новый, `IF` — старый). Точного сниппета этой страницы у нас нет, а
угадывать его нельзя: это прямой отказ модерации. Сниппет живёт в разметке сборки, поэтому
его место — цель сборки, а адаптер принимает уже поднятый `ysdk` (и от этого тестируется
без сети). Что именно нужно найти — §4.

### YAG-1.3 · Язык от площадки `[proto]` 🔒(YAG-1.2) — S
Локаль выбирается языком игрока с площадки, с падением на русский; подставляется в уже

## Фаза 6 · Возможности площадки, меняющие поведение мира `[proto]`

> Заведены после сверки с `@types/ysdk@1.2.0` (§1.1). Это не интеграционные мелочи: три из
> четырёх меняют то, как ведёт себя симуляция.

### YAG-6.1 · Серверное время вместо системного `[proto]` 🔒(YAG-1.2) — M
`ysdk.serverTime()` как источник времени для забега. Мир Sector Zero идёт по стенным часам
на клиенте игрока, то есть **перевод системных часов промотает забег** — самое дешёвое
читерство, какое бывает. Ядро времени не берёт (инвариант 1: время приходит через
`Context.now`), значит это работа адаптера и хозяина цикла, а не правка симуляции.
**Готово, когда:** забег считает время от площадки; подмена системных часов его не двигает;
отсутствие SDK (веб-фолбэк) деградирует на локальное время, а не падает.

### YAG-6.2 · Пауза площадки: что делает мир `[proto]` 🔒(YAG-1.2) — M
`ysdk.on('game_api_pause' | 'game_api_resume')`. Площадка сообщает о паузе — например, на
показе рекламы. **Это решение о поведении мира, а не подписка на событие:** мир либо
замирает (и тогда реклама даёт бесплатную паузу — игрок будет ею пользоваться), либо тикает
без игрока (и тогда ролик стоит игроку потерь). Обе модели допустимы, но выбрать надо
осознанно и одинаково для всех продуктов.
**Готово, когда:** поведение выбрано, покрыто тестом и одинаково на всех площадках через
контракт, а не через проверку имени площадки.

### YAG-6.3 · Удалённый конфиг баланса `[proto]` 🔒(YAG-1.2) — M
`ysdk.getFlags()`. Правка чисел баланса без пересдачи на модерацию (3–5 рабочих дней). Для
цели «проверить баланс на живых игроках» это разница между итерацией в день и итерацией в
неделю. Границы: флагами крутятся ЧИСЛА (длина главы, интервал волн, размеры наград), но не
правила — иначе детерминизм станет зависеть от удалённого состояния.
**Готово, когда:** числа берутся из флагов с безопасными умолчаниями; недоступность флагов
не ломает забег; тест подтверждает, что флаг не может изменить правило.

### YAG-6.4 · Кнопка «назад» и выход `[proto]` 🔒(YAG-1.2) — S
`ysdk.onEvent('HISTORY_BACK' | 'EXIT')`. На телефоне это системная кнопка, и без обработки
она выкинет игрока из игры посреди забега.
**Готово, когда:** «назад» ведёт по экранам продукта, а выход не теряет несохранённый
прогресс.
