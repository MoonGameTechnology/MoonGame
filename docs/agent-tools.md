# Инструменты агента: воспроизводимая настройка

Утверждённый профиль для разработки Void Dominion: Ponytail в режиме `full`,
Z.A.E.B.A.L только по явной команде, SL UI Library для отдельных компонентов.
Это инструменты рабочей станции: они не входят в сервер, сайт, APK или зависимости игры.
Проектные `AGENTS.md`, `CLAUDE.md` и ритуалы `.claude/skills/` продолжают действовать.

## Закреплённые версии

Источник установки — `scripts/agent-tools.lock.json`. Менять его нужно отдельным
проверенным обновлением, вместе с повторным прогоном установки и хуков.

| Инструмент | Версия | Commit |
| --- | --- | --- |
| Ponytail | 5.3.3 | `96608e078b2d5ea607c5c3b8b5a54d1c1fba6846` |
| Z.A.E.B.A.L | commit | `84f0cb26ffac63cea54cc5693a8fe7c3068eac60` |
| SL UI Library | 1.2.4 | `0eeabb0a8ecbbfb8b592f74aa63cf634bdf565da` |

Проверенный хост — **Codex CLI 0.163.0 на Linux**, Node >=22, Python >=3.10, Git.
Нужен доступ к GitHub для загрузки исходников. Для других хостов и ОС этот установщик
не заявляет поддержку; их нативную установку нужно проверить отдельно.

## Установка

Из корня репозитория, от обычного пользователя, при закрытых редакторах конфигурации:

```bash
pnpm run tools:setup             # показать профиль, ничего не менять
pnpm run tools:setup --apply     # установить закреплённые версии и настройки
pnpm run tools:setup --check     # проверить версии, исходники и настройки
```

Эквивалент без pnpm — `node scripts/setup-agent-tools.mjs --apply`.
Установка не запускается автоматически из `pnpm install`, сборки или CI.
Существующие несвязанные настройки сохраняются. Перед изменением конфигов и навыка
создаются соседние резервные копии `*.before-agent-tools-*.bak`; установщик Z.A.E.B.A.L
также сохраняет свою копию `hooks.json.zaebal-*.bak`. Ошибка JSON останавливает установку.
Повторный запуск использует те же SHA; изменённый локальный checkout не сбрасывается.

Ponytail ставится через локальный индекс с SHA **самого плагина**: одного пина
marketplace недостаточно, потому что upstream-индекс ссылается на `main`.
У SL плагин лежит внутри checkout marketplace, поэтому его закрепляет SHA marketplace.
Z.A.E.B.A.L ставится штатным Python-helper только в Codex; остальные IDE не меняются.

Пути по умолчанию:

- исходники Z.A.E.B.A.L и индекс Ponytail: `~/.local/share/void-dominion-agent-tools/`;
- плагины: нативный кэш Codex; Z.A.E.B.A.L: `~/.zaebal/core` и `~/.agents/skills/zaebal`;
- режим Ponytail: `~/.config/ponytail/config.json`;
- режим Z.A.E.B.A.L: `~/.zaebal/config.json`; его регистрация: `~/.codex/hooks.json`;
- настройки обновления каталога SL: `~/.cache/sl-ui-library/settings.json`.

Учитываются заданные `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `CODEX_HOME`, `ZAEBAL_STATE_DIR`.
`PONYTAIL_DEFAULT_MODE` имеет приоритет над файлом: проверка сообщает об отличии от `full`.

После установки открой новую сессию Codex и проверь `/hooks`: хуки Ponytail
(`SessionStart`, `UserPromptSubmit`, `SubagentStart`) и Z.A.E.B.A.L (`UserPromptSubmit`)
должны быть включены и доверены. На новой машине это нативный выбор доверия Codex;
установщик его не подменяет. `--check` проверяет файлы и настройки, а не выполнение
хуков в живом диалоге. После обновления содержимого хука Codex может запросить доверие снова.

## Как используем

- **Ponytail `full`** — помощь в организации работы. Обязательные проверки, правила ядра,
  публикация PR и запрет разрастания файлов остаются проектными.
- **Z.A.E.B.A.L** — явно написать `zaebal audit` в сессии агента. Автотриггеры и ранний
  аудит выключены; `auditor: "none"`, `audit_levels: []`, `allow_unsafe_auditor: false`.
  Обычные сообщения и эмоциональные реплики аудит не включают. Внешний аудитор не запускается.
- **SL UI Library** — поиск и просмотр конкретного компонента, затем перенос нужного
  HTML/CSS/JS в существующий интерфейс с локализацией, игровыми цветами и браузерной проверкой.
  Весь каталог, React/Next.js и сторонняя дизайн-система в игру не добавляются.

Обновления данных SL отключены. Установщик не включает и не отправляет аналитику,
не меняет ранее выбранное согласие. Правки игрового интерфейса и новые зависимости
проходят обычный PR; установка библиотеки сама по себе их не добавляет.

## Восстановление и обновление

При ошибке сначала прочитай её и `--check`: установщик не откатывает уже завершённые
шаги. Исправив причину, повтори `--apply`; не удаляй чужие плагины и конфиги целиком.
Для возврата настроек используй сохранённые копии конкретных файлов. Удаление плагинов
делается нативным менеджером Codex; сохранения/историю Z.A.E.B.A.L удалять не требуется.

При смене SHA проверь upstream-изменения, настройку `full`, ручной запуск аудита,
отсутствие автозапуска/внешнего аудитора и получение выбранного компонента SL. Обнови пины,
прогони `--apply`, `--check` и новую сессию с доверенными хуками, затем обычный `pnpm run check`.
