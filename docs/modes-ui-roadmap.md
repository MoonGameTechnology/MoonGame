# Режимы в интерфейсе — roadmap

> Как новые режимы (PvE + командные 1v1..5v5) **гармонично вливаются в интерфейс**:
> вкладки в хабе под каждый режим, свои списки карт и открытых лобби, игроки
> собирают лобби и запускают матчи. Спутник `docs/pve-team-modes-roadmap.md`
> (план реализации ядра/данных) и `docs/main-menu.md` (дизайн мета-шелла) —
> здесь **план интеграции в UI**, не дизайн режимов: кирпичики, зависимости,
> «готово, когда». Парные доки: `main-menu.md` §4.1 (Играть),
> `matchmaking-roadmap.md` (MM-1.1/1.2 — лобби/предматч), `pve-team-modes-roadmap.md`
> (PVE-0..6 — ядро/данные), `CODE-MAP.md` (карта модулей).
>
> Формат — кирпичики: *зона · статус · зависимости · «Готово, когда».*
> Статусы: ✅ · ⏳ · 🔒(dep).

## Текущее состояние (факт)

- **Хаб** (`prototype/src/main.ts:8700`, `prototype/build.mjs:2892`): 7 вкладок —
  `home`, `games`, `rank`, `friends`, `arsenal`, `ally`, `more`. Вкладка `games`
  → `showHub(false)` → `showConnect(true)` → `enterBrowse()` — браузер матчей.
- **Браузер матчей** (`main.ts:8691` `enterBrowse`): 3 таба —
  `available`/`active`/`archived` (`matchRow.ts:27` `MatchTab`). Список матчей
  через `GET /matches` (`matchApi.ts`). Нет разделения по режимам.
- **`NetworkMatchMode`** (`matchSetup.ts:110`): `'ffa'|'2v2'|'5v5'`. Нет 1v1/3v3/4v4.
- **`GameModeDef`/`modeId`** — ⏳ (PVE-0.1, не реализован). Режимов в данных нет.
- **Лобби** (`matchmaking-roadmap.md` MM-1.1): ручной старт-лобби есть
  (`matchRoom.ts`), формальный ready-check ⏳. `createLobby(mapId, mode)` —
  интент из `main-menu.md` §4.1, не реализован.
- **`HUB_PANELS`** (`main.ts:8715`): `home`/`rank`/`meta`/`friends`/`arsenal`/
  `ally`/`more` → `hp-*` panel ids. Вкладка `games` — особая (уходит в браузер).

**Чего нет:** вкладок режимов в хабе, разделения браузера матчей по режимам,
создания/поиска лобби по режиму, UI выбора режима при создании лобби.

## Принципы

- **Гармоничное вливание.** Режимы — не отдельный экран, а **вкладки в хабе** рядом
  с `games`. Игрок видит все режимы как равноправные точки входа. UI не ломает
  существующий поток `games` → `enterBrowse` — расширяет его.
- **Surgical changes** (`CLAUDE.md:241`). Не переписываем хаб/браузер — добавляем
  вкладки и фильтрацию. Существующие `games`/`enterBrowse`/`MatchTab` не трогаем.
- **Data-driven.** Список режимов берётся из `data/modes/*.json` (PVE-0.1), не
  хардкодится в UI. Новые режимы = новые JSON + вкладка появляется автоматически.
- **Server-authority.** Каталог режимов/карт/лобби — серверные read-models; клиент
  шлёт интенты (`createLobby(mapId, modeId)`), не состояние.
- **Локализация.** Каждая вкладка режима — i18n-ключ (`hub.nav.pve`, `hub.nav.1v1`
  и т.д.) в `/localization/ru.ts` + `en.ts`. Гейт `i18n.test.ts` — зелёный.

## Фаза 0 · Каркас режимов в данных (зависимость) `[core][data]`

> 🔒 PVE-0.1 (`GameModeDef`/`modeId`) — без этого UI не знает список режимов.
> См. `docs/pve-team-modes-roadmap.md` Фаза 0.

### MODE-UI-0.1 · Каталог режимов как read-model `[srv]` 🔒(PVE-0.1) ⏳ — S
**Цель:** сервер отдаёт каталог режимов клиенту для рендера вкладок.
**Подзадачи:**
- `GET /modes` — read-model: список `GameModeDef` из `data/modes/*.json` (id, name
  i18n-ключ, `teamFormat`, `pve?`, описание).
- Валидация: режим без `data/modes/<id>.json` — не отдаётся (fail-secure).
**Готово, когда:** `GET /modes` возвращает список режимов; тест.

## Фаза 1 · Вкладки режимов в хабе `[proto][cli]`

> Вкладки режимов рядом с `games` в bottom nav хаба. Каждая — свой список карт и
> открытых лобби. Гармонично: тот же UI-паттерн, что `games`, но фильтрованный по
> режиму.

### MODE-UI-1.1 · `hubTab` расширяется под режимы `[proto]` 🔒(MODE-UI-0.1) ⏳ — M
**Цель:** хаб показывает вкладки режимов; клик → браузер матчей, отфильтрованный
по режиму.
**Подзадачи:**
- `HUB_PANELS` (`main.ts:8715`): не меняем существующие, добавляем динамические
  панели режимов (или переиспользуем `games` поток с фильтром).
- `hubTab(tab)` (`main.ts:8716`): если `tab` — режим (`pve`, `1v1`, `2v2`, …),
  → `showHub(false)` → `showConnect(true)` → `enterBrowse(modeId=tab)`.
- Вкладки рендерятся из `GET /modes` (динамически, не хардкод).
- HTML: кнопки в bottom nav (`build.mjs:2943`) — динамически после `games`.
**Готово, когда:** хаб показывает вкладки режимов; клик открывает браузер матчей
с фильтром по режиму. Тест: вкладки рендерятся из каталога, клик → фильтр.

### MODE-UI-1.2 · Браузер матчей с фильтром по режиму `[proto]` 🔒(MODE-UI-1.1) ⏳ — M
**Цель:** `enterBrowse(modeId?)` — браузер показывает матчи/лобби только этого
режима.
**Подзадачи:**
- `enterBrowse(modeId?: string)` (`main.ts:8691`): пробрасывает `modeId` в
  `refreshMatches(modeId)`.
- `refreshMatches(modeId?)` (`main.ts:10516`): `GET /matches?mode=<modeId>` —
  сервер фильтрует по `modeId` манифеста матча.
- `MatchTab` (`matchRow.ts:27`): не меняем (available/active/archived — внутри
  режима). Фильтр по режиму — поверх, не вместо.
- Заголовок браузера: имя режима (`t('mode.pve-waves')` и т.д.).
**Готово, когда:** браузер показывает матчи только выбранного режима; смена
режима → новый список. Тест: `enterBrowse('pve_waves')` → `GET /matches?mode=pve_waves`.

### MODE-UI-1.3 · Список карт по режиму `[proto][srv]` 🔒(MODE-UI-0.1) ⏳ — S
**Цель:** в браузере режима видны карты, поддерживающие этот режим
(`GameModeDef.requiredMap` / `teamFormat`).
**Подзадачи:**
- `GET /maps?mode=<modeId>` — read-model: карты из `data/maps/*.json`, отфильтрованные
  по совместимости с режимом (`avaShape` для team-режимов, `requiredMap` теги).
- UI: карточки карт (имя, размер, скорость, краткое описание) — выбор карты для
  создания лобби.
**Готово, когда:** в режиме `2v2` видны только 2-сторонние карты; в `pve_waves` —
карты с периферией (когда теги появятся). Тест.

### MODE-UI-1.4 · Локализация вкладок режимов `[data]` 🔒(MODE-UI-1.1) ⏳ — S
**Цель:** имена режимов в bottom nav хаба — i18n-ключи в обеих локалях.
**Подзадачи:**
- `hub.nav.pve`, `hub.nav.1v1`, `hub.nav.2v2`, `hub.nav.3v3`, `hub.nav.4v4`,
  `hub.nav.5v5` в `/localization/ru.ts` + `en.ts`.
- `mode.pve-waves.name`, `mode.duel.name`, `mode.team-2v2.name` и т.д. (имена
  режимов в заголовке браузера) — уже в PVE-1.3, но здесь — для UI хаба.
**Готово, когда:** гейт `i18n.test.ts` зелёный (ключи в обеих локалях).

## Фаза 2 · Создание и поиск лобби по режиму `[proto][srv]`

> Игроки собирают лобби под режим: выбирают карту, слоты, готовность, старт.

### MODE-UI-2.1 · UI создания лобби `[proto]` 🔒(MM-1.1, MODE-UI-1.3) ⏳ — M
**Цель:** игрок создаёт лобби: выбирает режим → карту → слоты → приватность.
**Подзадачи:**
- Кнопка «Создать лобби» в браузере режима.
- Модал/экран: выбор карты (из `GET /maps?mode=`), название, приватная/публичная,
  число слотов (по `teamFormat`: 1v1=2, 2v2=4, …).
- Интент `createLobby(mapId, modeId, options)` → сервер (`matchApi.ts`).
- После создания → экран лобби (слоты, готовность, старт).
**Готово, когда:** игрок создаёт лобби под режим; лобби появляется в списке
открытых. Тест.

### MODE-UI-2.2 · Экран лобби: слоты, готовность, старт `[proto][srv]` 🔒(MM-1.1, MODE-UI-2.1) ⏳ — M
**Цель:** лобби — слоты игроков, готовность, хост стартует.
**Подзадачи:**
- Список слотов (id, имя, фракция, готовность, AI/человек).
- `setReady`, `leaveLobby`, `kickSlot`, `fillWithAI` (хост).
- Хост: `startMatch` когда все готовы (или таймер).
- Командные режимы: слоты сгруппированы по team A/B (визуально).
- PvE: слоты людей + NPC-слот (Рой, не заполняется игроком).
**Готово, когда:** игроки собираются в лобби, готовы, хост стартует матч. Тест.

### MODE-UI-2.3 · Поиск/вход в открытое лобби `[proto]` 🔒(MODE-UI-2.1) ⏳ — S
**Цель:** игрок видит открытые лобби режима и входит.
**Подзадачи:**
- Список открытых лобби в браузере режима (карта, слоты заполнения, хост).
- `joinLobby(id)` → экран лобби.
- Фильтр: только лобби текущего режима.
**Готово, когда:** игрок находит и входит в лобби режима. Тест.

> 🔒 MM-1.2 (предматч: фракция/техи). Расширение под режим.

работает. Тест.

## Фаза 5 · Гармоничное вливание (полировка) `[proto][cli]`

> Режимы — не «прикручены сбоку», а органичная часть хаба.

### MODE-UI-5.1 · Визуальный язык вкладок режимов `[proto]` ⏳ — S
**Цель:** вкладки режимов визуально согласованы с хабом, не чужеродны.
**Подзадачи:**
- Иконки режимов (PvE — щит/волна, 1v1 — мечи, 2v2 — два щита, и т.д.).
- Цвет-акцент режима (PvE — янтарный/тёплый, командные — синий/зелёный по team).
- Анимация переключения вкладок (тот же паттерн, что `games`).
**Готово, когда:** вкладки режимов визуально неотличимы от существующих по стилю.

### MODE-UI-5.2 · Адаптивность: мобайл/десктоп `[proto]` ⏳ — S
**Цель:** на мобайле вкладки режимов не переполняют bottom nav.
**Подзадачи:**
- Если режимов > 7 — горизонтальный скролл bottom nav (или hamburger «Ещё режимы»).
- На десктопе — все вкладки видны; на мобайле — скролл/группировка.
**Готово, когда:** 7+ вкладок не ломают вёрстку на мобайле. Тест на 320px.

### MODE-UI-5.3 · «Требует внимания» для режимов `[proto]` ⏳ — S
**Цель:** async-лента хаба (`main-menu.md` §5.1) показывает режим-специфичные алерты.
**Подзадачи:**
- PvE: «Волна 3 наступает через 2 часа» / «Рой атакует планету X».
- Командные: «Сокомандник ждёт твоего приказа» / «Командный матч требует внимания».
- Существующая лента — не трогаем, добавляем типы алертов.
**Готово, когда:** лента показывает режим-специфичные алерты. Тест.

## Зависимости и последовательность

```
PVE-0.1 GameModeDef (ядро)         ← 🔒 фундамент, без этого UI не знает режимы
   ↓
MODE-UI-0.1 GET /modes (сервер)    ← каталог режимов как read-model
   ↓
MODE-UI-1.1 hubTab расширяется     ← вкладки режимов в хабе
MODE-UI-1.2 браузер с фильтром      ← enterBrowse(modeId)
MODE-UI-1.3 список карт по режиму   ← GET /maps?mode=
MODE-UI-1.4 локализация вкладок    ← i18n ключи
   ↓
MODE-UI-2.1 UI создания лобби      ← createLobby(mapId, modeId)
MODE-UI-2.2 экран лобби             ← слоты, готовность, старт
MODE-UI-2.3 поиск/вход в лобби      ← joinLobby(id)
   ↓
MODE-UI-3.1 предматч под режим      ← фракция + команда + PvE контекст
   ↓
MODE-UI-4.1 итоги под режим         ← режим-специфичная информация
   ↓
MODE-UI-5.1 визуальный язык         ← полировка
MODE-UI-5.2 адаптивность            ← мобайл/десктоп
MODE-UI-5.3 «Требует внимания»      ← алерты
```

**Порядок сборки:** MODE-UI-0.1 (сервер) → MODE-UI-1.* (хаб + браузер, параллельно
с PVE-1..3 ядра) → MODE-UI-2.* (лобби) → MODE-UI-3.1 (предматч) → MODE-UI-4.1
(итоги) → MODE-UI-5.* (полировка).

## Тесты как страховка

- **Перед изменением** `hubTab`/`enterBrowse`/`refreshMatches` — запустить
  существующие тесты, убедиться зелёные.
- **После каждого изменения** — `pnpm run check` (lint + typecheck + test + docs-check).
- **Регрессионные тесты** — существующий поток `games` → `enterBrowse` не сломан.
- **TDD-цикл** — для каждого UI-кирпичика сначала тест, потом реализация.
- **Локализация** — гейт `i18n.test.ts` после каждого нового ключа.
