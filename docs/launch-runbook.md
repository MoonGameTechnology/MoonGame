# Запуск сервера и приглашение игроков — ранбук

> Сверено с кодом 2026-10-19. Канонический путь для живых игроков — **прототип-хост**
> `prototype/netserver.ts`; его же запускает образ сервера (`proto-server.mjs`). Это единый
> HTML-клиент (браузер + APK) поверх авторитетного сервера с полным ядром прототипа
> (состав ядра — `state.md` §9: весь каталог плюс два модуля прототипа).
> Альтернативный стек `packages/server/src/main.ts` + `packages/client` стоит на той же
> серверной инфраструктуре, но его клиент отдаёт 11 из 53 приказов — игроков туда не
> приглашаем (см. «Дальше»). Боевую установку ведёт
> [руководство развёртки](../deploy/README.md); этот ранбук — короткая карта и проверка
> того, что увидит игрок.

## 1. Запуск

### Публичный сервер (VPS)

Только по [руководству развёртки](../deploy/README.md):

- `sudo bash deploy/install-ubuntu.sh` ставит Docker-стек в `/opt/moongame` и команду
  `moongame` (`status`, `logs`, `restart`, `update`).
- `bash deploy/launch.sh --build` (`pnpm stack`) поднимает стек через production-preflight;
  `deploy/stack.sh` — то же на подписанном образе, `deploy/update.sh` — обновление с
  миграцией и откатом. С `DOMAIN` в `server.env` включается TLS-оверлей с Caddy.
- `PROD=1` (дефолт образа) не даёт серверу стартовать без `AUTH_JWT_SECRET`, `GATE=1`,
  `SEAT_LOCK=1`, `ALLOWED_ORIGINS`, TLS, least-privilege роли БД и политики бэкапов
  (`BACKUP_POLICY`).
- Автодеплой (ZTP), если его включить, сам довозит merge в `main` до сервера — раздел
  «Автодеплой» руководства.
- Правка `deploy/server.env` (например, новый адрес в `ALLOWED_ORIGINS`) вступает в силу
  после `moongame restart`.

### Локальный или дружеский плейтест

```bash
git clone https://github.com/MoonGameTechnology/MoonGame && cd MoonGame
pnpm install
pnpm host   # сборка клиента + сервер на 0.0.0.0:8788, печатает ссылку для игроков
```

Без `AUTH_JWT_SECRET` это открытый режим `?nick=`: кто знает ник, займёт место, и сервер
предупреждает об этом при старте. `deploy/serve.sh` (tmux-сессия «void») — тоже только для
разработки: по умолчанию слушает loopback, LAN требует `ALLOW_INSECURE_LAN=1`, а с
`PROD=1` скрипт откажется работать.

Переменные хоста (читает `prototype/netserver.ts`, полная таблица — в
[руководстве развёртки](../deploy/README.md)):

| Переменная | Значение |
| --- | --- |
| `HOST` / `PORT` | куда биндиться (дефолт хоста `127.0.0.1`, `pnpm host` ставит `0.0.0.0`; порт 8788) |
| `TIME_SCALE` | ускорение мира: 1 = реальное время, 24 = сутки за час (дефолт compose) |
| `DATABASE_URL` | Postgres: матчи, квитанции и места переживают рестарт; без неё — in-memory |
| `AUTH_JWT_SECRET` | аккаунты (логин/пароль → session-JWT → join-токен); без него — `?nick=` |

## 2. Доступ игроков снаружи

Сервер отдаёт игру сам: игрок открывает `https://<домен>/` (или `http://<адрес>:8788/` в LAN).

- **Свой домен** — Caddy с автоматическим Let's Encrypt перед сервером
  (`deploy/Caddyfile` + `deploy/docker-compose.tls.yml`, HTTPS-2.1/2.2), сервер на
  loopback. Альтернатива — нативный TLS по `TLS_KEY_FILE`+`TLS_CERT_FILE` (RS-5.1).
  Рецепты — в [руководстве развёртки](../deploy/README.md).
- **Без домена, для разработки** — туннель `cloudflared tunnel --url http://localhost:8788`;
  адрес туннеля нужно добавить в `ALLOWED_ORIGINS`. Диагностика сети: `pnpm doctor`.
- **Клиент из веба (GitHub Pages)** — `pages.yml` публикует соло-сборку на
  `https://moongametechnology.github.io/MoonGame/`; последние прогоны на `main` зелёные
  (сверено 2026-10-19). Если деплой снова начнёт падать за ~3 с без шагов, Pages выключились
  в настройках: Settings → Pages → Source «GitHub Actions» (подробно — комментарий в
  `pages.yml`).
- **Клиент из веба (Cloudflare)** — воркер раздаёт статику без своего кода
  (`wrangler.jsonc` в корне, имя в нём — `moongame`; сборки и превью в Cloudflare идут под
  именем `void-dominion`). Workers Builds выкладывает его на каждый push в `main`
  командой `npx wrangler deploy`, а пуш в любую другую ветку — превью командой
  `npx wrangler preview`. Сайт обе команды собирают сами: `build.command` в
  `wrangler.jsonc` — `pnpm run site` (сборка прототипа + `scripts/stage-site.mjs`), так
  что команда сборки в дашборде не нужна; превью, кроме того, требует блок `previews`. На
  сайте три страницы: `/` — тот же `void-dominion.html`, что и у Pages,
  `/sector-zero.html`, `/player.html`; админка и архив площадки не публикуются. Сервер
  партий сюда не едет — только клиент, а адрес сервера вшивается в страницы на сборке
  (`GAME_SERVER` в `build.command`, `scripts/siteServer.mjs`), и поле «сервер» стартует на
  нём. Сервер пускает такую страницу, только если её origin есть в `ALLOWED_ORIGINS` на
  хосте сервера (и для `/auth`, `/matches` по CORS, и для рукопожатия WS). В PR превью — это
  проверка «Workers Builds: void-dominion»: мерж её не ждёт, а лог сборки виден только в
  дашборде Cloudflare.
- **Android APK** — `android.yml` собирает два APK: dev (rolling-релиз `alpha`) и player
  (rolling-релиз `player`, свой applicationId, ставится рядом с dev). В каждом встроен
  автоапдейтер своего релиза. Адрес сервера вшит на сборке (`VOID_SERVER`, сейчас VPS
  владельца), игрок может сменить его в карточке «Сервер не отвечает». Origin APK
  `http://localhost` должен быть в `ALLOWED_ORIGINS` сервера.

## 3. Как выглядит вход для игрока

1. Открыл ссылку → «Вход по позывному». С `AUTH_JWT_SECRET` там же пароль: первый вход
   создаёт аккаунт. Кнопки Google и Apple пока отвечают «скоро».
2. Хаб → **Игра по сети** → страница «Матчи» (UIX-17.1): вкладки «Доступные / Мои /
   Архив», фильтр по виду, картам и числу игроков. Полей адреса и позывного на странице нет:
   адрес берётся со страницы (или вшитый), позывной — со входа. Список тихо обновляется раз
   в 10 секунд.
3. «Войти» на свободное место либо «Новый матч» → карта → «Создать». Лобби нет (SES-2.1,
   модель Iron Order): мир живёт 24/7 с момента создания, игрок всегда попадает в уже
   идущую партию — ни хоста, ни кнопки Start.
4. Место закреплено за позывным (таблица `seats`): выход, возврат и рестарт сервера
   сохраняют место и мир. Пока игрок офлайн, его оборону держит серверный ИИ; брошенное
   кресло ИИ забирает целиком через `AI_GRACE_MS` (дефолт — 3 реальных дня). Новичок может
   войти в партию в течение `ENTRY_WINDOW_MS` от её создания (дефолт — 4 дня).

## 4. Ограничения текущего пути (важно при приглашении)

- **Партии — сущности, а не комнаты процесса (ADDR-1).** Список партий хост берёт из стора;
  `MATCHES=N` (до 16) только засевает пустой стор на старте. Новые партии создаются кнопкой
  (`POST /matches`): не больше трёх идущих на одну учётку и не больше 64 в одном процессе.
  На хосте можно закрыть создание игроками своей политикой (`COMPOSE_EXTRA_FILE`); на VPS
  владельца так и сделано (на 2026-10-18), партии заводит оператор.
- **Места задаёт карта.** `duel-1` — 2, `ffa-4` — 4, `team-2v2` — 4, `team-3v3` — 6,
  `ffa-20` — 20, `ffa-50` — 50. `TEAMS` — легаси-параметр и на этих картах число мест не
  меняет. Порог победы тоже свой у каждой карты (`MAP_SCORE_LIMITS` в
  `packages/shared-core/src/action/mapVictory.ts`, одна таблица для обоих хостов).
- **Аккаунты** (SES-2.5) включаются `AUTH_JWT_SECRET`: регистрация и вход
  (`POST /auth/register|login` → session-JWT), обмен сессии на join-токен
  (`GET /matches/:id/join`) для WS-рукопожатия, восстановление пароля почтой (нужны
  `RESET_BASE_URL` и SMTP), выход со всех устройств, удаление аккаунта. Без секрета —
  dev-режим `?nick=` либо `SEAT_LOCK=1` (посадочные билеты, дефолт в compose).
- **TLS — два пути** (RS-5.1): сервер терминирует его сам (`TLS_KEY_FILE`+`TLS_CERT_FILE`)
  либо за Caddy из `deploy/docker-compose.tls.yml`, и тогда серверу ставят `TRUST_PROXY=1`,
  чтобы он видел IP клиента, а не прокси.
- **Action-gate** включается `GATE=1` (дефолт в compose): `ActionGate` стоит перед
  редьюсером на netserver-пути (REL-4).
- **Конец матча:** победа фиксируется, партия уходит во вкладку «Архив». Новая партия —
  кнопкой «Новый матч», рестарт процесса для этого не нужен.

**Блок NET-P0 закрыт** (порог победы и timeScale доезжают до комнаты, совет учёных у всех
мест, боевые эффекты видны по сети, сессионный чат через сервер — session/коалиция/DM с
реплеем бэклога на джойне, переговоры между людьми консент-офферами: война →
предложение мира → у второй стороны кнопка «✓ принять» → мир; проверено e2e двумя
живыми игроками).
