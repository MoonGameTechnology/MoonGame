# Яндекс Игры — возможности и требования для Void Dominion: Sector Zero

> **Статус:** Draft / platform reference. Проверено по официальной документации Яндекс Игр 16 сентября 2026 года. Требования платформы могут меняться; перед отправкой каждой production-версии на модерацию необходимо повторно сверять актуальную документацию.

## Цель документа

Зафиксировать, что Яндекс Игры предоставляет Sector Zero, какие ограничения накладывает площадка и какие требования нужно учитывать при проектировании HTML5-клиента, сохранений, рекламы, покупок, UX и release pipeline.

# 1. Что предоставляет Яндекс Игры

## 1.1. SDK обязателен

SDK Яндекс Игр должен быть встроен в игру для прохождения модерации и публикации.

Через SDK доступны:

- авторизация и данные игрока;
- облачные сохранения;
- реклама;
- внутриигровые покупки;
- лидерборды;
- серверное время;
- управление отдельными параметрами игры без обновления билда;
- Game Ready / gameplay lifecycle API;
- полноэкранный режим;
- предложение пользователю оценить игру;
- установка иконки игры на рабочий стол (там, где поддерживается).

Для архитектуры MoonGameTechnology SDK Яндекса должен находиться за `YandexGamesAdapter`, а gameplay Sector Zero не должен обращаться к нему напрямую.

# 2. Авторизация

## Возможности

Яндекс предоставляет объект игрока и возможность авторизации через Яндекс ID.

Для авторизованного игрока SDK может предоставить, в зависимости от разрешений и доступности:

- стабильный идентификатор;
- имя;
- аватар;
- данные/идентификаторы игрока;
- платежный статус пользователя в поддерживаемых случаях.

## Требования

Игра не должна требовать регистрации или авторизации через сторонний сервис для запуска и использования на Яндекс Играх.

Допустима авторизация через Яндекс ID средствами SDK.

Запрос авторизации должен происходить после осознанного действия пользователя (например, кнопки), а интерфейс должен объяснять преимущество авторизации.

### Следствие для Sector Zero

Yandex build не должен блокировать первый запуск экраном MoonGameTechnology Account.

Если позднее понадобится связать Sector Zero с основной Void Dominion, cross-game linking следует проектировать отдельно и так, чтобы он не нарушал требования площадки.

# 3. Облачные сохранения

Яндекс позволяет хранить прогресс на своих серверах или использовать собственный сервер.

## Лимиты SDK Player

`player.setData()`:

- до **200 КБ данных на игрока**;
- лимит запросов: до 100 запросов за 5 минут.

`player.setStats()` / числовая статистика:

- до **10 КБ**;
- предназначена для часто меняющихся числовых значений вроде опыта, очков и валют;
- лимит соответствующих запросов — до 60 в минуту.

Если состояние превышает лимиты SDK (официальная документация отдельно приводит пример сложной стратегии с большим количеством юнитов), Яндекс рекомендует использовать собственный сервер.

## Требования к прогрессу

Если игра имеет прогресс — уровни, достижения, улучшения, победы и т. п. — прогресс не должен теряться после обновления страницы или смены ориентации.

Сохранять изменения необходимо после действий пользователя либо по явно предусмотренной механике сохранения.

**Для игр с внутриигровыми покупками облачное серверное сохранение обязательно**, а прогресс и покупки должны быть доступны одному пользователю с разных устройств.

### Предложение для Sector Zero

Для первой PvE-версии стремиться держать компактный versioned meta-save в пределах лимита Яндекса:

- сюжетный прогресс;
- открытые миссии;
- герои;
- skills;
- modules;
- currencies/resources;
- Classified Files;
- настройки/необходимые meta flags.

Не хранить в platform save огромный полный snapshot долговременной grand-strategy вселенной. Если состояние Sector Zero перерастёт 200 КБ или появятся критичные серверные системы, переносить соответствующую часть на собственный backend.

# 4. Реклама

Яндекс поддерживает через SDK:

- fullscreen/interstitial;
- rewarded video;
- sticky banners.

## Обязательные требования

- Реклама вызывается только через SDK Яндекс Игр.
- Сторонняя реклама внутри Yandex build запрещена.
- После перехода по рекламе и возврата игровой процесс должен сохраняться.
- Реклама должна соответствовать ориентации игры.
- Fullscreen-реклама показывается только в логических паузах и не должна мешать взаимодействию.
- При fullscreen/rewarded показе звук и gameplay должны быть поставлены на паузу.

## Rewarded Video

Rewarded-реклама должна быть добровольной.

До просмотра игроку должно быть однозначно понятно:

1. что сейчас будет показана реклама;
2. какую конкретную награду он получит.

Награда является **дополнительным бонусом** и не должна быть необходима для продолжения основного gameplay.

### Предложение для Sector Zero

Основной рекламный формат — rewarded video между игровыми действиями/после PvE-сессии.

Возможные placements:

- дополнительная часть meta reward;
- дополнительный salvage;
- дополнительный вариант награды;
- небольшой бонус progression resource.

Interstitial использовать осторожно и только в естественных паузах. Retention и repeat-match rate важнее максимального количества показов.

# 5. Внутриигровые покупки (IAP)

Яндекс Игры поддерживают покупки через SDK.

Покупки делятся, в частности, на:

- постоянные (например отключение рекламы);
- используемые/consumable (например внутриигровая валюта).

Для consumable purchases используется механизм консумирования.

## Критический порядок обработки

Перед консумированием покупки необходимо сначала корректно начислить/сохранить приобретённую ценность игроку. После `consumePurchase()` обработанная покупка удаляется и восстановить её через этот вызов нельзя.

## Требования

- подключён корректный механизм обработки/консумирования;
- используется портальная валюта, определяемая SDK;
- цена отображается цифрами и с портальной валютой;
- описание, изображение и фактический состав покупки совпадают;
- активные товары в игре соответствуют товарам, настроенным в Консоли;
- покупки и прогресс сохраняются на сервере и доступны пользователю на другом устройстве.

### Предложение для Sector Zero

Первая товарная матрица должна быть маленькой и понятной:

- Starter Pack;
- Meta/Premium Currency;
- Module/Progression Pack;
- возможно Remove Ads, если формат рекламы это оправдает.

Главный принцип Sector Zero:

> **Покупка ускоряет метапрогрессию, а не является обязательным условием прохождения PvE.**

# 6. Размер и структура билда

На 16 сентября 2026 года:

- **размер всех файлов игры — не более 100 МБ в разархивированном виде**;
- в корне архива должен находиться `index.html`;
- в именах файлов и каталогов нельзя использовать пробелы и русские символы.

### Следствие для Sector Zero

Yandex build должен быть отдельной оптимизированной production-сборкой, а не полной Void Dominion со скрытыми ненужными системами.

Не включать без необходимости:

- assets основной grand strategy;
- FFA/large-map content;
- corporate UI/assets;
- неиспользуемые видео/аудио;
- SDK других площадок.

Platform-specific SDK по возможности включается только в соответствующий build target.

---

# 7. Техническая стабильность

Игра должна работать без зависаний, вылетов и технических ошибок при обычном gameplay и при системных действиях, включая:

- поворот экрана;
- жесты/длительное нажатие;
- сворачивание браузера;
- показ рекламы и возврат;
- переходы по истории браузера;
- другие типичные действия пользователя.

Поддержка должна соответствовать окружению, заявленному в черновике. В актуальных требованиях перечислены основные desktop browsers, мобильное приложение Яндекс, Android/iOS и другие поддерживаемые среды.

### Особое значение для Sector Zero

Наши предыдущие проблемы с Android/WebView, zoom и камерой являются **release blockers для Yandex build**, если воспроизводятся в поддерживаемом окружении.

Нужна отдельная device/browser QA matrix до отправки на модерацию.

---

# 8. Game Ready и lifecycle

SDK должен быть корректно инициализирован.

Когда пользователь уже может начать игру, необходимо корректно вызвать `LoadingAPI.ready()`.

Если используется Gameplay API, моменты `GameplayAPI.start()` и `GameplayAPI.stop()` должны соответствовать реальному состоянию gameplay.

При обработке pause/resume событий необходимо корректно приостанавливать и восстанавливать игру.

Для Sector Zero lifecycle должен быть частью `YandexGamesAdapter`, а не размазан по PvE gameplay code.

---

# 9. Требования к пользовательскому опыту

Платформа требует законченный и проработанный продукт.

Важно:

- управление полностью описано;
- игра соответствует заявленному жанру;
- сложность нарастает;
- присутствует понятный сюжет или сеттинг;
- основное содержание занимает более 10 минут **или** присутствует мотивация к перепрохождению;
- для сложных игр Яндекс рекомендует обучение;
- игра должна выглядеть завершённой, а не alpha/preliminary test.

### Sector Zero

Это прямо поддерживает выбранную продуктовую стратегию:

- понятный onboarding;
- постепенное знакомство с системами;
- законченная первая сюжетная глава;
- повторяемый PvE;
- метапрогрессия;
- причина начать второй матч.

Не публиковать Sector Zero как «технический тест Void Dominion». Для Яндекс Игр это должен быть самостоятельный законченный продукт.

---

# 10. Локализация

В игру должно быть встроено автоопределение языка через SDK Яндекс Игр.

Тексты, имеющие значение для gameplay и меняющиеся в зависимости от языка, должны быть локализованы для заявленных языков.

Если есть ручное переключение языка, пользователь должен иметь возможность найти его, не понимая текущий язык интерфейса.

### Предложение

Для первого релиза Sector Zero как минимум качественно поддержать RU и EN, если оба языка заявляются в Консоли.

---

# 11. Контентные ограничения, важные для Sector Zero

Актуальные требования запрещают ряд категорий контента. Особенно обратить внимание:

- игра не должна содержать запрещённые политические/реальные межгосударственные сюжеты и соответствующие отсылки;
- запрещены определённые религиозные материалы/отсылки;
- запрещены азартные игры/онлайн-лотереи и операции с реальными внеигровыми ценностями;
- материалы должны соответствовать возрастному рейтингу;
- права на используемые материалы должны принадлежать разработчику/правообладателю;
- интерактивный генеративный AI внутри игры запрещён; заранее созданные AI-материалы допускаются.

### Важно для нашей RNG-прогрессии

Hero duplicates, skill upgrade chance и risky crafting должны оставаться **внутриигровой progression-механикой**, а не превращаться в азартную игру с возможностью вывода/выигрыша реальных ценностей.

Не должно существовать cash-out или обмена игровых результатов на реальные деньги/призы.

---

# 12. Отдельные игры одного разработчика

Яндекс запрещает публиковать полные/частичные копии других игр каталога или дубликаты собственных игр.

Продолжение/другая часть может приниматься отдельно, если существенно переработаны сеттинг и/или механики; иначе новый контент следует добавлять обновлением существующей игры.

### Следствие для нашей продуктовой стратегии

`Sector Zero`, `First Contact` и другие будущие продукты нельзя планировать как один и тот же билд с заменённой обложкой.

Каждая отдельная публикация должна быть самостоятельным продуктом с реально отличающимся gameplay/settting/content там, где этого требуют правила платформы.

---

# 13. Промоматериалы

Для публикации необходимо подготовить обязательные поля и материалы: название, описание, инструкцию «Как играть», версию, категории, иконку, обложку, архив, платформы, ориентацию и скриншоты.

Ключевые правила:

- промоматериалы должны относиться к реальной игре;
- скриншоты в основном демонстрируют настоящий gameplay;
- название совпадает в игре и материалах;
- иконка/обложка не должны быть просто скриншотом;
- материалы должны быть технически качественными и не вводить пользователя в заблуждение;
- название должно быть уникальным в каталоге для выбранных языков.

### Sector Zero

Перед финальным брендингом проверить доступность/уникальность названия **Void Dominion: Sector Zero** непосредственно в каталоге и Консоли Яндекс Игр.

---

# 14. Ссылки и cross-promotion

Требования ограничивают внешние ссылки из игры и медиаматериалов. Допустимые переходы на другие игры в каталоге Яндекс Игр должны выполняться через предусмотренные SDK-механизмы.

Нельзя рассчитывать на обычную внешнюю кнопку вида «скачать полную Void Dominion на нашем сайте/в другом store» без отдельной проверки соответствия правилам.

### Следствие

Будущую воронку `Sector Zero → Void Dominion` для Yandex-аудитории нужно проектировать с учётом разрешённых platform-native способов cross-promotion и account/entitlement architecture, а не через произвольные внешние ссылки.

---

# 15. Модерация

По актуальной документации обычная модерация занимает примерно **3–5 рабочих дней**.

Игра проходит проверку технических требований, UX, контента, рекламы и промоматериалов.

Sector Zero следует отправлять на модерацию только как release candidate, прошедший собственный pre-moderation checklist.

---

# 16. Что особенно хорошо подходит Sector Zero

Яндекс Игры дают нам практически весь необходимый platform layer для первого PvE validation:

```text
Yandex ID / Player
        ↓
Cloud Save
        ↓
Sector Zero PvE
        ↓
Rewarded Ads + IAP
        ↓
Meta Progression
        ↓
Analytics / product validation
```

При этом собственные multiplayer-серверы Яндекс нам не заменяет — и для Sector Zero v1 это не является проблемой, поскольку продукт целенаправленно строится вокруг PvE.

# 17. Pre-release checklist для Sector Zero

Перед отправкой в Яндекс Игры проверить:

- SDK встроен и корректно инициализируется;
- Game Ready вызывается в правильный момент;
- игра запускается без сторонней обязательной авторизации;
- Yandex auth работает по явному действию игрока;
- прогресс переживает reload;
- cloud save работает между устройствами для авторизованного пользователя;
- IAP начисляется идемпотентно и корректно консумируется;
- rewarded ad выдаёт награду только после подтверждённого завершения;
- gameplay/audio корректно ставятся на паузу во время fullscreen ads;
- interstitial появляется только в логических паузах;
- отказ/недоступность рекламы не блокирует progression;
- build ≤ 100 МБ в разархивированном виде;
- `index.html` находится в корне;
- нет русских символов/пробелов в путях build-файлов;
- Android/mobile browser QA пройден;
- desktop browser QA пройден;
- onboarding понятен новому игроку;
- управление опис
