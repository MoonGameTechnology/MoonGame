# Шаблон плейтеста (2 человека) — чеклист

Заполняется **после каждого живого теста** на двоих. Цель — чтобы у каждого теста
были и машинные данные (JSONL-лог сервера), и человеческие наблюдения (баги, что
путало, фан). Это брик **M0** из `docs/metrics-roadmap.md`; как поднять сервер —
`docs/multiplayer.md`.

Копируй блок ниже в новый файл (например, `playtest-logs/2026-06-26-notes.md`) и
заполняй. Машинный лог лежит рядом: `playtest-logs/match-YYYY-MM-DD.jsonl`
(журнал за UTC-день, все партии дня; пишется сам), сводка печатается в терминал сервера по `Ctrl-C`.
События браузеров — в `playtest-logs/client-YYYY-MM-DD.jsonl` (вход, связь, ошибки; PTM-1).

Сетевой тест на десятках людей (прод-сервер, приглашение по ссылке) идёт по порядку из
скилла `playtest-report` (раздел «Сетевой тест»): что проверить до, на что смотреть во время,
какие отчёты снять после и как забрать журналы с хоста. Раздел G — анкета, её получает
каждый тестер.

## Машинные данные (приложить к заметкам)

1. **Сводка сервера** — скопировать из терминала блок `── playtest summary ──`
   (joins/leaves/actions/ok/rejects/by type/by reject/match end).
2. **JSONL-лог** — `playtest-logs/match-YYYY-MM-DD.jsonl` (по строке на событие, у каждой — `match`:
   `join` / `leave` / `action` / `end`; `lobby` оставлен для паритета транспорта, но при авто-старте SES-2.1 не эмитится). Быстрый разбор, например:
   ```bash
   # сколько действий каждого типа и сколько реджектов
   grep '"kind":"action"' playtest-logs/match-*.jsonl | wc -l
   grep '"ok":false' playtest-logs/match-*.jsonl
   ```
   Отчёт по одной партии: `pnpm run metrics -- --day YYYY-MM-DD --match <id>`.
3. Если ловили desync — сохранить кадр/скрин оверлея с `✗` и время.
4. **Поведение игроков** — вывод `pnpm run analytics -- --from YYYY-MM-DD --to YYYY-MM-DD`
   (воронка, связь, загрузка, ошибки, сессии, удержание) за дни теста.
5. **Счётчики приёмника** — `journal` и `telemetry` из `/metrics/summary` в конце теста:
   принято событий, отброшено, отклонено запросов.
