## Результат

Транспорт и проверки подлинности работают в проверенных сценариях, но **TLS 1.3
везде и шифрование всех данных не обеспечены текущей конфигурацией**. Успешный тест
наблюдения «TLS 1.2/CBC принят» подтверждает ограничение, а не безопасность этой политики.

| Область | Подтверждено | Ограничение |
| --- | --- | --- |
| Нативный HTTPS/WSS | TLS 1.3 с AEAD; доверенная CA + корректный SAN; WSS welcome без отключения проверки сертификата | Также принимаются TLS 1.2 и CBC; минимум 1.3 не задан |
| Старые TLS и MITM | TLS 1.0/1.1 отвергнуты даже с разрешёнными клиентом legacy-ciphers; чужая CA и неверный hostname отвергнуты; plaintext HTTP не работает на TLS listener | Не аттестация сертификата живого сайта |
| JWT | HS256; alg=none, изменение player claim, неверная подпись/alg/issuer/audience/typ, просроченные токены отвергнуты; ротация проверена | JWT подписан, не зашифрован |
| Пароли | scrypt, случайная соль 16 байт, ключ 32 байта, timingSafeEqual; пароль в browser session record не хранится | См. ECP-03 |
| PostgreSQL | Runtime role реально входит с SCRAM-SHA-256; отдельные права из #1566 | См. ECP-01 |
| Зашифрованный бэкап | age v1.2.1; корректный ключ работает; чужой ключ отвергнут; подменённый шифротекст с пересчитанным SHA-256 отвергнут до SQL | SHA-256 sidecar сам по себе не обеспечивает подлинность; её для .age обеспечивает authenticated decryption |
| Wire-протокол | JSON/action.v1; gate проверяет schema, полномочия, session binding, порядок и повтор действия; malformed/raw flood/oversize/compressed bomb тесты прошли | Это защита действий, не одноразовость bearer JWT и не отдельное E2E-шифрование сообщений |
| Память/файлы | Нет прикладного шифрования игровых JSONB | См. ECP-05 |

### ECP-02 · Токен сброса в debug-логах — исправлено

Статус на 2026-10-13: флаг `MAILER_LOG_BODY` удалён (#1574), письма уходят через SMTP.

По умолчанию `authApi.ts` скрывает тело recovery-письма. Два дополнительных теста
показали: `MAILER_LOG_BODY=1` выводит bearer reset link и при `PROD=1`. Это сознательный
debug opt-in, а не утечка по умолчанию. Recovery также зависит от RESET_BASE_URL;
реальное значение на хосте неизвестно. Запретить этот флаг в production и подключить
доставку, не пишущую содержимое в логи; не считать отдельный redacted security JSONL
гарантией отсутствия токенов во всех журналах. По умолчанию логируется адрес получателя.

### ECP-04 · Явная политика TLS 1.3 / AEAD — исправлено для нативного сервера

Статус на 2026-10-13: нативный сервер принимает TLS 1.2 только с AEAD-шифрами (#1604).

Нативный Fastify получает PEM key/cert без minVersion/ciphers. Живой тест принял
`TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256` при TLS 1.2. TLS 1.0/1.1 отвергнуты.
Это расхождение с SE-1.2, не доказанный эксплойт CBC. Для политики TLS 1.3 выставить
минимум явно в обоих TLS-терминаторах; если совместимость требует TLS 1.2, отдельно
разрешить современные ECDHE+AEAD suites. `deploy/Caddyfile` не задаёт явную политику
версий; его реальный публичный handshake в этом аудите не запускался.

Caddy терминирует HTTPS/WSS, затем делает `reverse_proxy server:8788` по HTTP в
приватной сети. Это шифрование внешнего участка, не TLS между каждым компонентом.
HTTP/3 заявлен конфигурацией Caddy по умолчанию; QUIC/ALPN/UDP 443 живого хоста
не проверены. Нативный сервер с теми options не становится HTTP/2/HTTP/3 сервером.

## Протокол: что не следует путать

Join JWT имеет срок 15 минут и purpose/match/player scope. sessionId/clientSeq/actionId
и receipts препятствуют подмене, неправильному порядку и повторному применению
**игровых действий**; это не защита bearer-токенов. Замечания по жизненному циклу
токенов ведутся вне публичного репозитория. Встроенная CSP и Origin-check проверены;
полного нового XSS-аудита не было.

Wire-контракт общий для клиента и сервера (паритет проверен). Невалидный action.v1
доходит до ActionGate и там отвергается; parser сам не обязан считать его валидным.
WS maxPayload — 32768 **после распаковки**; permessage-deflate согласуется с браузерами,
serverNoContextTakeover включён. Повреждённый кадр закрывает свой сокет, не процесс.
Протокол не использует собственное шифрование/подпись каждой JSON-команды: защиту
транспорта обеспечивает TLS, а полномочия — серверная проверка.

## Метод и доказательства

Среда: Node 22.23.3 (OpenSSL 3.5.8), PostgreSQL 16.15, age 1.2.1; TLS-negotiation выполнен на
нативном сервере под Node 22. Это не отдельный запуск финального Docker-образа с
его Node/OpenSSL и не публичный handshake Caddy. Публичный TLS-профиль проверять
на фактически запущенном image digest и endpoint.

- Полный `pnpm run check` на свежем main прошёл; актуальный счётчик — в [state.md](../state.md).
- **162 различных целевых проверки:** 138 существующих TLS/auth/password/wire/gate;
  16 дополнительных наблюдательных/негативных cases; 8 реальных backup/restore.
- Логи: первый набор 147/147; дополнительный набор 14/14; два отдельных reset-logger
  cases 2/2; backup 8/8. Повтор CBC-only выполнен для фиксации negotiated cipher.
  Skips в выборочном запуске означают невыбранные cases, а не недоступность инструмента.
- [Параметры Node/TLS стенда](2026-10-10-encryption-runtime.json).
- Дополнительные cases: [текст воспроизводимого теста](2026-10-10-encryption-protocol-cases.txt).
  Для повторения скопировать в `packages/server/src/__encryptionProtocolAudit.test.ts`
  в **одноразовом checkout**, выполнить Vitest и затем убрать временный файл.
- [Результаты PostgreSQL и authenticated backup-проверки](2026-10-10-encryption-database-results.json):
  выделенный PostgreSQL 16.15, loopback-only порт; база/роли/данные синтетические.
- age v1.2.1 — официальный release; SHA-256 бинарного архива
  `7df45a6cc87d4da11cc03a539a7470c15b1041ab2b396af088fe9990f7c79d50`.
- TLS CA и приватный RSA-ключ созданы только в tmpdir и удалены; сертификат доверялся
  адресно через ca, а не через rejectUnauthorized=false. Legacy-client cipher override
  использовался только для доказательства **отказа** сервера от TLS 1.0/1.1.
- Ошибки первоначальной сборки audit-harness (неверное имя export и кавычки SQL)
  исправлены вне production-кода; продуктовых отказов из них не выводили.

Это проверка поведения приложения и локального стенда, не независимая аттестация
библиотек crypto/OpenSSL/age и не подтверждение конфигурации живого сервера.
