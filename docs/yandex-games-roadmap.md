## 0. Достоверность источников — читать первым

**Официальная документация площадки в сессии агента недоступна:** хосты `yandex.ru` и
`yandex.com` закрыты политикой egress-прокси. Всё, что касается требований площадки,
собрано из поисковых сводок по её документации и открытой сторонней обвязки SDK —
**не из первоисточника**.

Рабочее соглашение (`CLAUDE.md`, «verify docs against reality») запрещает документировать
по неподтверждённому, поэтому утверждения помечены:

- **✔ проверено** — сверено с кодом или измерено в этом репозитории;
- **◆ сверено по декларациям** — взято из `@types/ysdk@1.2.0` (DefinitelyTyped, скачан с
  npm-реестра): машинные объявления типов реального SDK. Даёт **сигнатуры** авторитетно;
  политику (лимиты, квоты, правила модерации) не даёт вовсе;
- **⚠ требует сверки** — вторичный источник о площадке (поисковые сводки).

**Ни один кирпич ниже не берётся в работу, пока его ⚠-предпосылки не подтверждены
(YAG-0.1).** Цифры площадок меняются, а ошибка здесь стоит отказа модерации.

## 1. Площадка: API и политика — это разные уровни достоверности

### 1.1 API ◆ — сверено по `@types/ysdk@1.2.0`

**Жизненный цикл.**

```ts
YaGames.init<TGlobalSigned>(opts?: { signed?: TGlobalSigned }): Promise<SDK>
ysdk.features.LoadingAPI.ready(): void
ysdk.features.GameplayAPI.start(): void
ysdk.features.GameplayAPI.stop(): void
```

**Реклама — колбэки, возврат `void`, а НЕ промис.**

```ts
adv.showFullscreenAdv(opts?: { callbacks?: {
  onOpen?(), onClose?(wasShown: boolean), onError?(e: Error), onOffline?() } }): void
adv.showRewardedVideo(opts?: { callbacks?: {
  onOpen?(), onRewarded?(), onClose?(), onError?(e: Error) } }): void
adv.showBannerAdv(): Promise<{ reason?: StickyAdvError }>
adv.hideBannerAdv(): Promise<{ stickyAdvIsShowing: boolean }>
adv.getBannerAdvStatus(): Promise<{ stickyAdvIsShowing: boolean; reason?: StickyAdvError }>
```

Два следствия. Контракт `PlatformAds` из `platform-adapters.md` объявлен промисами —
значит адаптер **переводит** колбэки в промис, это не проброс. И `onRewarded` отдельно от
`onClose`: закрытие ролика наградой **не является**, что и подтверждает инвариант «награду
выдаёт игра только по подтверждённому результату адаптера».

**Покупки.**

```ts
payments.getCatalog(): Promise<Product[]>
payments.purchase(opts?: { id: string; developerPayload?: string }): Promise<Purchase | Signature>
payments.getPurchases(): Promise<Purchase[] | Signature>
payments.consumePurchase(token: string): Promise<void>
ysdk.getPayments<TSigned>(opts?: { signed?: TSigned }): Promise<Payments<TSigned>>
```

**Личность игрока — и это меняет историю с entitlement.**

```ts
ysdk.getPlayer<TSigned>(opts?: { signed?: TSigned }):
  Promise<TSigned extends true ? Signature : Player>
player.getIDsPerGame(): Promise<Array<{ appID: number; userID: string }>>
player.isAuthorized(): boolean
player.getPayingStatus(): "not_paying" | "partially_paying" | "paying" | "unknown"
player.setData(data, flush?): Promise<void>
player.getData<T>(keys?): Promise<Partial<Record<T, Serializable>>>
player.setStats / getStats / incrementStats
```

Тип `Signature` документирован дословно: *«при передаче через signature объект возвращается
не сам по себе — поле signature содержит зашифрованную строку с полями объекта, которую
можно расшифровать на вашем сервере»*. То есть площадка умеет отдавать **проверяемое на
сервере доказательство личности**, и межпродуктовый entitlement внутри площадки упирается
не в аккаунты/OIDC, а в тот же эндпойнт проверки подписи, что и покупки (`YAG-4.1`).

А `getIDsPerGame()` отдаёт идентификаторы игрока **в других играх того же разработчика** —
значит будущий First Contact увидит, что этот же человек прошёл Sector Zero, без кодов.
Код остаётся нужен только для перехода С площадки в основную игру.

**Остальное, чего в роадмапе не было и что стоит знать.**

```ts
ysdk.serverTime(): number
ysdk.getFlags(params?): Promise<Record<string, string>>
ysdk.getStorage(): Promise<SafeStorage>          // typeof window.localStorage
ysdk.on("game_api_pause" | "game_api_resume", observer): () => void
ysdk.onEvent("EXIT" | "HISTORY_BACK", listener): () => void
ysdk.environment.i18n.lang: ISO_639_1            // 73 языка
ysdk.environment.i18n.tld: TopLevelDomain        // 19 доменов
ysdk.deviceInfo.isDesktop/isMobile/isTablet/isTV()
ysdk.shortcut.canShowPrompt() / showPrompt()
ysdk.feedback.canReview() / requestReview()
ysdk.leaderboards.setScore / getEntries / getPlayerEntry / getDescription
ysdk.multiplayer.sessions                        // асинхронный «призрачный» мультиплеер
```

Четыре из них меняют проектирование, и им заведены кирпичи Фазы 6:

- **`serverTime()`** — у нас игра в реальном времени на клиенте. Без серверного времени
  забег промотается переводом системных часов.
- **`getFlags()`** — удалённый конфиг, то есть правку баланса можно выкатить **без
  пересдачи на модерацию** (3–5 рабочих дней). Для «проверим баланс на живых» это
  решающее.
- **`getStorage()`** — безопасная обёртка над `localStorage`. Снимает риск
  партиционирования в iframe, о котором писал `PVR-0.3`.
- **`game_api_pause` / `resume`** — площадка сообщает о паузе (например, на показе
  рекламы). Мир идёт по стенным часам: надо решить, замирает он или тикает без игрока.

Отдельно: **`isTV()` — телевизор как тип устройства**, другая модель ввода. Мы
проектируем под телефон; это стоит явно объявить вне охвата v1.

### 1.2 Политика ⚠ — требует сверки, и числа расходятся

Декларации типов политику не несут. Ниже — вторичные источники, и **они противоречат друг
другу**, что само по себе довод в пользу `YAG-0.1`.

**Сборка.** Архив до 100 МБ в несжатом виде; в корне один `index.html`; в именах файлов и
папок нет пробелов и кириллицы. Модерация 3–5 рабочих дней, проверяет и сборку, и
промо-материалы карточки; отказ приходит письмом с причинами и ссылками на нарушенные
требования.

**Локализация.** Русская обязательна для каталога на `.ru`; отдельно требуется
автоопределение языка. Ключевая формулировка: **если хотя бы один заявленный язык
переключается не полностью, игра отклоняется «за неперевод»** — частичный перевод хуже
отсутствующего.

**Запрещено.** Внешние ссылки (сайт автора, сторы, сторонние игры, скачивание), в том
числе внутри логотипов; любые платежи мимо SDK площадки; реклама сторонних сетей, включая
статичные картинки и текст.

**Правила показа рекламы.** Только в логических паузах; максимальная задержка между
действием игрока и стартом ролика 0.33 с; **звук на время показа обязан выключаться**;
после покупки отключения рекламы она не показывается. У полноэкранной есть встроенное
ограничение частоты — слишком частый вызов не открывается, и это приходит в `onClose`.

**Проверка подписи покупки на своём сервере обязательна для модерации** (называется пункт
1.13.1); `signature` — две base64-строки вида `<подпись>.<JSON>`; ключ выдаётся в консоли.
Непогашенные покупки (без настроенного `consumePurchase`) блокируют модерацию.

**Квота данных игрока — ЧИСЛА РАСХОДЯТСЯ.** Лимит называют **10 КБ на игрока**; частоту
одни источники дают как «не чаще 100 запросов за 5 минут», другие — «не более 60 раз в
минуту». Это разные величины, и проектировать под них надо по-разному. `YAG-0.1` обязан
закрыть именно это расхождение, а `YAG-2.2` — писать по событию (конец главы), а не по
таймеру, при любом исходе сверки.

## 2. Что измерено и что из этого следует

### 2.1 Сохранение забега НЕ влезает в облако площадки — с числом

`platform-adapters.md` уже говорит, что состояние большого матча не обязано помещаться в
platform save. **Вот число, которое это подтверждает и задаёт форму `PortableMetaSave`.**

**✔ Измерено 2026-09-16.** Состояние партии на карте, которую прототип играет сегодня
(`nexus`, 121 сектор): **29.3 КБ на старте, 30.9 КБ после шести игровых часов**. Лимит
площадки — 10 КБ (⚠). Не влезает **втрое, ещё до начала забега**, и растёт дальше.
Маленькая карта спасает частично: `skirmish-1` (5 секторов) — 2.1 КБ на старте и 3.5 КБ
через сутки; карта забега `pve-1` имеет 7 секторов и десять волн впереди.

**Следствие для PVR-0.3 и YAG-2.1: сейв — это НЕ `GameState`.** Варианты:

- **(а) компактный дескриптор забега** — сид, сложность, номер волны, взятые усиления;
  мир пересобирается. Классическая форма сейва рогалика, влезает в сотни байт. Опирается
  на детерминизм — здесь это инвариант №1, закреплённый golden-тестами.
- **(б) лог действий + реплей** — машинерия ✔ уже есть: `ReplayLog` и `runReplay`
  (`packages/shared-core/src/replay/replay.ts`) с CI-тестом, который гоняет живую комнату
  48 игровых часов и сверяет `hashState` бит-в-бит. Точнее, но лог растёт и упрётся в тот
  же лимит.
- **(в) гибрид** — точное состояние локально, дескриптор в облако.

**Рекомендация — (а), с (в) как поведением по умолчанию.** Рогалику не нужно возвращать
позицию флота попиксельно: достаточно вернуть игрока в тот же забег на той же волне с
теми же усилениями.

### 2.2 Покупки требуют сервера, а сервер — это цель дохода

⚠ Проверка подписи покупки **на вашем сервере** обязательна для модерации. План при этом:
доход от покупок → аренда сервера. Замкнутый круг.

**Он разрывается тем, что это НЕ игровой сервер.** Проверка подписи — функция без
состояния: приняла `signature`, сверила ключом из консоли, ответила. Ни базы, ни комнаты,
ни постоянного процесса; живёт на бесплатном тарифе и к арендованному серверу матчей
отношения не имеет. Поэтому эндпойнт — самостоятельный маленький кирпич (YAG-4.1), а не
«дождёмся сервера», и он не тянет ни `packages/server`, ни Postgres.

**✔ Про доверие.** Репозиторий стоит на server-authority (инвариант 5), одиночная игра
сервера не имеет. Даже с проверкой подписи всё, что происходит ПОСЛЕ неё — выдача
купленного, состояние прогресса — остаётся клиентским и подделывается. Это ещё одна
причина держаться guardrail'ов `platform-adapters.md` §4: продавать ускорение меты, а не
исход матча.

### 2.3 Реклама за продолжение забега — отозвано

**Ранняя редакция этого файла рекомендовала rewarded-видео за продолжение забега после
смерти («одно за забег»). Рекомендация СНЯТА** после сверки с `platform-adapters.md`,
который прямо называет такое нежелательным: §4 — не продавать «неограниченное
воскрешение/перемотку поражения», §1 — rewarded ставить на бонус к **мета-награде после
завершённого** PvE, а не к результату идущего боя, и «не должен превращаться в
проигрываю → плачу → победил».

Довод того документа сильнее моего: цена смерти — это и есть то, что делает забег
забегом, а заодно то, что мы собираемся мерить. Записано здесь, а не удалено, чтобы
предложение не всплыло второй раз как свежая идея.

**Что остаётся верным:** ✔ структура забега (этапы = волны) даёт естественные паузы, и
требование площадки «только в логических паузах» выполняется по построению. Конкретные
placements берутся из `platform-adapters.md` §1–§2, а не изобретаются здесь.

## 3. Что у нас уже соответствует (✔ сверено с кодом)

- **Размер.** Цели `build.mjs`: `void-dominion.html` 2773 КБ, `-player.html` 2760 КБ,
  `-admin.html` 437 КБ — один файл, без внешних ресурсов. Лимит в 100 МБ (⚠) не близко.
- **Один `index.html` в корне** — сборка и так однофайловая.
- **Полнота перевода.** Требование «частичный перевод = отказ» (⚠) закрыто сильнее, чем
  требуется: гейт `prototype/src/i18n.test.ts` роняет сборку на ключе, которого нет в
  обеих локалях, и отдельно запрещает русский литерал в коде. Расхождение локалей
  физически не доезжает до модерации.
- **Автоопределение языка.** Клиент грузит ровно одну локаль на старте (LOC-6) — точка
  подстановки языка площадки уже есть.
- **Границу «SDK и сети здесь нет» репозиторий умеет держать сторожем, а не
  соглашением** — образец `prototype/src/aiProfile.test.ts`. Это готовый способ
  исполнять инварианты `platform-adapters.md` («`shared-core` не импортирует SDK
  площадки», «gameplay не проверяет строку `yandex`») тестом, а не бдительностью.
- **Детерминизм** (инвариант 1, golden-тесты RNG) — то, на чём стоит компактный сейв
  из §2.1.

## Фаза 1 · Платформенный слой и сборка `[proto]`

### YAG-1.1 · `WebPlatformAdapter` и платформенная цель сборки `[proto]` 🔒(YAG-0.1) — L
Контракты `GamePlatform` из `platform-adapters.md` и их fallback-реализация без внешнего
SDK — та, на которой всё тестируется детерминированно. Плюс отдельная цель сборки рядом
с тремя существующими. Общее (ядро, `/localization`, `/decisions`, рендер) берётся
импортом, НЕ копией.

**Механизм уже есть, изобретать не надо.** `prototype/build.mjs` гоняет esbuild от
`entryPoints` по графу импортов с `write: false` — шага «скопировать каталог» в сборке нет
вообще, и что не импортировано, того в артефакте нет физически. Измерено 2026-09-17 одним
прогоном: `void-dominion.html` — 2827 КБ, `void-dominion-admin.html` — **438 КБ**. Разница
в 6,5 раз получается только от другой точки входа (`admin.ts` против `bootstrap.ts`).

**Решение владельца 2026-09-17: артефакт РАЗЛОЖЕННЫЙ**, а не один самодостаточный HTML.
`index.html` в корне архива плюс `assets/` рядом. Сегодня прототип инлайнит всё в один файл
(`loader: { '.webp': 'dataurl' }`), и для площадки это был бы самый простой возможный архив
— ровно один файл. Но data-URL это base64 (около +33% на бинарниках), и кэширования по
частям нет: правка одной строки заставляет игрока перекачать весь бандл. Раскладка принята
до того, как приедет настоящий арт, а не после третьего релиза.

⚠️ **Свой сторож для бандла данных — обязателен, иначе контент пропадёт молча.**
`data/bundle.ts` вшивает 21 фрагмент `data/*.json` статическими импортами, и его шапка
предупреждает: каждое поле каталога в `schemas.ts` несёт `.default({})`, поэтому
НЕ переданный фрагмент **не роняет загрузку** — zod подставляет пустую запись, и приложение
получает валидный бандл с молча пропавшим контентом. Это уже случалось: до браузера доехали
11 фрагментов из 18, а весь слой героев и модулей корабля был пуст. Готовое противоядие —
`data/bundle.test.ts` (список сверяется с тем, что реально спрашивает композер; каждый
фрагмент резолвится в контент, а не в `undefined`; каталоги заполнены). Своему набору
фрагментов Sector Zero нужен свой такой тест.

**Готово, когда:** цель собирается в `index.html` + `assets/`, и распакованный результат
запускается без доступа к репозиторию; тест-сторож падает, если в граф импортов попал SDK
площадки, сетевой модуль или что-то ещё из списка «не нужно продукту» (§0.1
[`sector-zero-roadmap.md`](sector-zero-roadmap.md)); тест бандла данных падает, если
фрагмент пропал из списка; `WebPlatformAdapter` покрывает success/cancel/unavailable для
рекламы и покупок.

### YAG-1.2 · `YandexGamesAdapter`: инициализация и жизненный цикл `[proto]` 🔒(YAG-1.1) — M
Подключение SDK, готовность после загрузочного экрана, разметка геймплея на старте и

## Фаза 6 · Возможности площадки, меняющие поведение мира `[proto]`

> Заведены после сверки с `@types/ysdk@1.2.0` (§1.1). Это не интеграционные мелочи: три из
> четырёх меняют то, как ведёт себя симуляция.

### YAG-6.1 · Серверное время вместо системного `[proto]` 🔒(YAG-1.2) — M
`ysdk.serverTime()` как источник времени для забега. Мир Sector Zero идёт по стенным часам
на клиенте игрока, то есть **перевод системных часов промотает забег** — самое дешёвое
читерство, какое бывает. Ядро времени не берёт (инвариант 1: время приходит через
`Context.now`), значит это работа адаптера и хозяина цикла, а не правка симуляции.
**Готово, когда:** забег считает время от площадки; подмена системных часов его не двигает;
отсутствие SDK (веб-фолбэк) деградирует на локальное время, а не падает.

### YAG-6.2 · Пауза площадки: что делает мир `[proto]` 🔒(YAG-1.2) — M
`ysdk.on('game_api_pause' | 'game_api_resume')`. Площадка сообщает о паузе — например, на
показе рекламы. **Это решение о поведении мира, а не подписка на событие:** мир либо
замирает (и тогда реклама даёт бесплатную паузу — игрок будет ею пользоваться), либо тикает
без игрока (и тогда ролик стоит игроку потерь). Обе модели допустимы, но выбрать надо
осознанно и одинаково для всех продуктов.
**Готово, когда:** поведение выбрано, покрыто тестом и одинаково на всех площадках через
контракт, а не через проверку имени площадки.

### YAG-6.3 · Удалённый конфиг баланса `[proto]` 🔒(YAG-1.2) — M
`ysdk.getFlags()`. Правка чисел баланса без пересдачи на модерацию (3–5 рабочих дней). Для
цели «проверить баланс на живых игроках» это разница между итерацией в день и итерацией в
неделю. Границы: флагами крутятся ЧИСЛА (длина главы, интервал волн, размеры наград), но не
правила — иначе детерминизм станет зависеть от удалённого состояния.
**Готово, когда:** числа берутся из флагов с безопасными умолчаниями; недоступность флагов
не ломает забег; тест подтверждает, что флаг не может изменить правило.

### YAG-6.4 · Кнопка «назад» и выход `[proto]` 🔒(YAG-1.2) — S
`ysdk.onEvent('HISTORY_BACK' | 'EXIT')`. На телефоне это системная кнопка, и без обработки
она выкинет игрока из игры посреди забега.
**Готово, когда:** «назад» ведёт по экранам продукта, а выход не теряет несохранённый
прогресс.
