# Ритуал плейтеста: машинная половина + человеческая

`docs/playtest-template.md` — чеклист, который заполняется **после каждого живого теста**.
Это брик **M0** из `docs/metrics-roadmap.md`, и у него ровно один смысл: сервер уже пишет,
что произошло (JSONL + агрегаты), но **не знает, почему это важно**. Лог покажет
`rejects=7 · E_FORBIDDEN`, и только человек напишет «оба игрока думали, что тапом по
нейтральной планете её захватывают». Балансное или UX-решение принимается на паре
«цифра + наблюдение»; по отдельности первая не объясняет, а второе не проверяется.

Шаблон — источник правды по структуре. Не придумывай новых разделов и не переписывай
формулировки: сводимость заметок между прогонами держится на том, что все файлы
одинаковые.

## 1. Поднять сервер

Полная инструкция — `docs/multiplayer.md` («Playing the real prototype together»).
Короткий путь для теста на людях:

```bash
pnpm host                    # собирает прототип + отдаёт игру и матч на 0.0.0.0:8788
TEAMS=5v5 pnpm host          # десять кресел: p1–p5 против p6–p10
MATCHES=3 pnpm host          # три независимых сессии в одном процессе
```

`pnpm host` печатает локальный и LAN-URL; игроки открывают `/` (player-клиент), хост
может взять `/dev` (полный dev-клиент). Лобби нет — сессия идёт с момента создания
(SES-2.1), заходящий попадает в живой мир.

Не бери `pnpm dev:proto-server` для теста по сети: он биндит `127.0.0.1`, и это ровно тот
случай «у меня работает, друг не подключается». Если кто-то не заходит — сначала
`pnpm doctor` (он перечислит адреса и скажет, какой URL раздавать или что нужен туннель),
потом раздел «Troubleshooting» в `docs/multiplayer.md`.

Для друга из другой сети — туннель: `cloudflared tunnel --url http://localhost:8788`.

## 2. Завести файл заметок ДО теста

Имя — по дате, как в шаблоне (его пример: `playtest-logs/2026-06-26-notes.md`):

```bash
mkdir -p playtest-logs
cp docs/playtest-template.md "playtest-logs/$(date +%F)-notes.md"
```

Дальше из копии удали шапку шаблона (всё до первого `---`) — в файле остаётся сам блок
чеклиста. Заводи его **до** прогона: половину пунктов (что путало, где лагало) невозможно
восстановить через час, а пустой файл рядом с логом заставляет их записать.

`playtest-logs/` в `.gitignore` (строка 16) — файл локальный, в `git status` он не
появится. Это нормально: сюда же пишется сырой JSONL. Если заметки нужны в репозитории,
добавлять их придётся явным `git add -f`, и это решение владельца, а не твоё.

## 3. Заполнить метаданные, что заполняется машинно

Блок «Метаданные прогона» просит: дату/время, билд, игроков, способ подъёма сервера,
устройства/сеть, файл лога. Три из них добываются командами, остальные знает только
человек — спроси их, не выдумывай.

```bash
git rev-parse --short HEAD          # «Билд» — шаблон прямо называет эту команду
pnpm prototype                      # печатает: wrote prototype/dist/void-dominion.html (NNN KB)
```

Размер сборки берётся из вывода `pnpm prototype` (`pnpm host` делает эту же сборку —
если хост уже запущен, строку можно взять из его лога). Это метрика «Bundle size» из
`docs/metrics-roadmap.md`, категория C: следим за ростом от прогона к прогону, поэтому
цифра в заметках должна быть от **той самой** сборки, на которой играли.

Поле «Файл лога» — `playtest-logs/match-YYYY-MM-DD.jsonl` (журнал за UTC-день, в нём все
партии дня, PTM-0.1) плюс id партии; точное имя файла сервер печатает в сводке при выходе.

## 4. Во время теста

Клиент показывает оверлей в углу: `NN FPS · NN ms · sync ✓` (при расхождении —
`desync ✗ K`). Он покрывает сразу три раздела чеклиста: **A · Связь** (RTT), **B ·
Корректность / десинк** и **C · Производительность (клиент)**. Появившийся `✗` —
единственное, что стоит бросить всё и зафиксировать немедленно: шаблон просит скрин
оверлея и время, потому что по логу потом можно найти действие-виновника, а по памяти —
нет. Цель по десинкам — ноль, это инвариант детерминизма из `CLAUDE.md`.

Разделы **D · Баги и краши** и **E · UX — что путало** заполняются по ходу, а не в
конце: «шаги к воспроизведению» вспоминаются только пока свежо.

## 5. После теста: Ctrl-C и разбор

`Ctrl-C` на сервере печатает блок `── playtest summary ──` (joins/leaves/actions,
by type, by reject, battles/captures/desyncs, submit/advance/broadcast, delta, client
fps/rtt, match end, путь к логу) и дописывает те же агрегаты последней строкой
`{"kind":"summary"}` в JSONL. Раздел «Машинные данные» шаблона просит скопировать этот
блок в заметки — сделай это до того, как терминал закроют.

Затем — читаемый отчёт по логу:

```bash
pnpm run metrics                                   # свежайший playtest-logs/*.jsonl
pnpm run metrics -- --day 2026-10-14               # журнал дня: список партий в нём
pnpm run metrics -- --day 2026-10-14 --match <id>  # отчёт по одной партии
```

`prototype/report.mjs` разбирает лог: длительность, joins/leaves, микс действий по типам
и игрокам, реджекты по кодам, события, таймлайн `planet.captured` («control over time»),
десинки (с явным «← ЦЕЛЬ 0, смотреть немедленно»), латентности и размер дельты. Отчёт
только читает файл — его безопасно запускать и на живом логе.

Отчёт **не** заполняет чеклист. Он даёт цифры для разделов A–C; разделы D–F (баги, что
путало, фан 1–5, «топ-1 что чинить») пишутся словами и только людьми, которые играли.
Спроси у них оценки фана и «хотелось бы доиграть»: на двоих это главный сигнал по
вовлечённости. На сетевом тесте рядом с ним — `pnpm run analytics` (раздел 6).

## 6. Сетевой тест на людях (прод-сервер)

Тест, где играют не двое за соседними столами, а десятки людей по ссылке, живёт на
прод-хосте автодеплоя (`deploy/README.md`) и даёт два журнала: партий
(`match-YYYY-MM-DD.jsonl`) и браузеров (`client-YYYY-MM-DD.jsonl`, PTM-1). Порядок задан
кирпичом PTM-2.2 в `docs/playtest-telemetry-roadmap.md`; без него тесты не сравнить между
собой.

**До теста.**

1. На хосте в `/var/lib/moongame/server.env` заданы `ANALYTICS_SALT` и `METRICS_TOKEN`
   (`deploy/env-keys.sh` их генерирует). Без соли в журналах нет `actor`, и людей нельзя
   связать между днями и партиями.
2. Приёмник жив: на хосте

   ```bash
   TOKEN=$(sudo grep '^METRICS_TOKEN=' /var/lib/moongame/server.env | cut -d= -f2)
   curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8788/metrics/summary \
     | jq '{journal, telemetry}'
   ```

   отдаёт оба блока, а открытая в браузере игра за 5–10 секунд поднимает
   `telemetry.events` и `telemetry.activeInstalls`.
3. Ссылка для приглашения несёт метку: `https://<домен>/?src=tg-oct` — `[a-z0-9-]`, до
   32 символов; иначе метка отбрасывается. Разным каналам — разные метки, тогда
   `pnpm run analytics` покажет воронку по каждому.
4. Файл заметок заведён (раздел 2), в метаданных записаны билд и метка.

**Текст приглашения** — что пишем людям, кроме ссылки и времени:

> Это ранний тест. Игра пишет обезличенный журнал: какие экраны открылись, сколько
> грузилась страница, обрывалась ли связь, какие действия сервер отклонил, и ошибки
> браузера без текста. Ник, почту, пароль и текст сообщений в журнал не пишем. После
> игры пришлём короткую анкету на 2–3 минуты.

Не обещай в тексте того, чего нет в коде: перечень полей — `packages/protocol/src/telemetry.ts`
и раздел PTM-1 роадмапа.

**Во время теста.** Каждые полчаса — тот же `curl` к `/metrics/summary`. Тревожно, если
`telemetry.rejected` или `telemetry.limited` растут вместе с числом людей (клиент шлёт
не то или упирается в лимиты), если в `journal.client` растут `dropped` (очередь записи переполнена) или `failed`
(запись на диск не удалась)
и если `activeInstalls` заметно меньше числа людей, которые говорят, что играют.

**После теста.**

1. Забрать журналы с хоста. Они лежат в томе `void-logs` по пути контейнера
   `/app/playtest-logs`; имя контейнера показывает `sudo docker ps` (проект Compose —
   `deploy`, обычно `deploy-server-1`):

   ```bash
   sudo docker cp deploy-server-1:/app/playtest-logs ./void-logs-$(date +%F)
   ```

   Потом `scp` к себе в `playtest-logs/` рабочей копии.
2. Отчёты за дни теста:

   ```bash
   pnpm run metrics -- --day 2026-10-20                    # партии дня, сводки запусков
   pnpm run analytics -- --from 2026-10-20 --to 2026-10-27 # поведение людей
   pnpm run analytics -- --person <id>                     # лента одного тестера
   ```

   Удержание считается только по закрытым окнам: D7 появится через неделю после первого
   дня теста, и раньше на него смотреть нечего.
3. Разослать анкету (раздел G шаблона), ответы положить в заметки по нику.
4. В заметки — оба вывода и счётчики приёмника (раздел «Машинные данные» шаблона).

**Хранение.** Журналы держат псевдонимы, а не имена; копия у оператора нужна, пока
идёт разбор. Правила хранения и удаления по запросу человека — кирпич PTM-3.1, до него
лишние копии не плоди и не клади журналы в репозиторий.

## 7. Границы

- **Не трогай `docs/playtest-template.md`** при заполнении заметок. Правка шаблона — это
  отдельная задача: он общий для всех будущих прогонов, а заметки — одноразовый файл.
- **Метрики — только наблюдение** (инвариант из `docs/metrics-roadmap.md`). Если по
  итогам теста хочется что-то замерить, это делается на observe-потоке сервера или
  постфактум по логу. Ни счётчиков, ни `Date.now()` внутри `applyAction`/`advanceTo` —
  иначе ломается детерминизм и реплеи.
- Найденный баг превращается в кирпичик `docs/backlog.md` (навык `brick`), а не в
  правку «по-быстрому» посреди разбора лога.
- Не заполняй за игроков поля, которых не видел: незаполненный пункт честнее
  придуманного, а по чеклистам потом считают тренды.
