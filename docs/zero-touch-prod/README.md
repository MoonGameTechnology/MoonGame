## Что такое Zero Touch Prod

**Человек не трогает прод руками.** Ни SSH на машину, ни `docker compose up` в консоли,
ни `psql` в боевую базу, ни правки `server.env` на хосте. Любое изменение прода — код,
образ, конфиг, секрет, схема БД — идёт одним путём:

```
изменение в git → PR → ревью + CI → merge
  → конвейер собирает, сканирует, подписывает
  → прод сам забирает подписанное, проверяет здоровье, при сбое откатывается
```

Подход пришёл из SRE-практики крупных эксплуатаций: большинство аварий начинается с
человека, который «на минутку» зашёл на сервер. Когда путь в прод один и автоматический:

- каждое изменение записано (git + журнал конвейера), его можно повторить и откатить;
- на машине ровно то, что описано в репозитории, дрейфу неоткуда взяться;
- украденный ключ или ноутбук не открывают прод, потому что постоянного доступа нет;
- ошибку ловят проверки до выкатки, а не человек после.

Четыре принципа:

1. **Всё как код.** Образ, конфиг, секреты (зашифрованными), описание хоста, миграции.
2. **Один путь изменения.** Через PR, с гейтом CI; обходного «быстро руками» нет.
3. **Безопасная выкатка.** Проверка подписи, проверка здоровья, автоматический откат.
4. **Break-glass вместо постоянного доступа.** Ручной вход существует только на аварию,
   оставляет след и заканчивается PR, который закрепляет сделанное руками.

Zero touch не значит «никогда». Значит «никогда без следа и без причины».

## Где проект сейчас

**Уже работает без рук** (сверено по файлам):

| Звено | Где |
| --- | --- |
| `main` защищён, изменения только через PR и merge queue | `.github/workflows/automerge.yml`, `pr-merge-rule.md` |
| Гейт качества с Postgres в CI | `.github/workflows/ci.yml` |
| Сканеры безопасности | `.github/workflows/security.yml` |
| Образ собирается в CI, блокирующий Trivy и smoke, push в GHCR (`:main`, `:sha-<12>`) | `.github/workflows/image.yml` |
| Keyless cosign-подпись по дайджесту + SLSA provenance | `.github/workflows/image.yml` |
| Деплой проверяет подпись: только дайджест, только `image.yml@refs/heads/main` | `deploy/verify-image.sh` |
| Обновление: verify → pull → up → `/health` → откат на `.last-good-image` | `deploy/update.sh` |
| Миграции БД выполняет сервер при старте | `packages/server/src/persistence.ts` |
| Клиент выкатывает Cloudflare Workers Builds на push в `main` | `wrangler.jsonc` |

Клиент уже zero touch. У сервера готова верхняя половина (собрать, проверить, подписать),
нет нижней: доставки на машину.

**Где руки ещё нужны:**

1. **Выкатка сервера.** `image.yml` заканчивается шагом `deploy instructions`, который
   печатает команду; человек заходит на хост и запускает `moongame update`.
   Pull-таймер ADEP-3 не сделан.
2. **Обход гейта.** `deploy/update.sh` без `VOID_IMAGE` делает `git pull` и собирает образ
   на хосте — сам скрипт пишет «образ не сканирован и не подписан».
3. **Конфиг и секреты на хосте.** `server.env` правится на машине и в git не описан.
4. **Хост настраивается однажды.** `deploy/install-ubuntu.sh` запускается от root один
   раз; дальше состояние машины никто не сверяет (скилл `infra-audit` — по запросу).
5. **Ручная работа с БД.** `deploy/README.md` описывает `psql … DELETE FROM seats …`.
6. **Нет версии на проде.** `/health` отвечает `{ ok: true }` (`wsServer.ts`), какой образ
   запущен — не узнать без входа на машину.
7. **Ревью формальное.** `.github/CODEOWNERS` целиком закомментирован; GitHub Environment
   с ревьюерами есть только у Pages.
8. **Автооткат почти слепой.** Без метрик (OPS-0.*) он видит только «не поднялся», а
   рестарт рвёт WebSocket'ы (OPS-1.1 не сделан).
